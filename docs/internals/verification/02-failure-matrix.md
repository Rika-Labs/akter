# Failure matrix

The 0.2 failure model is discard, conditional-create fencing, checkpoint-plus-tail recovery, and restart of durable obligations. Recorded 0.1 transaction observations are in [dated history](history/2026-10-12-failure-matrix-0.1.md), not evidence for the bucket engine.

| Failure boundary                                                                           | Current evidence                                                                                           | What is still open                                                                                          |
| ------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| F1–F5: declared failure, defect, replay, interrupted execution and pre-append crash        | [E1](e1-execution.md), E2 recovery, E7 speculative-index tests and [E6](e6-pages-history.md) page rollback | Production-provider behavior is not inferred from local page tests.                                         |
| F6–F12: unknown append, fencing, trim, checkpoint upload, drain and build mismatch         | [Store protocol](store-protocol.md), [E2](e2-recovery.md), E7 atomic replay                                | Cross-runtime recovery and provider-specific behavior are not inferred from a local pass.                   |
| F13–F16: cross-shard delivery, timers, cron/DST and gateway loss                           | [E3](e3-cluster.md), [E4](e4-rpc-serve.md) and E7 routed `find`                                            | Default coordination timings miss the five-second move target; hosted wake orchestration is separate.       |
| F17–F19/F17′: job journals, retries, derived actor calls and concurrency                   | [E5](e5-jobs.md) and E3 job-process handoff                                                                | External I/O still needs provider idempotency/reconciliation.                                               |
| F20–F22: history, GC, upload and fork races                                                | [E6](e6-pages-history.md): seeded moves/replay, filesystem and MinIO, retained anchor and complete tail    | Production-provider/50 GB gates, whole-shard forks and stranded unknown-outcome recovery remain open.       |
| F24/F27: refused-build drain and stopped-store `nextDue`                                   | E2/E3 local evidence                                                                                       | Cloud must retain builds, persist drain reports and arrange startup.                                        |
| E7: index visibility/recovery, denied operator scope, audit failure and interrupted replay | [E7 find and operators](e7-find-operators.md)                                                              | General multi-tenant addresses, hosted operator proxying and production provider certification remain open. |

Every durable transition needs a failure case asserting resulting state and obligations. An audit write held or refused must hold/refuse the read; a replay append must contain its replay image and audit together. Simulator, filesystem, MinIO and production-provider results are separate evidence classes.

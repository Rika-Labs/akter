# Architecture decisions

- [ADR 0067: Due-work scans use the data shard map](0067-due-work-shard-ranges.md) (implementation decision, 2026-10-03) makes relay claims, capped-job discovery, subscription probes, and holder liveness use one data bucket range at a time; isolates optional Neki shard targeting on dedicated sessions; preserves the ordinary database's one-statement, one-flight claim; and records the catalog-backed routing-key uniqueness audit. Neki topology and plan evidence remain unverified.

**Responsibility:** index the architecture decisions and their recorded rationale.  
**Authority:** historical decision record.  
**Owner role:** architecture.
**Change policy:** supersede via a new ADR; do not edit accepted ADRs in place.

Use an ADR when a choice changes an interface, invariant, data model, deployment guarantee, or supported workload. An ADR must state context, decision, alternatives, consequences, evidence, and revisit conditions.

Decisions do not override newer accepted requirements. When a decision is superseded, preserve it and link the replacement.

- [ADR 0060: Generated protocols: an MCP endpoint and a Python client derived from the served OpenAPI document](0060-generated-protocols-mcp-and-python-client.md) (proposed 2026-09-30) adds `serve({ mcp: { path } })`, a stateless MCP 2026-07-28 endpoint whose tools (one per public command, reducer, and query, named by operation id, plus `durable.commandIds`) are computed from the OpenAPI document and run the route's own execution path, so authentication, `authorize`, errors, and command identity match HTTP (the caller supplies `commandId`, never the JSON-RPC id); serves no resources and no earlier revisions; generates a stdlib-only Python client from the same document in `packages/python-client`; amends rule 41; no migration.

- [ADR 0062: Scale-to-zero serving](0062-scale-to-zero-serving.md) (accepted 2026-09-30, Dallen) lets a deployment opt into `scale_to_zero`: with no ready runner in a region the edge records a `runner_wake` request for the provider, waits (one cold start per region per edge, bounded by `EDGE_COLD_START_TIMEOUT`) until a registered runner answers `GET /ready`, then forwards; scaling down is the provider's drain, due work that comes due at zero runs on the next cold start, and parked connections end; amends ADR 0031 §1; control-plane migration `0004_scale_to_zero`.
- [ADR 0063: Greenfield framework simplification](0063-framework-simplification.md) (accepted 2026-09-30, Dallen) authorizes the coordinated unreleased-alpha API/storage vocabulary migration, immutable declaration compilation, canonical jobs, integration-first evidence, and removal of duplicated fixture/protocol/tooling machinery in [plan.md](../../plan.md), without weakening durable guarantees or adding compatibility aliases.

- [ADR 0071: First-come, first-served pools, a query pool, and releasing the turn session before publish](0071-fair-pools-query-pool-and-early-turn-release.md) (proposed 2026-10-03) puts a first-come, first-served gate in front of every runner pool, which ends the 10-second waits Effect's pool allowed, gives queries their own pool (`queryConnections`, default 10), and returns a turn's session before it publishes when no batch is chained. It amends ADR 0019's connection budget and ADR 0020's pools and lease span, and sits under ADR 0077's checkout bound: bounded admission, then the gate, then the native pool.

- [ADR 0077: Admission control: shed load with `ActorUnavailable` and `retry-after`](0077-admission-control.md) (implementation decision, 2026-10-03) bounds a runner's hidden queues: at most `admission.concurrency` external commands run at once with as many waiting at most `admission.wait`, `Actors.serve` refuses commands before authentication when its command request handler limit or runtime admission queue is full, and an actor without a declared `mailboxCapacity` holds at most 1,024 commands; every refusal is `ActorUnavailable` with `retry-after`, never runs, writes no receipt, and is not retried inside the runtime.

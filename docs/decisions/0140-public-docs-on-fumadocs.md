# ADR 0140: Public docs on Fumadocs, hosted by Akter

**Status:** accepted (2026-10-17, Dallen); supersedes [ADR 0080](0080-public-docs-on-mintlify.md).

**Responsibility:** decide how Akter's public documentation is built and where it is hosted.

**Authority:** design decision record.

**Owner role:** documentation.

**Change policy:** supersede through a new ADR.

## Context

[ADR 0080](0080-public-docs-on-mintlify.md) published the public pages through a hosted docs platform. The platform owned theme selection, font loading and page rendering, so the repository could not guarantee what the first paint shows. An earlier evidence round on the hosted platform recorded a light page under a dark system preference and a title that changed width after the first contentful paint, and fixing those needed overrides on top of a renderer the repository does not own. Dallen's rule for the docs is that the page is server-rendered and complete on first paint: no theme flash, no layout shift on refresh, no late font swap and no entrance animation. His second rule, from 2026-10-18, is that the docs look the way docs.capy.ai looks, in Akter's colours.

## Decision

1. The public docs are a static Next.js export built with Fumadocs in `apps/docs` (`@akter/docs`). It is a private workspace app and publishes nothing to npm.
2. The app reads the Markdown under `docs/` in place; no page is copied or moved, and the pages keep reading correctly on GitHub. `apps/docs/src/content/navigation.ts` is the only list of published pages and products, so a document is published only when it is listed there. Decisions, contracts, architecture, operations internals, verification and vision stay unpublished. The welcome page and the API reference overview are written by the app from that list; each card shows the description of the page it opens.
3. Links are resolved at build time. A link to a published page becomes its route, a link to another repository file becomes a GitHub URL, and a missing page or heading fails the build.
4. Akter hosts the export on Cloudflare at `https://docs.akter.dev`. The export carries `_redirects` (the redirects ADR 0080 configured, plus `/` to `/welcome`), `_headers`, a `.md` twin of every page, `llms.txt`, `llms-full.txt`, a static search index, a sitemap and `robots.txt`. `_headers` sends `Strict-Transport-Security`, `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy` and a `Content-Security-Policy` that matches the hosting platform's own policy, with two differences: `script-src` allows `'unsafe-inline'` because Next writes inline data and bootstrap scripts into every page (up to 30 on one page, so hashing them would exceed Cloudflare's 2,000-character header line), and `font-src` allows `data:` because both fonts are embedded in the stylesheet.
5. The shell follows docs.capy.ai measurement for measurement, in Akter's colours. A fixed 260 px sidebar runs the full height and holds the Akter wordmark, a product switcher (Documentation, and API reference, which swaps the tree and opens an overview page), the search button, the page tree, an Appearance row, an Open Akter link and the X and GitHub icons. The article sits in an inset panel (8 px margin, 12 px radius, 1 px border) with a 720 px reading column and a 220 px table of contents that also holds Copy page and View as Markdown. Below the desktop breakpoint the sidebar is a 300 px drawer under a 44 px bar. Search is a ⌘K palette with All, Documentation and API reference filters. Backgrounds are Akter's (panel #121311 on #0a0a09 in dark, #fbfbfa on #eeeeed in light) and Akter yellow (#ffc300, the favicon's colour) stands wherever Capy uses its primary colour. The site has no header, no tabs, no Sign in button and no previous and next links; a Capy-only feature with no Akter counterpart (its colour-theme submenu, its Discord link, its product screenshots) is left out.
6. The theme follows `prefers-color-scheme` in CSS until the reader chooses. The Appearance menu offers Light, Dark and System; the choice is kept in local storage under `akter-theme`, and a small inline script in the document head puts it on the root element before the first paint, so the other theme never shows first. System clears the choice. A reader with scripts off gets the operating system's theme.
7. Text is set in Inter and code in Geist Mono, both latin subsets under the SIL Open Font Licence, committed in `docs/fonts/` with their licence texts. `bun scripts/embed-fonts.ts` writes them into the render-blocking stylesheet as `data:` URLs with `font-display: block`, so the first response carries everything the first paint needs and no font request follows it. A font file requested after the first paint reached WebKit too late (a previous design painted the fallback in 38 of 40 cold loads), and an optional face that finishes decoding after the engine's 100 ms window is dropped for the life of the page, which drew code in a proportional fallback. Even an embedded face is decoded only after the first text is laid out, and a page that paints in that gap moves its boxes when the face arrives (WebKit on most loads of the delayed-script matrix, Chromium on 3 of 48), so a script in the head puts `data-font-gate` on `html` and a style hides the page while the attribute is there. A script at the end of the body removes it once both faces are decoded, when loading either fails, or after 1.5 s. React never renders the attribute: a page that React renders again after a hydration mismatch would get it back and stay hidden. A page without scripts is never gated. PolySans and Geist Sans are not used, and the build fails if the export names PolySans.
8. The panel scrolls, not the window. `history.scrollRestoration` is manual and one inline script owns restoring the offset on a reload and on back and forward loads, because WebKit restores its own offset only after the page scripts have loaded. Opening a page from the sidebar starts at the top, and an address with a hash scrolls the panel to that heading.
9. The build is reproducible. The Next build id is the commit being built, and syntax highlighting has no time limit, so a loaded machine cannot cut a code line into fewer tokens. `bun run --cwd apps/docs check:reproducible` builds twice, the second time with every CPU busy, and fails if the two exports differ by one byte.
10. Mintlify is removed: `docs/docs.json`, `docs/.mintignore`, `docs/style.css` and the Mintlify-only logo files are deleted.

## Consequences

- `bun run --cwd apps/docs build` produces `apps/docs/out`, the whole deploy artifact. One optional build setting names the origin: `SITE_URL` (default `https://docs.akter.dev`) is used for canonical links, the sitemap, `robots.txt`, `llms.txt`, the Markdown twins and the page actions. It must be a bare `https://` origin, and the build fails if the production site address is still in the export when `SITE_URL` is overridden, if the export names PolySans, or if no stylesheet carries Inter and Geist Mono. The build runs inside a git checkout because the build id is the commit. It needs no network.
- A new public page is added to `navigation.ts`; the build fails if its links or anchors are wrong.
- The first-paint claims are checked by measurement; rerun the matrix in the evidence document when the layout, stylesheet or fonts change. The match with docs.capy.ai is checked by measuring both sites' computed styles and rectangles on the same screens, and the differences that remain are Capy's own content and brand, listed in the evidence document.
- Hosting, the `docs.akter.dev` custom domain and the cutover from Mintlify belong to the private Akter Cloud repository.
- The fonts travel inside the stylesheet, about 146 KB of text that carries 109 KB of font bytes in the first load and nothing after it: the stylesheet is hashed and cached for a year, so the fonts never revalidate, and no font origin needs a CORS grant. The first paint waits for the stylesheet, so it waits for the fonts.
- The sidebar, switcher, search palette, appearance menu and table of contents are the app's own components, so they do not change when Fumadocs does; Fumadocs supplies the content source, the Markdown pipeline and the page tree.

## Alternatives

- **Stay on the hosted platform.** Rejected: the first-paint behaviour is not ours to guarantee, and the earlier measurements failed it before overrides.
- **Host on Vercel.** Rejected: Akter hosts the docs itself on Cloudflare, and a static export needs only a file server with redirects and headers.
- **Copy the pages into the app.** Rejected: two copies drift, and GitHub readers would read different text from the site.
- **Fetch the body font from the marketing site at build time.** Rejected: the build then needs the network and a font that is not in the repository, and a second origin cannot reach WebKit before the first paint.

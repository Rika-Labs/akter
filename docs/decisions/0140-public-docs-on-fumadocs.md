# ADR 0140: Public docs on Fumadocs, hosted by Akter

**Status:** accepted (2026-10-17, Dallen); supersedes [ADR 0080](0080-public-docs-on-mintlify.md).

**Responsibility:** decide how Akter's public documentation is built and where it is hosted.

**Authority:** design decision record.

**Owner role:** documentation.

**Change policy:** supersede through a new ADR.

## Context

[ADR 0080](0080-public-docs-on-mintlify.md) published the public pages through a hosted docs platform. The platform owned theme selection, font loading and page rendering, so the repository could not guarantee what the first paint shows. An earlier evidence round on the hosted platform recorded a light page under a dark system preference and a title that changed width after the first contentful paint, and fixing those needed overrides on top of a renderer the repository does not own. Dallen's rule for the docs is that the page is server-rendered and complete on first paint: no theme flash, no layout shift on refresh, no late font swap and no entrance animation. His second rule, from 2026-10-18, is that the docs look the way docs.capy.ai looks, in Akter's colours.

## Decision

1. The public docs are a static Next.js export built with Fumadocs in `apps/docs` (`@akter/docs`). It is a private workspace app and publishes nothing to npm.
2. The app reads the Markdown under `docs/` in place; no page is copied or moved, and the pages keep reading correctly on GitHub. `apps/docs/src/content/navigation.ts` is the only list of published pages and products, so a document is published only when it is listed there. Decisions, contracts, architecture, operations internals, verification and vision stay unpublished. The welcome page and the API reference overview are written by the app from that list; each card shows the description of the page it opens.
3. Links are resolved at build time. A link to a published page becomes its route, a link to another repository file becomes a GitHub URL, and a missing page or heading fails the build.
4. Akter hosts the export on Cloudflare at `https://docs.akter.dev`. The export carries `_redirects` (the redirects ADR 0080 configured, plus `/` to `/welcome`), `_headers`, a `.md` twin of every page, `llms.txt`, `llms-full.txt`, a static search index, a sitemap and `robots.txt`. `_headers` sends `Strict-Transport-Security`, `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy` and a `Content-Security-Policy` that matches the hosting platform's own policy, with one difference: `script-src` allows `'unsafe-inline'` because Next writes inline data and bootstrap scripts into every page (up to 30 on one page, so hashing them would exceed Cloudflare's 2,000-character header line). Fonts and images allow `'self'` only, and no page, stylesheet or script names a `data:` URL.
5. The shell follows docs.capy.ai measurement for measurement, in Akter's colours. A fixed 260 px sidebar runs the full height and holds the Akter wordmark, a product switcher (Documentation, and API reference, which swaps the tree and opens an overview page), the search button, the page tree, an Appearance row, an Open Akter link and the X and GitHub icons. The article sits in an inset panel (8 px margin, 12 px radius, 1 px border) with a 720 px reading column and a 220 px table of contents that also holds Copy page and View as Markdown. The contents list is drawn as Capy draws it: one rail path beside the entries and a thumb clipped to the text of the first to the last heading in view, as the Fumadocs anchor observer reports them. The API reference overview is an article in that frame, not a landing grid. Below the desktop breakpoint the sidebar is a 300 px drawer under a 44 px bar. Search is a ⌘K palette with All, Documentation and API reference filters. Backgrounds are Akter's (panel #121311 on #0a0a09 in dark, #fbfbfa on #eeeeed in light) and Akter yellow (#ffc300, the favicon's colour) stands wherever Capy uses its primary colour. The site has no header, no tabs, no Sign in button and no previous and next links; a Capy-only feature with no Akter counterpart (its colour-theme submenu, its Discord link, its product screenshots) is left out.
6. The theme follows `prefers-color-scheme` in CSS until the reader chooses. The Appearance menu offers Light, Dark and System; the choice is kept in local storage under `akter-theme`, and a small inline script in the document head puts it on the root element before the first paint, so the other theme never shows first. System clears the choice. A reader with scripts off gets the operating system's theme.
7. Text is set in Inter and code in Geist Mono, both latin subsets under the SIL Open Font Licence, committed in `docs/fonts/` with their licence texts. `next/font/local` copies each file into the export as `/_next/static/media/<name>.<hash>.woff2`, writes its `@font-face` rule into the render-blocking stylesheet and puts a preload link (`as="font"`, `type="font/woff2"`, `crossorigin`) for both files in the head of every page, so the requests start before the body is parsed, with or without scripts, and the stylesheet's request for a face is served by the preloaded one. The faces are `font-display: optional` and the stylesheet declares `Inter Fallback` and `Geist Mono Fallback` with the faces' metrics, so a face that is late is never swapped in and no line changes width after the first paint. The files are hashed, so `_headers` caches `/_next/static/*` for a year as immutable and no font request revalidates. Next writes no preload on the pages it renders for an unknown address, so the export step copies the welcome page's links into `404.html` and `_not-found.html`, and fails the build if any page lacks both links, names a font that is not in the export, preloads without the anonymous cross-origin mode (which would fetch the file twice), or carries a `data:` URL. An earlier design embedded the fonts as `data:` URLs in the stylesheet and again in every page's head, which raised the mean gzip size of a page from 12.9 KB to 124.2 KB and needed a script to hold the page until the faces decoded; hashed files with a preload keep the HTML at its size without fonts. PolySans and Geist Sans are not used, and the build fails if the export names PolySans.
8. The document scrolls, not a panel inside it. The browser owns history restoration throughout, including Next's client-side navigation. With scripts off it also owns reloads, with the short-delay WebKit exception recorded in the verification document. With scripts on, a small inline script at the end of the body saves the offset in `sessionStorage` under the current route's path on `pagehide`. Only a reload with a saved finite, nonnegative offset runs a bounded correction before the first content frame. WebKit can later restore a stale offset or scroll to the URL's fragment, so the script corrects competing scrolls until the reader interacts, history or the fragment changes, the document is left, or 400 ms after `load`. It never writes `history.scrollRestoration`: an asynchronous manual hold can outlive its history entry, and a timer then updates the wrong entry. Saved zero is distinct from a missing value and needs the same correction as a positive offset. The end marker holds the paint in Chromium; the script cannot run in the head because the document has no height there yet. The inset panel is a frame layer drawn over the scrolling page: a fixed element with the panel's border, radius and shadow, whose spread shadow paints the margin and the rounded corners in the page colour. The sidebar and the contents rail are sticky. Opening a page from the sidebar starts at the top, and an ordinary visit to an address with a hash scrolls to that heading. Below the desktop breakpoint the drawer takes focus when it opens, keeps it (Tab and Shift Tab wrap inside), makes the bar and the page inert, locks the page's scroll, and gives focus back to the button that opened it. Programmatic focus uses `preventScroll`. Mobile header clearance is a scroll margin on article targets, not root scroll padding, so keyboard focus on the sticky header cannot move the reading position. Any link chosen in the drawer closes it, including a link to the page already open, and so does widening the window.
9. The build is reproducible. The Next build id is the commit being built, and syntax highlighting has no time limit, so a loaded machine cannot cut a code line into fewer tokens. `bun run --cwd apps/docs check:reproducible` builds twice, the second time with every CPU busy, and fails if the two exports differ by one byte.
10. Mintlify is removed: `docs/docs.json`, `docs/.mintignore`, `docs/style.css` and the Mintlify-only logo files are deleted.

## Consequences

- `bun run --cwd apps/docs build` produces `apps/docs/out`, the whole deploy artifact. One optional build setting names the origin: `SITE_URL` (default `https://docs.akter.dev`) is used for canonical links, the sitemap, `robots.txt`, `llms.txt`, the Markdown twins and the page actions. It must be a bare `https://` origin, and the build fails if the production site address is still in the export when `SITE_URL` is overridden, if the export names PolySans, or if a page lacks the preload links of both fonts, names a font file the export does not hold, or carries a `data:` URL. The build runs inside a git checkout because the build id is the commit. It needs no network.
- A new public page is added to `navigation.ts`; the build fails if its links or anchors are wrong.
- The first-paint claims are checked by measurement; rerun the matrix in the evidence document when the layout, stylesheet or fonts change. The match with docs.capy.ai is checked by measuring both sites' computed styles and rectangles on the same screens, and the differences that remain are Capy's own content and brand, listed in the evidence document.
- Hosting, the `docs.akter.dev` custom domain and the cutover from Mintlify belong to the private Akter Cloud repository.
- The fonts are two files of 99 KB and 11 KB, requested in parallel with the stylesheet and cached for a year. The first paint does not wait for them: a face that has not arrived by then is not used for that page load, and the fallback faces have the same metrics, so nothing moves when a later load finds the files in cache.
- The sidebar, switcher, search palette, appearance menu and table of contents are the app's own components, so they do not change when Fumadocs does; Fumadocs supplies the content source, the Markdown pipeline, the page tree and the anchor observer behind the contents list. The two menus are Radix dropdowns, which move through their items with the arrow keys, wrap from the last item to the first, and give focus back to their button, and the drawer's focus loop is Radix's focus scope; both packages are MIT.
- A failed search-index download shows an unavailable state instead of an empty result set. Fumadocs caches rejected loads by URL, so each failed attempt advances `/search.json?retry=N`; a new query, filter or palette opening can load the index again without a document reload. A successful load stays cached. The sections file remains optional and shape-checked.
- Each page's head carries two preload links of about 0.3 KB, so a page's HTML is the size it would be without fonts.
- Icons. Capy draws its icons from Central Icons (its pages name them `SquareBehindSquare1`, `Checkmark1` and `ChainLink1`, and ship them under `/icons/central/`). The Iconists licence is per seat, forbids sharing the icons or parts of them publicly and forbids shipping them where an end user can extract them, so they cannot go in this public repository or its export. Akter draws its own glyphs in `apps/docs/src/components/glyphs.tsx` from circles, rounded rectangles and lines on the same 24-unit grid with the same 2-unit round stroke, fitted to the ink bounds of Capy's rendered icons to within 0.75 px, and uses Lucide (ISC) for the page icons that have no Capy counterpart.

## Alternatives

- **Stay on the hosted platform.** Rejected: the first-paint behaviour is not ours to guarantee, and the earlier measurements failed it before overrides.
- **Host on Vercel.** Rejected: Akter hosts the docs itself on Cloudflare, and a static export needs only a file server with redirects and headers.
- **Copy the pages into the app.** Rejected: two copies drift, and GitHub readers would read different text from the site.
- **Fetch the body font from the marketing site at build time.** Rejected: the build then needs the network and a font that is not in the repository, and a second origin cannot reach WebKit before the first paint.

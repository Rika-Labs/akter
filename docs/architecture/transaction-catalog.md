# Transaction catalog

**Responsibility:** show which facts share a commit boundary.  
**Authority:** design.  
**Owner role:** storage/runtime.
**Change policy:** a change that alters a contract guarantee requires an ADR.

| Operation            | In the turn transaction                                                                                                                                                                          | After commit                                                                                                                                                                                                                          |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Command              | generation fence, receipt, dirty keyed state, actor-table writes, events, outbox rows                                                                                                            | reply, then outbox delivery                                                                                                                                                                                                           |
| Turn batch           | each command's fence-scoped receipt and consequences, with declared failures isolated per command; the next batch may run in memory meanwhile                                                    | replies, broadcasts, and outbox visibility for every command                                                                                                                                                                          |
| Intent               | actor-shard `actor_outbox` row                                                                                                                                                                   | relay delivers a direct command keyed by the intent id; row deleted after the receiver's receipt commits                                                                                                                              |
| Timer / cron         | keyed `actor_outbox` row with `due_at`                                                                                                                                                           | due delivery as a direct command; singleton cron has one cluster owner                                                                                                                                                                |
| Effect               | effect obligation in `actor_outbox`                                                                                                                                                              | executor retry; its result is delivered to `onSuccess`, or `onDeadLetter` after exhaustion, as a System command keyed by the effect id                                                                                                |
| Workflow start       | owner-scoped outbox intent; the owner's start turn writes the execution row, version markers, and resume timer (ADR 0022)                                                                        | workflow engine transition                                                                                                                                                                                                            |
| Workflow activity    | no originating actor-turn mutation; actor calls use their own turns                                                                                                                              | the framework engine records the activity `Exit` in `actor_workflow_step`; provider I/O holds no actor turn open                                                                                                                      |
| Subscription         | publisher: event rows and at most one keyed `feed` outbox row; subscriber: receipt, applied cursor, and handler consequences                                                                     | relay expands the feed and delivers each event as a System command; source cursor settled after the subscriber commits                                                                                                                |
| Event                | ordered event row                                                                                                                                                                                | streams, waits, and subscribers observe it                                                                                                                                                                                            |
| Blob                 | actor-scoped blob mutation                                                                                                                                                                       | transport of committed bytes                                                                                                                                                                                                          |
| Connection broadcast | durable changes, if any; the turn that requests it has already woken the actor                                                                                                                   | after the activation's connection rows are loaded, frame flush to each holder, stamped with the activation's flushed-through cursor (and the event's own cursor when sent from an event); parked connections on any runner receive it |
| Connection open      | after `createdBy` is checked and the `open` handler returns: generation fence and the `actor_connections` row, in one short framework transaction with no receipt                                | frames `open` sent, then broadcasts queued while it ran, are flushed; the holder starts forwarding inbound frames                                                                                                                     |
| Connection session   | not a turn: one `UPDATE` of the connection's row after its handler returns, fenced by the activation's generation (acquired first if this activation has none) and guarded by the frame sequence | the holder is acknowledged and sends the next frame                                                                                                                                                                                   |

No transaction remains open while waiting for another actor, a workflow activity, timer, socket, or external provider. A failure before commit delivers none of the staged consequences.

Under [ADR 0022](../decisions/0022-workflow-engine-storage-and-version-markers.md), each engine write (step, status, result, suspend) is its own short transaction that first takes `FOR SHARE` on the owner's generation row and checks the generation, runs no user code, and writes a pending step row before an activity attempt runs; a turn that emits events also re-arms matching workflow waits. The workflow-activity row describes engine persistence, not a continuation of the actor transaction that requested the workflow. Connection frames requested by a turn flush after commit but remain best-effort; durable replay requires an event. Blob mutation means database `bytea` writes, not a network upload to an external provider.

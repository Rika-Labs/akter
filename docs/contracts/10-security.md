# Security and tenancy

**Responsibility:** define trust boundaries and tenant isolation.  
**Authority:** normative.  
**Owner role:** security/runtime.  
**Change policy:** security review is required for auth, SQL, transfer, blob, and admin changes.

`CurrentCaller` MUST be a `Context.Reference` defaulting to `Anonymous` and MUST be set at each trusted edge. Handles capture caller identity when acquired from the ambient value, which `Actor.as(caller)` may scope. `X.Turn` exposes `caller` and `principal`; `X.Workflow` exposes `principal`, while workflow actor calls carry persisted System/on-behalf-of attribution.

For served HTTP, caller identity MUST be resolved per call. Concurrent requests carrying different bearer tokens MUST receive different principals. `Actor.serve` requires auth configuration; `Actor.auth.none` is the explicit public opt-out. When an endpoint requires authentication, missing or invalid credentials MUST fail with `ActorError` reason `Unauthorized`; they MUST NOT run as `Anonymous`. The `Unauthorized` reason has `code` (`error.reason.code` on its `ActorError` wrapper): `missing_credentials`, `invalid_credentials`, or `expired`.

Under the served protocol proposed in [ADR 0027](../decisions/0027-served-protocol.md), the tenant MUST come only from the auth provider; an auth provider MUST NOT produce a `System` caller; a caller's `subject` is at most 512 UTF-8 bytes and its encoding at most 1 KiB; a tenant is 1 to 128 bytes of `[A-Za-z0-9._:-]`; credentials MUST NOT travel in URLs; a browser request (one carrying `Origin`) from an origin that is neither the server's own nor configured MUST be refused before authentication on every route, including WebSocket upgrades and SSE, while requests without `Origin` are served; and a live session's revocation bound is also capped at its credential's expiry. M3.2 enforces these rules on HTTP routes: an oversized subject or encoded caller, or an invalid tenant, fails `Unauthorized` `invalid_credentials` before any turn, and a provider that returns a `System` caller is a defect answered as an opaque 500.

Hosted edge-to-runner requests MUST use signed, short-lived internal assertions over TLS. Runners MUST verify the signature against a trusted issuer/key, permitted algorithm, deployment audience, expiry, and request binding before admitting work, then authorize the requested resource and operation. The edge MUST replace client-supplied attribution. Persist only verified caller attribution, never external credentials or the assertion; its later expiration MUST NOT cancel admitted work. Operator actions require separate scoped capabilities and audited repair intents. See the [authorization model](../security/authorization-model.md).

Stored command outcomes MUST require the original logical caller's current authorization or an explicit receipt-scoped operator capability. Knowledge of a command id MUST NOT grant access or permit a second execution under another caller. Replay authorization MUST NOT depend on rerunning the handler.

Permission revocation MUST block new external admissions and result access, but MUST NOT implicitly cancel already accepted durable work or its internal recovery. Cancellation is explicit; applications MAY reauthorize sensitive steps. Live sessions MUST reauthorize or disconnect within the revocation bound `policy.reauthorizeEvery` (default 60 seconds), including parked-session resumption; the check reuses the runtime's authorization with the connection or stream tag as the operation and a `kind` of `open`, `stream`, or `reauthorize`, closes the session at the bound without extension, fails closed with `Unauthorized` code `reauthorization_unavailable` when no check succeeds, and discards buffered frames on revocation. Connection handlers run with the actor's tenant and the caller stored at open, never a caller taken from frame content. Commands they call use ids derived from a per-connection secret, so a known connection id or sequence number cannot pre-empt them ([ADR 0023](../decisions/0023-connections-parking-and-streams.md)). See [ADR 0004](../decisions/0004-receipt-access-revocation-and-expiry.md).

Internal commands, declared in the `internal` section, MUST be absent from public handles, the Promise client, and served endpoints. They are reachable only by System callers: outbox intents, effect routes, cron, and subscription deliveries; a non-System attempt is a deterministic defect, not a public way to forge executor results. System calls preserve `source`, optional actor reference, and optional `onBehalfOf` principal. Subscription deliveries carry `System({ source: "subscription", ref: <source> })` without `onBehalfOf`, and a command named as a subscription handler accepts only that caller: it is absent from `X.intents`, and any other caller is a deterministic defect. A subscription MUST stay within the source's tenant: no subscription API accepts a tenant, the runtime checks tenant equality again at each delivery, and cross-tenant fan-in uses `Fleet.view`. A source MAY restrict subscriber types with `policy.subscribers` (type names), checked when the runtime layer is built ([ADR 0026](../decisions/0026-cross-actor-event-subscriptions.md)).

One database MUST serve each deployment region; a tenant's rows live only in its home region's database, which only an operator assigns. Tenant isolation MUST use trusted `tenant_id` on every framework and business row, composite indexes, transaction scoping, and optional per-table RLS. Client-supplied tenant, actor id, cursor, connection id, or connection data is input, not authority. Compute placement is `shardGroup`; data placement is Neki shard placement.

Runner-to-runner Cluster traffic, including holder and connection messages, is trusted only over mTLS or an isolated private network; a deployment that claims served transports MUST provide one. Maintenance statements that span tenants (the `actor_connections` sweep, holder-shutdown batches, and holder liveness checks) run under a framework role that optional RLS exempts, and every other framework statement stays tenant scoped. Credentials and sensitive payloads MUST be redacted from logs. Spans MUST be named `durable-actors.<Actor>/<Command>`, and connection handler spans `durable-actors.<Actor>/<Member>.open`, `.frame`, or `.close`. The framework is trusted application infrastructure, not a hostile-code sandbox. Verification: **Per-call caller over HTTP**, **Cluster header size**, and **Workflow tenant isolation** gates.

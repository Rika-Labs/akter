# Security and tenancy

**Responsibility:** define trust boundaries and tenant isolation.  
**Authority:** normative.  
**Owner role:** security/runtime.  
**Change policy:** security review is required for auth, SQL, transfer, blob, and admin changes.

The transport decides who the caller is and which tenant; actors decide what is allowed; ordinary code names neither ([ADR 0059](../decisions/0059-caller-and-tenant-defaults.md)). `CurrentCaller` MUST be a `Context.Reference` defaulting to `System({ source: "process" })` in tenant `"default"`, the trusted caller of code that runs in the application's own process outside a turn and not through `Actors.serve`, and MUST be set at each trusted edge. Handles capture caller identity when acquired from the ambient value, which `Actor.as(caller)` and `Actor.tenant(tenant)` may scope for trusted code that acts on behalf of a user or a tenant. `X.Turn` exposes `caller` and `principal`; `X.Workflow` exposes `principal`, while workflow actor calls carry persisted System/on-behalf-of attribution. Calls from turns, schedules, workflows, jobs, and subscriptions keep their `System` attribution, `onBehalfOf` included.

Authorization is a per-actor `access` policy on `Actor.make` and an optional global `authorize` hook on `Actors.layer`. Both receive `{ caller, ref, command, kind, of }` with `kind` one of `command`, `query`, `open`, `stream`, `feed`, `watch`, `reauthorize`, `content`, or `fleet`, and are asked for every external admission and every live-session recheck; when both exist both MUST allow, and either alone decides when the other is absent. **Secure defaults:** with no `access` and no `authorize`, `System` callers MUST be allowed and `User` and `Anonymous` callers MUST be denied with `Unauthorized` code `access_denied`; those two arrive only through `Actors.serve` or the client. A declared `access` or `authorize` replaces that default for the callers it is asked about. `Actor.access.public` is a ready-made `access` that allows every caller and kind; it opens the actor to anyone who can reach the server, `Anonymous` callers under `Auth.none` included, and MUST be used only for demos and deliberately public actors. `access` MUST NOT turn a non-`System` attempt at an internal command into a success. Verification: the **access** conformance group.

For served HTTP, caller identity MUST be resolved per call. Concurrent requests carrying different bearer tokens MUST receive different principals. `Actors.serve` requires auth configuration; `Auth.none` is the explicit public opt-out. When an endpoint requires authentication, missing or invalid credentials MUST fail with `ActorError` reason `Unauthorized`; they MUST NOT run as `Anonymous`. The `Unauthorized` reason has `code` (`error.reason.code` on its `ActorError` wrapper): `missing_credentials`, `invalid_credentials`, or `expired`.

Under the served protocol of [ADR 0027](../decisions/0027-served-protocol.md), the tenant MUST come only from the auth provider; an auth provider MUST NOT produce a `System` caller; a caller's `subject` is at most 512 UTF-8 bytes and its encoding at most 1 KiB; a tenant is 1 to 128 bytes of `[A-Za-z0-9._:-]`; credentials MUST NOT travel in URLs; a browser request (one carrying `Origin`) from an origin that is neither the server's own nor configured MUST be refused before authentication on every route, including WebSocket upgrades and SSE, while requests without `Origin` are served; and a live session's revocation bound is also capped at its credential's expiry. M3.2 enforces these rules on HTTP routes: an oversized subject or encoded caller, or an invalid tenant, fails `Unauthorized` `invalid_credentials` before any turn, and a provider that returns a `System` caller is a defect answered as an opaque 500.

Hosted edge-to-runner requests MUST use signed, short-lived internal assertions over TLS. Runners MUST verify the signature against a trusted issuer/key, permitted algorithm, deployment audience, expiry, and request binding before admitting work, then authorize the requested resource and operation. The edge MUST replace client-supplied attribution. Built by M4.8 ([ADR 0031](../decisions/0031-hosted-ingress-tenant-directory-and-regions.md), accepted): authentication happens only at the edge; the assertion is a compact JWS signed with Ed25519 and no other algorithm; it lives at most 60 seconds (10 by default) with 5 seconds of skew; its `aud` is the deployment and its `region` the region routed to, and a runner refuses any other; its `req` claim binds the canonical request string of the [wire protocol](protocol.md); the edge strips every client-supplied `durable-assertion`; runners take verification keys from a polled key set, so a revoked signing key stops verifying within 5 minutes; an assertion is signed for one forwarded request and never reaches the client, so a revoked caller makes no new admission; streaming reauthentication goes through the edge with a fresh assertion carrying the session's signed `sid`. Hosted deployments run hosted API keys and declarative JWT settings only, never custom `Auth.make` code. Persist only verified caller attribution, never external credentials or the assertion; its later expiration MUST NOT cancel admitted work. Operator actions require separate scoped capabilities and audited repair intents. See the [authorization model](../security/authorization-model.md).

Stored command outcomes MUST require the original logical caller's current authorization or an explicit receipt-scoped operator capability. Knowledge of a command id MUST NOT grant access or permit a second execution under another caller. Replay authorization MUST NOT depend on rerunning the handler.

An operator export of an actor's state and pending work MUST need its own `export` capability scoped to the tenant and, optionally, actor type and id, which no other operator action implies. It MUST run in one read-only snapshot, be audited before it is answered (a refusal by scope audited as denied), and MUST NOT carry the tenant, any caller, or any credential, so a seed replayed by a test cannot confer authority. It is a seed of current state and pending work, not history.

Permission revocation MUST block new external admissions and result access, but MUST NOT implicitly cancel already accepted durable work or its internal recovery. Cancellation is explicit; applications MAY reauthorize sensitive steps. Live sessions MUST reauthorize or disconnect within the revocation bound `policy.reauthorizeEvery` (default 60 seconds), including parked-session resumption; the check reuses the actor's `access` policy and the runtime's `authorize` with the connection or stream tag as the operation and a `kind` of `open`, `stream`, or `reauthorize`, closes the session at the bound without extension, fails closed with `Unauthorized` code `reauthorization_unavailable` when no check succeeds, and discards buffered frames on revocation. Connection handlers run with the actor's tenant and the caller stored at open, never a caller taken from frame content. Commands they call use ids derived from a per-connection secret, so a known connection id or sequence number cannot pre-empt them ([ADR 0023](../decisions/0023-connections-parking-and-streams.md)). See [ADR 0004](../decisions/0004-receipt-access-revocation-and-expiry.md).

Internal commands, declared in the `internal` section, MUST be absent from public handles, the Promise client, and served endpoints. They are reachable only by System callers: outbox intents, job routes, schedules, and subscription deliveries; a non-System attempt is a deterministic defect, not a public way to forge executor results. System calls preserve `source`, optional actor reference, and optional `onBehalfOf` principal. Subscription deliveries carry `System({ source: "subscription", ref: <source> })` without `onBehalfOf`, and a command named as a subscription handler accepts only that caller: it is absent from `X.intents`, and any other caller is a deterministic defect. A subscription MUST stay within the source's tenant: no subscription API accepts a tenant, the runtime checks tenant equality again at each delivery, and cross-tenant fan-in uses `Fleet.view`. A source MAY restrict subscriber types with `policy.allowedSubscriberTypes` (type names), checked at the subscriber's `Actor.make` ([ADR 0026](../decisions/0026-cross-actor-event-subscriptions.md)).

One database MUST serve each deployment region; a tenant's rows live only in its home region's database, which only an operator assigns. Tenant isolation MUST use trusted `tenant_id` on every framework and business row, composite indexes, transaction scoping, and optional per-table RLS. The optional RLS is a `durable_tenant` policy on every tenant-bearing framework and owned table, keyed by the transaction's `durable.tenant` setting, which exempts the table owner. With `rowLevelSecurity` on, every command turn, query, and caller-facing read outside a turn (event feeds, workflow polls, and blob, row, and event reads by stream and connection handlers) MUST run as the configured tenant role with its actor's tenant set; framework maintenance statements keep the connecting role and stay scoped by explicit predicates. The runtime MUST refuse to start when that role is exempt from RLS, cannot be taken, lacks grants, or owns a protected table, when any inspection view is not owned by a view-owner role that the policies bind (not a superuser, not `BYPASSRLS`, not an owner of a table with RLS on) and that the tenant role cannot act as, or when a tenant-bearing table lacks the policy ([ADR 0051](../decisions/0051-row-level-security.md)). An enforced adopted table ([ADR 0054](../decisions/0054-existing-schema-adoption.md)) narrows who may write it in the database itself: only the runtime's writer role and the roles named at enforcement pass its guard trigger, and a role that can act as the table's owner, or take the writer role, could undo that, which enforcement refuses. The runtime's turn marker (`durable.turn`) only classifies recorded legacy writes; it never authorizes one, and a login shared by the application and the runtime is supported for observation only, because a login that can take the writer role can do what the runtime does. Client-supplied tenant, actor id, cursor, connection id, or connection data is input, not authority. Built by M4.8 ([ADR 0031](../decisions/0031-hosted-ingress-tenant-directory-and-regions.md), accepted): the tenant directory in the control plane maps each tenant to its home region; a tenant with no row lives in the primary region, and no request writes a row. Built by M4.13 ([ADR 0034](../decisions/0034-tenant-scoped-content-addressed-blobs.md)): knowing a content hash never grants a read; a content grant is an HMAC over the deployment (a random id `0020_content_blobs` stores in `actor_deployment`), tenant, hash, size, and a one-hour expiry; `Content.grant` and the served download run `access` and `authorize` with kind `content` and `<blob>.grant` or `<blob>.get`; job executors hold no content capability; content is deduplicated within a tenant, never across tenants. Target, built by L.2 ([ADR 0036](../decisions/0036-cold-tier.md), accepted): cold-tier object keys and runner credentials are scoped to the deployment and tenant. Compute placement is Effect Cluster's shard assignment of each actor; data placement is Neki shard placement.

Runner-to-runner Cluster traffic, including holder and connection messages, is trusted only over mTLS or an isolated private network; a deployment that claims served transports MUST provide one. Built by #541 ([ADR 0086](../decisions/0086-runner-mutual-tls.md)): `Runner.mtls` speaks TLS 1.3 only; each side MUST present a certificate whose only subject alternative name is the URI `spiffe://akter/deployment/<deployment>` and MUST refuse a peer without a certificate, a plaintext peer, a peer whose chain does not reach a trusted authority, a peer outside its validity window, a peer whose certificate names anything else, and a peer of another deployment before any runner message is handled or sent, whatever the process's TLS environment overrides; sessions are never resumed, so every connection is verified in a full handshake; credentials are reloaded so certificates, keys and authorities rotate without a restart, a runner whose certificate expired or whose loads keep failing reports not ready (`peering`), and established sessions are not reauthenticated. Framework statements outside command turns and queries run as the connecting role, which optional RLS exempts. That includes those that span tenants: relay and executor claims and settles, retention, workflow recovery, subscription fan-out, the `actor_connections` sweep, holder-shutdown batches, and holder liveness checks. Every framework statement that serves one actor stays scoped by explicit tenant predicates. The `durable` inspection views are read-only for every role; a role granted only that schema MUST be unable to read any `actor_*` table. Without RLS, view access is operator access to every tenant in the database. With RLS, the views belong to the tenant role and return only the tenant the reader's transaction names ([ADR 0028](../decisions/0028-sql-inspection-views.md), [ADR 0051](../decisions/0051-row-level-security.md)). The local inspector (`Inspector.serve`, served by `durable dev`) MUST read only the authenticated principal's tenant, taken from its credential and never from the request, and only through those views inside a read-only transaction. Credentials and sensitive payloads MUST be redacted from logs. Spans MUST be named `akter.<Actor>/<Command>`, and connection handler spans `akter.<Actor>/<Member>.open`, `.frame`, or `.close`. The framework is trusted application infrastructure, not a hostile-code sandbox. Verification: **Per-call caller over HTTP**, **Cluster header size**, and **Workflow tenant isolation** gates.

# Messaging and events

**Responsibility:** define actor communication and durable publication.  
**Authority:** normative.  
**Owner role:** runtime/realtime.  
**Change policy:** wire changes require protocol versioning and replay tests.

Outside a turn, a command call MUST be a direct request/reply: it runs in the owner's turn, and the committed receipt is its only durable admission record. Handles MUST retry retryable failures with the same command id. There is no persisted or fire-and-forget command call ([ADR 0011](../decisions/0011-direct-commands-outbox-and-performance.md)).

Inside a command turn, `X.intents(id)` methods, including `Intent.after`/`Intent.at` timers and workflow starts, MUST write `actor_outbox` rows on the sending actor's shard in the turn transaction. They MUST be delivered only after commit, as direct commands whose command id is the intent id, and MAY be delivered more than once; receiver receipts provide idempotency. `Intent.cancel(key)` MUST remove a pending keyed timer in the same transaction. A timer whose delivery the relay has already begun is firing, not pending: cancelling or replacing its key does not stop that delivery, which completes at most one receiver transition, so handlers that must ignore a superseded timer check actor state. Any runner's relay may claim a due row with a lease. A claimed row is not due until its claim settles or its lease ends; a row whose claiming relay dies is delivered again, under the same intent id, after the lease ends. A row whose delivery fails or whose settle dies MUST back off with a capped delay, so it cannot hold back newer due rows; committed intents have no retry limit ([ADR 0021](../decisions/0021-multi-runner-relay-singleton-and-cron.md)). Delivering a committed intent is trusted internal recovery of accepted work: it MUST NOT be refused because the originating caller lost access or the external retry window elapsed ([ADR 0011](../decisions/0011-direct-commands-outbox-and-performance.md), [receipts](04-receipts.md)).

A `schedules` entry is a keyed timer on its own actor, with the reserved key prefix `$cron:`; application code MUST NOT stage or cancel a `$cron:` key. The prefix `$job:` is reserved for keyed jobs ([ADR 0024](../decisions/0024-effect-cancellation-and-per-actor-concurrency.md)), which share the sender's key index but not intent keys' namespace. Under [ADR 0025](../decisions/0025-turn-mint.md), the creating intent to a child minted by `turn.mint` carries `mint: { commandId, ordinal }` on its System caller, and the child's `createdBy` check accepts it only when that proof derives the child's id. The rest of a tick's key names its entry: the time zone and canonical expression, or the interval, so one expression in two zones is two keys ([ADR 0042](../decisions/0042-cron-time-zones-intervals-and-daylight-saving.md)). At most one tick per entry is pending; a claimed tick fires once and is rewritten to the next scheduled time only after its receipt commits ([background work](08-background-work.md)).

A creating intent's relay delivery MUST carry the committed outbox row's sender provenance alongside its target, caller, command id, command, and payload. The child's first turn MUST validate that provenance and the mint derivation without reading the parent's shard, as specified by [actor authority](01-actor-authority.md) and [ADR 0048's amendment](../decisions/0048-mint-progress-and-inspection-record-corrections.md#amendment-child-local-creating-intent-proof-485-2026-10-03). The sender's row remains until the receiver's committed outcome permits deletion; a redelivery MUST replay the child's receipt even after the row is gone.

Request/reply inside a turn is forbidden. Messaging does not create a distributed transaction and MUST NOT be presented as a synchronous remote call from the sender's transaction.

Due-work claims MUST probe one inclusive bucket range from the data shard map at a time, independently of actor compute ownership. All claim families MUST share the runner's free capacity across ranges; no range may claim rows that cannot start immediately. The ordinary single-database map covers all 256 buckets in one range and MUST add no statement or network flight to a claim. A failed claim or settle MUST preserve the existing lease and retry identity rules. Neki-targeted ranges and provider-specific routing remain gated by provider evidence ([ADR 0067](../decisions/0067-due-work-shard-ranges.md)).

Every statement that compares or sets a due time MUST read the outbox clock once, from the database that holds the rows: the statement's start time on Postgres and PGlite, and the shard's `clock_timestamp()` on Neki. On Neki, statements on the turn, relay and Cluster storage paths MUST avoid the SQL the router refuses, which [ADR 0092](../decisions/0092-neki-runtime-sql.md) lists as found on a live single-shard router.

`turn.emit` MUST append an owner-scoped event only if the turn commits. Events MUST have a monotonically ordered cursor within their declared actor stream; the sequence MUST be assigned under the generation fence, MUST have no gaps between committed events, and MUST never be reissued after pruning. Replay MUST either resume after a valid cursor or return an explicit cursor/retention failure; it MUST NOT silently skip committed events. Built by M4.7 ([ADR 0032](../decisions/0032-event-and-effect-payload-evolution.md), accepted): every committed event stores its payload version; replay, feeds, subscription deliveries, and workflow waits decode it through the event class's chain; a value the chain cannot decode is a defect, never a skip.

A subscriber MAY declare `Actor.subscription` members that follow another actor type's declared events in the same tenant ([ADR 0026](../decisions/0026-cross-actor-event-subscriptions.md)). A committed source event MUST reach each matching subscription as a System command turn delivered through the outbox relay, and MUST take effect exactly once per active subscription, epoch, source, and cursor: the derived command id's receipt and the subscriber's applied cursor both deduplicate it. The only exceptions, each counted: routed events committed before the source's routed row exists (a routed subscription starts at that row), routed events for a subscriber whose `createdBy` refuses creation, and gaps on an id-routed row, which has no recipient for them. Within one subscription row, deliveries MUST follow source cursor order, with one in flight; nothing else is ordered. A rolled-back source turn MUST deliver nothing. Pruned history MUST reach a dynamic or singleton-routed subscriber as a `RetentionGap` delivery, never a skip. The publisher's turn MUST NOT do work proportional to its subscribers. Delivery wakes a hibernated or parked subscriber like any command. A workflow that waits for another actor's event does so through an owner subscription whose handler emits an owner event; see gate **Subscription delivery**.

A workflow's owner-event wait (`Ship.wait(name, Event)`, called with `{ where, timeout }`) MUST observe only the owner actor's events, and registration MUST close the start-to-wait race. Per [ADR 0022](../decisions/0022-workflow-engine-storage-and-version-markers.md): a wait sees the owner's events after its execution's cursor, which starts at the start anchor (for a workflow started by its owner's own turn, the owner's event sequence before that turn's emits, so the starting turn's events are visible) and advances past each resolved wait; it resolves with the lowest-sequence matching event, and exactly once when the event races its timeout. Registration and event appends lock the same generation row, so one of them always sees the other. See gates **Intent rollback**, **Outbox delivery**, and **waitFor registration** in conformance.

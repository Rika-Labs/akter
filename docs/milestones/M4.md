# M4: Operations, tenancy, and hosting

**Responsibility:** define the M4 slices, their order, and the exit test.  
**Authority:** delivery plan.  
**Owner role:** delivery/runtime lead.
**Change policy:** a change requires delivery lead sign-off.

M4 makes the framework operable in its three deployment shapes: embedded, served, and hosted ([vision](../vision/07-deployment.md)). It adds:

- readiness and bounded drain;
- observability;
- migrations, backup and restore;
- optional row-level security;
- operator authority;
- evolution of stored event and effect payloads;
- a single-region hosted edge;
- read-your-writes from replicas;
- parent-actor placement;
- tenant-scoped content-addressed blobs;
- PGlite as a supported embedded production backend, with stated durability limits.

M4 is single-region. Multi-region placement and the cold tier each get an ADR here and are built later, when hosted usage asks for them ([later](#later-when-hosted-usage-asks)).

The exit test is a rehearsal on the served chat room from M3:

1. deploy it;
2. drain a runner under load;
3. fail over the Postgres primary;
4. restore a backup;
5. show that no command ran twice or got lost.

## Slice details

**M4.2: drain.**

- **What it builds:** `RuntimeControl` from [ADR 0003](../decisions/0003-failure-scoping-drain-and-hosted-trust.md). Draining refuses new admission, lets in-flight turns finish until a deadline, and then interrupts them. Pending durable work stays recoverable. The outcome says whether the drain finished cleanly or hit the deadline.
- **Evidence:** the **Bounded graceful drain** check, and the row "Drain deadline expires", both on the multi-runner harness.

**M4.3: observability.**

- **What it builds:** OTLP spans for admission, turn, commit, relay and effect execution with stable names, and Prometheus metrics for mailbox age, relay lag, receipt, event and outbox growth, pool waits, and activation counts. `durable defects list` reads defect spans from the telemetry exporter.
- **Evidence:** a span assertion for invariant O1.

**M4.4: migrations and restore.**

- **What it builds:** an expand-and-contract migration guide for framework and business tables, and a restore rehearsal on Postgres.
- **Evidence:** invariant D1, R5's restore cases, the row "Restore, clock change, or version skew at the retry horizon", and the mixed-supported-versions part of **Finite retry horizon and safe cleanup** (two runtime versions behind one database during a rolling deploy).

**M4.5: row-level security.** Opt-in RLS policies on framework and owned tables, keyed by the transaction's tenant scope. [ADR 0051](../decisions/0051-row-level-security.md) records the design: a `durable_tenant` policy keyed by the `durable.tenant` setting, command turns and queries run as a configured tenant role, cross-tenant framework maintenance stays exempt, and the inspection views keep owner rights but belong to that role instead of switching to `security_invoker`.

- **Evidence:** S2 with RLS on, and the support-matrix row "Tenant-scoped transactions".

**M4.6: operator authority.**

- **What it builds:** operator capabilities scoped by action and resource, audited repair intents, `durable inspect Room/r1`, and the operator subscription skip of [ADR 0026](../decisions/0026-cross-actor-event-subscriptions.md) question 6. The runtime never prunes operator audit rows.
- **Evidence:** the operator half of the **Hosted assertions and operator authority** check, the operator half of **Receipt access without re-execution** (a scoped operator reads an outcome without re-executing it), and the row "Application credential attempts operator repair".

**M4.7: payload evolution.** Today a stored event that no longer decodes fails its query ([M1.5](M1.md)). Events and effect payloads get a declared migration chain, as state has.

**M4.8: hosted edge.**

- **What it builds:** the edge authenticates a request and issues a short-lived signed assertion bound to:
  - the actor;
  - the operation;
  - the command id;
  - the payload.

  Runners verify the assertion before admission.

- **Evidence:** the **Hosted assertions and operator authority** check (edge half), and the row "Hosted assertion forged, expired, or bound to a different request".

**M4.9: read-your-writes.** A handle sends the highest commit version it has seen, and a replica answers only once it has caught up to that version.

- **Evidence:** Q1 and the **Read-your-writes** check against a real streaming replica.

**M4.11: parent-actor placement.** This is the third placement kind from [ADR 0006](../decisions/0006-scale-rules-placement-and-query-tiers.md).

- **Evidence:** the **Placement and single-shard paths** check for it.

**T10: Postgres failover drill.** A streaming replica is promoted under load. Commit-unknown outcomes resolve through receipts, and there's no duplicate or lost work.

- Status: `crash/drills/failover.test.ts` runs in `test:integration` with its own primary and synchronous standby in Docker ([ledger](../verification/01-conformance.md#postgres-primary-failover-drill-t10)). No work is lost or duplicated, and commit-unknown turns resolve through receipts. Every runner commits again within about a second of the kill (0.36–0.90 s, p50 0.47 s over ten runs; 1.11 s in a later run) (#243's fix).

**M4.13: tenant-scoped content-addressed blobs.** General uses: shared attachments, and deduplicating identical uploads across a tenant's actors.

- **What ADR 0034 decides.** It amends [contract 06](../contracts/06-storage-ownership.md), where every blob is actor-owned today:
  - **Access.** Knowing a hash never grants a read. A read needs a reference held by an actor the caller can reach, the same way knowing a command id doesn't grant receipt access ([contract 04](../contracts/04-receipts.md)).
  - **GC.** Reference counts or mark-and-sweep with a grace period, safe under concurrent add and remove.
  - **Placement.** Content lives on the tenant's routing key. A turn of an actor-placed actor that references it touches two shards on Neki, which [ADR 0006](../decisions/0006-scale-rules-placement-and-query-tiers.md)'s single-shard rule forbids on hot paths, so the ADR says how references cross (for example through the outbox) and how per-tenant reference counts avoid a hot row.
  - **Retention** of unreferenced content.
- **Evidence:** hash-knowledge denial; GC safety under concurrent references on Postgres; tenant isolation (S2); references roll back with the turn (T1).
- **Benchmark:** `content-blobs`: dedup ratio and write cost.

**M4.14: PGlite as an embedded production backend.** Today PGlite is a test and local-development backend ([support matrix](../operations/support-matrix.md)).

- **What ADR 0035 decides** and states as limits:
  - one process per `dataDir`, enforced by a lock, so a second process is refused;
  - a crash-safe `dataDir`: a SIGKILL mid-turn recovers to the last commit;
  - migrations on existing data;
  - backup by a stopped copy or `pg_dump`;
  - no contention or multi-runner claims.
- **Also amends** the docs that call PGlite test-only: the [conformance ledger](../verification/01-conformance.md), the [support matrix](../operations/support-matrix.md), and the [developer-experience vision](../vision/06-developer-experience.md).
- **Evidence:** SIGKILL cases on a file-backed PGlite; the second-process refusal; a new support-matrix row.
- **Benchmark:** turn and wake latency on a file-backed PGlite.

## Later: when hosted usage asks

Regional placement and the cold tier are designed in M4 (ADR 0031 and ADR 0036) and built only when hosted usage asks for them.

| Slice | What it adds                                                                  | Evidence when built                                                                                                                 |
| ----- | ----------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| L.1   | Regional placement: home-region routing, cross-region relay, and tenant moves | The **Regional placement** check, the support-matrix row "Multi-region home placement", and the **Remote users** required benchmark |
| L.2   | The cold tier (`cold_ref`)                                                    | Wake rehydrates within the wake-latency target; offload and rehydrate are crash-safe                                                |

M4.1 records **Regional placement** and **Remote users** as deferred in the ledger and the [performance document](../verification/03-performance.md), and M5.5 marks them unsupported, together with the cross-region paths of the **Outbox delivery** gate.

## Excluded

- Neki-specific gates are M5.
- Regions, tenant moves between regions, and the cold tier's build ([later](#later-when-hosted-usage-asks)).
- Scale runs at 10^7 stored actors are in [#66](https://github.com/Rika-Labs/durable-actors/issues/66).
- Automatic hot-tenant detection is excluded, because moves are operator actions ([ADR 0011](../decisions/0011-direct-commands-outbox-and-performance.md)).

## The operated chat room

```ts
// Readiness and drain on the served runner (M4.2)
const drain = Effect.gen(function* () {
  const runner = yield* RuntimeControl
  return yield* runner.drain({ deadline: "30 seconds" }) // "clean" | "deadline-expired"
})

// Opt-in row-level security (M4.5, ADR 0051)
Actors.layer({ authorize, rowLevelSecurity: { role: "durable_tenant" } })
```


## Exit criteria

M4 is complete when all of these hold:

- Every slice is merged with its cases passing in CI.
- The rehearsal (drain, failover, restore) passes and its results are recorded.
- The runbooks cover every failure M4 claims to recover from.
- The support matrix records migrations and restore, tenant-scoped transactions, and the hosted single-region path on Postgres, and PGlite as an embedded backend within its stated limits.

Neki remains gated until M5 and [#66](https://github.com/Rika-Labs/durable-actors/issues/66).

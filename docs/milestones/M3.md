# M3: Served actors and the browser client

**Responsibility:** define the M3 slices, their order, and the exit test.  
**Authority:** delivery plan.  
**Owner role:** delivery/runtime lead.
**Change policy:** a change requires delivery lead sign-off.

M3 serves actors over the network with `Actor.serve`:

- HTTP commands and queries, with OpenAPI;
- WebSocket connections;
- SSE event feeds;
- the browser-safe Promise client, `durable-actors/client`, which runs reducers optimistically.

The exit test is `examples/chat` served to a browser UI, driven by a Playwright test that loses its connection, reconnects, and replays from its cursor.

Spellings follow [server API](../api/01-server-api.md), the [TypeScript SDK](../api/03-typescript-sdk.md), the [protocol contract](../contracts/protocol.md), and the [error model](../contracts/error-model.md). ADR 0024 settles the wire format.

## Rules for every slice

The [M2 rules](M2.md#rules-for-every-slice) apply. Transport slices also follow [contract 07](../contracts/07-realtime.md)'s change policy: every transport tests the race between a snapshot and live events, loss, replay, and revocation.

## Slice details

**M3.1: ADR 0024, the served protocol.** It decides:

- the wire format for commands, queries, event feeds, and connections;
- how the command id and its expiry travel;
- the error envelope: `retryAfter`, `InvalidInput`, and `TransportError` exist only at this boundary;
- `Actor.serve` authentication: `Actor.auth.none` is the explicit opt-out, and a JWT verifier is the first provider;
- how OpenAPI is generated;
- the principal header size limit;
- SSE resume from an exclusive cursor;
- the revocation bound for live sessions (ADR 0023's default, carried over the wire).

**M3.2: HTTP.**

- **Evidence:**
  - the **Per-call caller over HTTP** gate and H1;
  - R3 over HTTP;
  - the row "HTTP credentials absent/changed";
  - the **Internal section** check: internal commands are absent from HTTP and OpenAPI;
  - `retryAfter` on retryable reasons.
- **Benchmark:** `http`, which measures transport overhead against the embedded path.

**M3.3: WebSocket and SSE.**

- **Evidence:**
  - contract 07's four transport tests;
  - rows "Socket-owning process dies" and "Live or parked session loses authorization";
  - a parked connection stays parked over a real socket.
- **Benchmark:** `ws` and `sse`, covering reconnect waves and fan-out.

**M3.4: Promise client.**

- **Behavior:** a command keeps its id across retries. An expired id comes back as `CommandExpired`, and the client never mints a replacement. Feeds are `AsyncIterable`, and connections have typed `send` and `close`.
- **Evidence:** R3 through the client, plus rows "Caller gives up before a reply" and "External identity expires before delivery or retry".
- **Benchmark:** `client`.

**M3.5: optimistic reducers.**

- **Behavior:** a browser handle applies a reducer at once, reapplies pending inputs on top of each committed state, and drops each input when its receipt arrives.
- **Evidence:** C3, the row "Optimistic reducer rejected by the server", and the client half of the **Reducers** check, in a Playwright e2e test.

**M3.6: examples.**

- The chat room is served to a small browser UI.
- `examples/coding-agent` is a showcase built only from public members: effects, workflows, and streams. It adds no framework feature ([vision](../vision/06-developer-experience.md)).

**T9: M3 scale run.** It covers:

- transport p50 and p99 against the embedded path;
- reconnect waves;
- the 16 KiB connection-state limit;
- parked-connection memory;
- the largest supported principal header.

## Excluded

- Read-your-writes from replicas (Q1), the hosted edge, and signed assertions are M4.
- Offline clients and generated MCP and Python clients are M6.
- Live query `watch` is M6.

## The served chat room

### Server (`examples/chat/src/main.ts`)

```ts
const ChatServer = Actor.serve({
  actors: [RoomLive, RoomReads, RoomEffects, DigestLive],
  auth: Actor.auth.jwt({ issuer, audience: "chat" }), // proposed; ADR 0024 settles the provider API
  openapi: { path: "/openapi.json" },
})

BunRuntime.runMain(
  Layer.launch(
    ChatServer.pipe(Layer.provide(Actors.layer({ database: Database.postgres({ url }) }))),
  ),
)
```

### Browser (`examples/chat/src/web/room.ts`)

```ts
import { Room } from "../room/contract.ts"

const room = Room.client({ baseUrl: "/api", headers: { authorization } }).get(roomId)

await room.SetTyping(1) // applied to room.state at once, confirmed or rolled back by its receipt
const id = await room.Post({ body: "hello" }) // same command id across retries

for await (const entry of room.History.events({ after: cursor })) render(entry)

const presence = await room.Presence.connect({ user: me })
presence.send({ typing: true })
for await (const frame of presence.frames) showTyping(frame.typing)
```

### What the tests prove

```ts
test("replays events after a dropped socket and never shows a gap as continuous", async ({ page }) => {
  await page.goto("/rooms/r1")
  await post(page, "one")
  await page.context().setOffline(true)
  await server.post("r1", "two") // committed while the browser is away
  await page.context().setOffline(false)
  await expect(page.getByTestId("messages")).toHaveText(["one", "two"])
})
```

## Exit criteria

M3 is complete when all of these hold:

- Every slice is merged with its cases passing on Postgres in CI, and on PGlite where they apply.
- The Playwright test for the chat room passes in CI.
- T9's results are in the [performance document](../verification/03-performance.md).
- The support matrix records served HTTP, WebSocket, and SSE on Postgres.

This closes self-hosted served support on one Postgres database. It does not close hosted support.

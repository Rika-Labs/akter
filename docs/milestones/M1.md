# M1 — Actor members and durable consequences

**Responsibility:** define the M1 slices, their order, and the exit test.  
**Authority:** delivery plan.  
**Owner role:** delivery/runtime lead.
**Change policy:** a change requires delivery lead sign-off.

M1 adds the rest of the actor definition on top of the M0 turn: owned tables, blobs, events, intents and timers, effects with routes, server reducers, and retention. The plan was approved on 2026-09-24. Its exit test is `examples/chat` running end to end, built from every slice; the code below is that example.

Spellings follow the target API in [server API](../api/01-server-api.md), [context](../api/02-context.md), [Drizzle](../api/04-drizzle.md), and the [contracts](../contracts/README.md). Where those docs name a member but not its declaration (`Actor.effect`, `Actor.blob`, `Actor.table` options), the shape below is **proposed** and is settled in that slice's PR, which updates the API docs to match.

## Order of work

1. **Plan and issues** ([#29](https://github.com/Rika-Labs/durable-actors/issues/29), docs): this document, [ADR 0017](../decisions/0017-m1-record-corrections.md), and the stale-claim fixes.
2. **In parallel:** M1.6 outbox, intents, and timers (L); M1.4 owned tables (L); M1.5 events (M); M1.8 reducers (M, no storage).
3. **After M1.4:** blobs (M), which reuse its ownership helpers.
4. **After M1.6:** M1.7 effects (L), which travel through the outbox.
5. **Last:** M1.9 retention plus `examples/chat` (M), the exit test below.

## Rules for every slice

- The branch is `type/<issue>-slug`, for example `feat/14-outbox`; CI rejects other names.
- Each slice uses only its assigned migration number. The Effect migrator skips an id at or below the latest applied one, so migrations land in number order on `main` only if each PR rebases before merge; a local database that already ran a higher-numbered M1 migration must be recreated.
- Each slice adds its cases to its own conformance file and registers them through `describeConformance`, so the same named cases run on PGlite and real Postgres. Crash and lock-contention cases run on Postgres.
- Every durable transition gets a failure test. The [conformance ledger](../verification/01-conformance.md), the [failure matrix](../verification/02-failure-matrix.md), and the [invariants](../verification/invariants.md) name the required evidence; the slice updates the ledger with its case names and executed counts.
- A slice that changes behavior updates its contract, API docs, and verification docs in the same PR.

## Excluded

- Anything multi-runner: relay ownership across runners, commutative reducer merging, and singleton failover wait for the M2 harness.
- Browser optimistic reducers (invariant C3) wait for the M3 client.
- Tenant-scoped content-addressed blobs, external object storage, effect cancellation and concurrency caps, executor live frames, and `turn.mint` need their own ADRs before they are scheduled.
- Cold state (`cold_ref`), `Fleet.view`, workflows, connections, streams, cron, and transports.

## Decisions taken for M1

[ADR 0017](../decisions/0017-m1-record-corrections.md) records two defaults accepted with this plan: state uses plain zstd with a stored codec version instead of per-actor-type dictionaries ([contract 06](../contracts/06-storage-ownership.md)), and `placement: "tenant" | "actor"` is the accepted API, with parent-actor placement still target.

## The chat room, one slice at a time

### Contract (`examples/chat/src/room/contract.ts`)

```ts
import { Actor } from "durable-actors"
import { pgTable, text, timestamp, integer } from "drizzle-orm/pg-core"
import { Effect, Result, Schema } from "effect"

export const RoomId = Schema.String.pipe(Schema.brand("RoomId"))

// M1.4: an owned table. The framework adds tenant_id, actor_id, and routing_key.
export const messages = Actor.table(
  pgTable("chat_messages", {
    id: text("id").primaryKey(),
    author: text("author").notNull(),
    body: text("body").notNull(),
    sentAt: timestamp("sent_at", { withTimezone: true }).notNull(),
    attachment: text("attachment"), // blob name, if any
  }),
)

// M1.blob: database-backed binary chunks, rolled back with the turn. (declaration shape proposed)
export const Attachments = Actor.blob("attachments")

// M1.5: events, appended only when the turn commits, replayable by cursor.
export class MessagePosted extends Actor.Event<MessagePosted>()("MessagePosted", {
  id: Schema.String,
  author: Schema.String,
  body: Schema.String,
}) {}
export class RoomArchived extends Actor.Event<RoomArchived>()("RoomArchived", {}) {}

// M1.7: external I/O requested in a turn, run after commit. (class shape proposed)
export class ModerateMessage extends Actor.effect<ModerateMessage>()("ModerateMessage", {
  input: { id: Schema.String, body: Schema.String },
  success: Schema.Struct({ id: Schema.String, flagged: Schema.Boolean }),
}) {}

export class RoomClosed extends Schema.TaggedError<RoomClosed>()("RoomClosed", {}) {}

export const RoomState = Actor.state({
  closed: Schema.Boolean.pipe(Schema.withDecodingDefault(Effect.succeed(false))),
  typing: Schema.Int.pipe(Schema.withDecodingDefault(Effect.succeed(0))),
})

// M1.8: a pure transition with no server handler; the M3 client will run it optimistically.
export const SetTyping = Actor.reducer("SetTyping", {
  state: RoomState,
  input: Schema.Int,
  reduce: (state, typing) => Result.succeed({ ...state, typing }),
})

export const Post = Actor.command("Post", {
  input: { body: Schema.String, file: Schema.optional(Schema.Uint8Array) },
  output: Schema.String,
  errors: [RoomClosed],
})
export const Archive = Actor.command("Archive")
export const Recent = Actor.query("Recent", {
  input: { limit: Schema.Int },
  output: Schema.Array(
    Schema.Struct({ id: Schema.String, author: Schema.String, body: Schema.String }),
  ),
})
export const History = Actor.query("History", {
  input: { after: Schema.optional(Schema.String) },
  output: Schema.Array(MessagePosted),
})

// Internal commands: only System callers (the relay, effect routes, cron) can reach them.
export const IdleCheck = Actor.command("IdleCheck")
export const Moderated = Actor.command("Moderated", {
  input: Schema.Struct({ id: Schema.String, flagged: Schema.Boolean }),
})
export const ModerationFailed = Actor.command("ModerationFailed", {
  input: Actor.DeadLetter(ModerateMessage),
})

export const Room = Actor.make("Room", {
  key: RoomId,
  state: RoomState,
  tables: [messages],
  blobs: [Attachments],
  events: [MessagePosted, RoomArchived],
  effects: [ModerateMessage],
  api: { Post, Archive, Recent, History, SetTyping },
  internal: { IdleCheck, Moderated, ModerationFailed },
  policy: {
    keepReceipts: "7 days", // M1.9
    keepEvents: "30 days", // M1.9
    effects: {
      ModerateMessage: {
        retry: { times: 5 },
        onSuccess: Moderated, // must accept the executor's return type, or it doesn't compile
        onDeadLetter: ModerationFailed,
      },
    },
  },
})
```

### Command handlers (`examples/chat/src/room/layer.ts`)

```ts
import { DateTime, Effect } from "effect"
import { Intent } from "durable-actors"
import {
  Room,
  RoomClosed,
  messages,
  Attachments,
  MessagePosted,
  RoomArchived,
  ModerateMessage,
} from "./contract.ts"

export const RoomLive = Room.toLayer(
  Effect.succeed({
    Post: Effect.fn(function* ({ body, file }) {
      const turn = yield* Room.Turn
      if (turn.state.closed) return yield* new RoomClosed() // rolls back everything below

      const id = turn.commandId
      if (file) yield* turn.blob(Attachments).set(id, file) // M1.blob

      // M1.4: no tenant_id / actor_id here; the framework adds and enforces them.
      yield* turn.rows(messages).insert({
        id,
        author: turn.caller.id,
        body,
        sentAt: yield* DateTime.now,
        attachment: file ? id : null,
      })

      yield* turn.emit(new MessagePosted({ id, author: turn.caller.id, body })) // M1.5

      yield* turn.perform(new ModerateMessage({ id, body })) // M1.7: runs after commit

      // M1.6: a timer. The same key replaces the pending one, so each post pushes it back.
      const self = yield* Room.intents(turn.id)
      yield* self.IdleCheck().pipe(Intent.after("24 hours"), Intent.key("idle"))

      return id
    }),

    Archive: Effect.fn(function* () {
      const turn = yield* Room.Turn
      yield* turn.state.set({ closed: true })
      yield* turn.emit(new RoomArchived())
      yield* Intent.cancel("idle") // M1.6
    }),

    IdleCheck: Effect.fn(function* () {
      const self = yield* Room.intents((yield* Room.Turn).id)
      yield* self.Archive() // committed with this turn, delivered after
    }),

    Moderated: Effect.fn(function* ({ id, flagged }) {
      const turn = yield* Room.Turn
      if (flagged) yield* turn.rows(messages).delete().where({ id }) // exact builder shape settled in M1.4
    }),

    ModerationFailed: Effect.fn(function* (dead) {
      yield* Effect.logWarning("moderation dead-lettered", dead.effectId)
    }),
  }),
)
```

### Queries and effect executor

```ts
export const RoomReads = Room.toQueryLayer(
  Effect.succeed({
    Recent: Effect.fn(function* ({ limit }) {
      const read = yield* Room.Read
      return yield* read.rows(messages).all({ orderBy: { sentAt: "desc" }, limit }) // read-only, scoped
    }),
    History: Effect.fn(function* ({ after }) {
      const read = yield* Room.Read
      return yield* read.events(MessagePosted, { after }) // explicit gap error past keepEvents
    }),
  }),
)

// May run on a separate process. No database capability; returns the value routed to onSuccess.
export const RoomEffects = Room.toEffectLayer(
  Effect.gen(function* () {
    const moderation = yield* ModerationApi
    return {
      ModerateMessage: Effect.fn(function* ({ id, body }) {
        const exec = yield* Room.Executor
        const flagged = yield* moderation.check(body, { idempotencyKey: exec.effectId })
        return { id, flagged }
      }),
    }
  }),
)
```

### What the tests prove

Each slice ships its cases in its own conformance file, running on PGlite and real Postgres, with crash and contention cases on Postgres. `test.advance` and blob, event, outbox, and effect counts in `test.inspect` are proposed `ActorTest` additions made by the slices that need them.

```ts
it("a declared failure commits nothing but its receipt", () =>
  run(Effect.gen(function* () {
    const test = yield* ActorTest
    const room = yield* Room.get("r1")
    yield* room.Archive()
    const failed = yield* room.Post({ body: "hi", file: bytes }).pipe(Effect.flip)
    expect(failed._tag).toBe("RoomClosed")
    expect(yield* test.inspect(room.ref)).toMatchObject({
      rows: { chat_messages: 0 }, blobs: 0, events: 1 /* RoomArchived */, outbox: 0, effects: 0,
    })
  })))

it("delivers an intent exactly once across a crash after the receiver commits", () =>
  run(Effect.gen(function* () {
    const test = yield* ActorTest
    const room = yield* Room.get("r2")
    yield* room.Post({ body: "hello" })
    yield* test.crashNext("afterCommit")      // the relay dies before deleting the outbox row
    yield* test.advance("24 hours")           // proposed test-clock helper
    expect((yield* test.inspect(room.ref)).state.closed).toBe(true)
    expect(yield* test.receiptsFor(room.ref, "Archive")).toBe(1) // redelivery deduped by receipt
  })))
```

## Exit criteria

M1 is complete when every slice above is merged with its conformance cases passing on PGlite and Postgres in CI, `examples/chat` runs end to end with its own test on both backends, and the conformance ledger, support matrix, and API docs record what M1 proved. This closes single-runner embedded support for the M1 members, not multi-runner, Neki, or transport support.

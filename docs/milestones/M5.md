# M5: Conformance on Postgres and Neki

**Responsibility:** define the M5 slices, their order, and the exit test.  
**Authority:** delivery plan.  
**Owner role:** delivery/runtime lead.
**Change policy:** a change requires delivery lead sign-off.

M5 is about evidence. It runs the whole contract on the backends the framework claims: Postgres, and Neki as PlanetScale's sharded Postgres. It finishes deterministic simulation, runs the failure drills and the 72-hour soak, and certifies the support matrix. Every gate in the [conformance ledger](../verification/01-conformance.md) and every row in the [failure matrix](../verification/02-failure-matrix.md) ends M5 either linked to an executable case or marked as an explicit unsupported result.

Provider gates apply when their feature ships ([milestone index](README.md)). M5 is where the remaining ones are closed, not where they first become required.

## Order of work

1. **Needs Neki access.** M5.1, M5.2, T12 and T14 need a Neki test deployment with several shards. Until one is provisioned, those slices stay gated and the support matrix keeps saying so.
2. **Doesn't need Neki.** M5.3, M5.4 and T13 need only Postgres and dedicated benchmark machines, so they start first.
3. **Last:** M5.5.

## Slice details

**M5.1: Neki locking and pinning.**

- **What it checks:** turn connections set `__neki.tx_mode = 'single'` and `__neki.fanout = 'single'`. The generation fence holds through the Neki router. Pinned connections behave as the **Neki locking and pinning** gate requires.
- **CI:** a check runs `EXPLAIN (NEKI_PLAN)` on every framework statement, so an accidental scatter fails the build ([ADR 0006](../decisions/0006-scale-rules-placement-and-query-tiers.md)).

**M5.2: Neki outbox.** Covers the cross-shard and cross-region paths of the **Outbox delivery** gate, with crashes before delivery, after the receiver commits, and before row deletion.

**M5.3: provider gates.**

- **Railway advertise address:** replicas reach each advertised runner address.
- **Cluster header size:** the largest supported principal fits the envelope headers.
- **PGlite in tests** and **PGlite under Bun:** re-run on the final schema.

**M5.4: simulation extensions.** T6's `ActorTest.simulate` gains primary failover, and multi-runner faults at larger scale. This completes the **Simulation** check and invariant X1.

**M5.5: gate audit.**

- Every gate and failure-matrix row links to a case, or to an explicit unsupported result.
- Every support-matrix cell says "verified" with its evidence, or "unverified" with the reason.

**T12: Neki drills.** Fails over a shard primary under load, and runs an online reshard. Measures recovery time, and checks for duplicate or lost work using receipts and the outbox.

**T13: 72-hour soak.** Steady load for 72 hours on dedicated machines. It measures:

- vacuum progress;
- transaction-ID age;
- WAL bytes per turn;
- full-page-image ratio;
- replica lag;
- relay lag;
- heap per runner, which also watches the upstream Cluster leak in [#46](https://github.com/Rika-Labs/durable-actors/issues/46).

**T14: M5 scale run.**

- linear scale-out on 1, 2, 4, 8 and 16 Neki shards, with turns per second per shard held constant, including during an online reshard;
- the `cluster_*` shard group measured separately;
- flat latency at 10^9 stored actors.

## The certification run

```sh
bun run test:integration --backend neki --shards 4        # M5.1, M5.2: the full conformance suite on Neki
bun run drills --target neki --fault primary-failover     # T12
bun run bench --scenario soak --duration 72h --runners 3  # T13, on a dedicated runner host
```

```ts
it("never scatters a framework statement across shards", () =>
  Effect.gen(function* () {
    for (const statement of yield* frameworkStatements) {
      expect(yield* nekiPlan(statement)).toMatchObject({ shards: 1 })
    }
  }))
```

## Excluded

- New public API. M5 changes only what evidence shows is wrong.
- Other database providers need their own adapter contract and gates ([ADR 0003](../decisions/0003-failure-scoping-drain-and-hosted-trust.md)).

## Exit criteria

M5 is complete when all of these hold:

- Every gate and failure-matrix row is linked or explicitly unsupported.
- The support matrix is certified.
- T12, T13 and T14's results are in the [performance document](../verification/03-performance.md), next to the [planning envelope](../verification/03-performance.md#planning-envelope-hypotheses) hypotheses, each marked met or missed.
- The nightly simulation has run for two weeks with no unreproduced failure.

# M5: Conformance and certification

**Responsibility:** define the M5 slices, their order, and the exit test.  
**Authority:** delivery plan.  
**Owner role:** delivery/runtime lead.
**Change policy:** a change requires delivery lead sign-off.

M5 is about evidence. It certifies the whole contract on Postgres, finishes deterministic simulation, and prepares everything the Neki runs need. Every gate in the [conformance ledger](../verification/01-conformance.md) and every row in the [failure matrix](../verification/02-failure-matrix.md) ends M5 linked to an executable case, marked as an explicit unsupported result, or marked "pending [#66](https://github.com/Rika-Labs/durable-actors/issues/66)".

Scale runs, the 72-hour soak, failure drills at scale, and running the suites against Neki happen on dedicated hardware in [#66](https://github.com/Rika-Labs/durable-actors/issues/66), outside the waves. M5 closes without waiting for them, and the support matrix says which cells are pending #66.

Provider gates apply when their feature ships ([milestone index](README.md)). M5 is where the remaining ones are closed, not where they first become required.

## Order of work

M5.1 through M5.4 run in parallel. M5.5 comes last.

## Slice details

**M5.1: Neki suite.**

- **What it builds:** a Neki backend option for the conformance suite; turn connections that set `__neki.tx_mode = 'single'` and `__neki.fanout = 'single'`; and a check that every framework statement's `EXPLAIN (NEKI_PLAN)` touches one shard ([ADR 0006](../decisions/0006-scale-rules-placement-and-query-tiers.md)), including the Neki half of the **Placement and single-shard paths** check.
- **Execution** against a Neki deployment, which the **Neki locking and pinning** gate needs, is in #66. Until it runs, those cells say "prepared; unverified, pending #66".

**M5.2: Neki outbox.** The cross-shard and cross-region cases of the **Outbox delivery** gate, with crashes before delivery, after the receiver commits, and before row deletion, written against the Neki option and run in #66.

**M5.3: provider gates.**

- **Railway advertise address:** replicas reach each advertised runner address.
- **Cluster header size:** the largest supported principal fits the envelope headers.
- **PGlite in tests** and **PGlite under Bun:** re-run on the final schema, alongside M4.14's embedded-production cases.

**M5.4: simulation extensions.** T6's `ActorTest.simulate` gains primary failover and more multi-runner faults. This completes the **Simulation** check and invariant X1.

**M5.5: gate audit.**

- Every gate and failure-matrix row links to a case, an explicit unsupported result, or "pending #66".
- Every support-matrix cell says "verified" with its evidence, or "unverified" with the reason.
- Rows covered only by M0's cases, such as "Different caller reuses a committed command id" and "Access revoked before admission / after durable admission", are re-run on the final schema and linked.
- Regional placement, remote users, and the cold tier are marked unsupported until they're built ([M4](M4.md#later-when-hosted-usage-asks)).

## A certification check (proposed)

```ts
it("never scatters a framework statement across shards", () =>
  Effect.gen(function* () {
    for (const statement of yield* frameworkStatements) {
      expect(yield* nekiPlan(statement)).toMatchObject({ shards: 1 })
    }
  }))
```

## Excluded

- New public API. M5 changes only what evidence shows is wrong.
- Running on Neki, scale runs, the 72-hour soak, and drills at scale: [#66](https://github.com/Rika-Labs/durable-actors/issues/66).
- Other database providers need their own adapter contract and gates ([ADR 0003](../decisions/0003-failure-scoping-drain-and-hosted-trust.md)).

## Exit criteria

M5 is complete when all of these hold:

- Every gate and failure-matrix row is linked, explicitly unsupported, or pending #66.
- The support matrix is certified for Postgres and PGlite, with Neki cells marked prepared and pending #66.
- The nightly simulation has run for two weeks with no unreproduced failure.

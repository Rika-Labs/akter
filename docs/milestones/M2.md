# M2: Many runners, background work, and sessions

**Responsibility:** define the M2 slices, their order, and the exit test.  
**Authority:** delivery plan.  
**Owner role:** delivery/runtime lead.
**Change policy:** a change requires delivery lead sign-off.

M2 runs actors on several runners at once and adds the members that do work in the background or hold a session:

- the multi-runner relay;
- singletons proven across runners;
- cron;
- workflows with version markers;
- connections with parking and hibernation;
- `Actor.stream`.

M2 also carries the first half of the performance roadmap: the two-round-trip turn, an optimistic one-round-trip fast path, turn batches, and commutative merging. It also builds the testing base that every later milestone uses: the multi-runner harness, a statement-count CI gate, property tests, deterministic simulation, and the first failure drills.

The exit test is `examples/chat` on three runners, with one runner killed mid-test. It adds a cron digest, a workflow, and typing sent as connection frames. The code below is that example.

Spellings follow [server API](../api/01-server-api.md), [context](../api/02-context.md), and the [contracts](../contracts/README.md). Members the docs name but don't fully specify (`ActorTest.cluster`, `wf.version`, `Actor.connection` options) are **proposed** here. Their ADR settles them, and the implementing slice updates the API docs.

## Rules for every slice

The rules in [M1](M1.md#rules-for-every-slice) still apply, plus these:

- **Multi-runner cases.** Anything about ownership, relay claims, singletons, or failover runs on the M2.1 harness against real Postgres. PGlite isn't a proof backend for them.
- **Benchmark scenario.** Every slice adds a scenario under `tooling/benchmarks/src/scenarios/` and commits a results file. A slice with nothing to measure says why in its PR.
- **Statement counts.** Once T2 lands, a change in statements per operation fails CI unless the PR updates `benchmarks/baselines/statements.json` and explains the change.
- **Migrations.** Migrations land in number order. After M1 closes, a slice that is ready ahead of a lower-numbered one takes the next unreserved number (`0018` and up) and updates its issue.

## Slice details

**M2.1: multi-runner harness.**

- **What it is.** N runtimes in one process against one real Postgres. Each runtime is a distinct Cluster runner with its own address and expiring per-address shard locks.
- **Controls.** `kill`, `restart`, `pauseHeartbeat`, and `owner(ref)`.
- **Evidence.**
  - The **In-process multi-runner** gate.
  - The failure-matrix row "Runner dies in a paused turn".
  - Invariant A1 with a real second runner, and M3 across a runner kill.

**M2.2: singleton uniqueness and failover.**

- **What it proves.** One activation and one `Effect.forkScoped` loop exist across 2–3 runners. After a kill, exactly one survivor takes over. Lock expiry and resumed service are timed separately.
- **Evidence.** G1 without cron, and the loop half of "Singleton runner dies".

**M2.3 and M2.4: multi-runner relay.**

- **What ADR 0021 decides.**
  - `FOR UPDATE SKIP LOCKED` claims.
  - Executors outside the relay transaction, on a per-runner pool with a concurrency limit and renewable leases.
  - Configurable executor timeout, lease, and backoff (M1.7 fixed them).
  - Capped backoff for rows that die without settling.
  - Wake-up messages after commit, never `LISTEN/NOTIFY`.
- **Evidence for M2.4.**
  - The **Outbox delivery** gate on two or more runners.
  - The **Effect routes** and **Due-work scans** checks.
  - Invariants M1, M2 and P1.
  - Both relay-crash rows in the [failure matrix](../verification/02-failure-matrix.md), with a runner kill between the steps.
- **Benchmark.** Concurrent effect throughput must beat M1's single-relay cap (225 op/s with 64 callers), and a slow executor must not delay intent delivery.

**M2.5: cron.**

- **What it does.** Per-actor cron runs as a keyed self-timer, and singleton cron runs once per deployment. `cronSkipIfOlderThan` and the catch-up rule come from ADR 0021. A tick the relay has already claimed fires once, like any claimed timer.
- **Evidence.**
  - The cron half of the **Singleton uniqueness** gate: two runners produce one logical tick.
  - G1 with cron.
  - The **API shape** check: a cron target that takes input doesn't compile.

**M2.6 to M2.8: workflows.**

- **The engine.** It is the framework `WorkflowEngine` from [ADR 0012](../decisions/0012-workflows-internals-effects-defects-merging-regions.md): steps in `actor_workflow_step` on the owner's shard, and clocks as outbox timers.
- **What ADR 0022 settles.**
  - the schema;
  - `WorkflowRun`;
  - `waitFor` registration;
  - `wf.version`;
  - the deploy check from [ADR 0014](../decisions/0014-adoption-observation-and-client-reach.md).
- **Evidence.**
  - The **Workflow engine** suite, run against both engines.
  - The **Workflow tenant isolation** and **`waitFor` registration** gates.
  - The **Workflow compatibility** check.
  - W1 and W2.
  - "Workflow resumes elsewhere" on the harness, and "Event races workflow wait registration".

**M2.9 and M2.10: connections.**

- **What ADR 0023 settles.**
  - A transport layer holds sockets and outlives activations. M2 uses an in-process test transport, and M3 adds WebSocket.
  - `actor_connections`, with 16 KiB state.
  - Waking across runners.
  - `Actor.stream`.
  - The session revocation bound.
- **Evidence.**
  - The **Connection park** gate and C1.
  - "Parked connection wakes" and "Live or parked session loses authorization".
  - A broadcast wakes a parked activation on another runner.

**P1, P4 and P7: round trips.**

- **What ADR 0020 designs.** The turn at two round trips, and an optimistic one-round-trip path for warm activations:
  1. The handler runs first.
  2. One round trip carries the fence check, the receipt insert, the guarded writes, and `COMMIT`.
  3. A fence or receipt miss discards the speculative result and reruns the command on the two-round-trip path.
- **Contract changes.** This reorders the [command-turn contract](../contracts/02-command-turns.md) and replaces the one-round-trip alternative that [ADR 0005](../decisions/0005-turn-latency-batching-and-regional-placement.md) rejected. Contract 02 and the [receipt contract](../contracts/04-receipts.md) change with it.
- **Evidence.**
  - The **Two-round-trip turns and state cache** check.
  - A new **Optimistic fast path** check.
  - New failure-matrix rows "Speculative turn loses its fence" and "Speculative duplicate command".

**P5 and P6: batches and merging.**

- **Rules.** Batches take only commands already waiting, with a cap of 32. Each command keeps its own receipt and failure isolation. Batch N+1 runs while batch N commits. Commutative merging takes up to 1,024 queued inputs and never waits.
- **Evidence.**
  - The **Turn batches**, **Pipelined batches**, and **Merging** checks.
  - B1 and C2.
  - "Pipelined batch N fails to commit" and "Commutative merge turn fails".

**T2 to T8: testing.**

- **T2: statement gate.** Statements per operation is the only benchmark metric that is stable across machines, so it is the one CI enforces.
- **T3: property tests.** Generated inputs with `effect/unstable/arbitrary`, plus model-based tests of receipts, cursors, timers, and table scoping.
- **T4: CI reliability.** Fixes the known CI flakes and extends the process-kill suite to reducers, dead letters, blobs, and owned rows.
- **T6: deterministic simulation.** Implements `ActorTest.simulate` from [ADR 0011](../decisions/0011-direct-commands-outbox-and-performance.md), which covers invariant X1:
  - It runs the real turn path under a seeded scheduler, with these faults: crash before and after commit, dropped replies, relay crash, clock skew, and runner kill. Primary failover waits for M5.
  - 20 fixed seeds run on PRs and 10,000 seeds nightly.
- **T7: failure drills.** Three runner processes run under load, and a runner and the relay are killed with SIGKILL. The drills measure recovery time and count lost and duplicated work.
- **T8: M2 scale run.** Measures:
  - the hot-actor ceiling with batches;
  - round trips (2, and 1 on the fast path);
  - turns per second from 1, 2, 4 and 8 runner processes against one Postgres;
  - timer lateness at 10^6 sleeping timers.

## Excluded

- Transports (HTTP, WebSocket, SSE), the Promise client, and browser optimistic reducers are M3.
- Drain, observability, restore, the hosted edge, and regions are M4.
- Neki is M5.
- Effect cancellation, per-actor effect concurrency caps, executor live frames, tenant content-addressed blobs, and `turn.mint` are not scheduled ([ADR 0017](../decisions/0017-m1-record-corrections.md) keeps the framework general). M2.4's per-runner executor concurrency limit is a runner setting, not a per-actor one.
- `Intent.cancel` for a timer the relay has already claimed stays "delivered at most once more" ([contract 05](../contracts/05-messaging.md)).

## The chat room on three runners

### New members (`examples/chat/src/room/contract.ts`)

```ts
// M2.5: a singleton runs the digest once per deployment.
export const Send = Actor.command("Send")
export const Digest = Actor.make("Digest", {
  key: Actor.singleton,
  api: { Send },
  policy: { cron: { "0 8 * * *": Send }, cronSkipIfOlderThan: "1 hour" },
})

// M2.7: an appeal waits for a moderator's decision, durably.
export class AppealDecided extends Actor.Event<AppealDecided>()("AppealDecided", {
  messageId: Schema.String,
  restore: Schema.Boolean,
}) {}
export const Appeal = Actor.workflow("Appeal", {
  input: { messageId: Schema.String },
  output: Schema.Boolean,
})

// M2.10: typing indicators travel as frames, never as commands.
export const Presence = Actor.connection("Presence", {
  state: Schema.Struct({ user: Schema.String }),
  frames: {
    client: Schema.Struct({ typing: Schema.Boolean }),
    server: Schema.Struct({ typing: Schema.Array(Schema.String) }),
  },
})

export const Room = Actor.make("Room", {
  // ...M1 members, plus:
  events: [MessagePosted, RoomArchived, AppealDecided],
  api: { Post, Archive, Recent, History, SetTyping, Appeal, Presence },
  policy: { connections: "park" /* ...M1 policy */ },
})
```

### Handlers (`examples/chat/src/room/layer.ts`)

```ts
Appeal: Effect.fn(function* ({ messageId }) {
  const wf = yield* Room.Workflow
  if ((yield* wf.version("notify-moderators", 1)) >= 1) {
    yield* Activity.make({ name: "notify", execute: moderators.notify(messageId) })
  }
  const decided = yield* wf.waitFor(AppealDecided, {
    where: (e) => e.messageId === messageId,
    timeout: "3 days",
  })
  return Option.match(decided, { onNone: () => false, onSome: (e) => e.restore })
}),

Presence: Effect.fn(function* (frames) {
  const conn = yield* Room.Connection
  yield* Stream.runForEach(frames, ({ typing }) =>
    conn.broadcast({ typing: typing ? [conn.state.user] : [] }),
  )
}),
```

### What the tests prove

```ts
it.cluster("runs one digest per day across three runners, through a runner kill", { runners: 3 }, () =>
  Effect.gen(function* () {
    const cluster = yield* ActorTest.Cluster
    yield* cluster.advance("1 day")
    yield* cluster.kill(yield* cluster.owner(Digest.ref()))
    yield* cluster.advance("1 day")
    expect(yield* cluster.receiptsFor(Digest.ref(), "Send")).toBe(2) // one per day, never two
  }))

it.cluster("resumes an appeal on another runner and resolves it from the owner's event", { runners: 3 }, ...)
it.cluster("wakes a parked room on another runner when a typing frame arrives", { runners: 3 }, ...)
it("simulates 10,000 seeds of posts, crashes, and relay restarts with exactly-once receipts", () =>
  ActorTest.simulate({ seed, faults: ["crashBeforeCommit", "crashAfterCommit", "dropReply", "relayCrash"] }, chatScript))
```

## Exit criteria

M2 is complete when all of these hold:

- Every slice above is merged with its cases passing on Postgres in CI, and on PGlite where they apply.
- `examples/chat` passes on three runners with a runner killed mid-test.
- T6 runs nightly with no unreproduced failures.
- T8's results are in the [performance document](../verification/03-performance.md), with the hot-actor, round-trip, and multi-runner rows marked met or missed.
- The conformance ledger, support matrix, and API docs record what M2 proved.

This closes multi-runner support on one Postgres database. It does not close transports, Neki, or hosted support.

# Cloud deployment verification

Before claiming the local deployment loop works, run the affected suites on the assigned local Postgres and the built local application image. A provider fake is not evidence for Docker, and Docker is not evidence for Fly Machines or Neki.

Required negative evidence includes: one winner under concurrent environment rollouts; no provider call before a wake commits; an identical build result that enqueues no new job; a changed build result refused; failed migration/start/activation leaving the prior deployment live; rollback copying the earlier image and snapshot; an audit failure rolling back activation; concurrent wakes starting one runner; ingress withdrawn before drain; a startup-time drain retained; paid tiers not idling; and stale task observations not deleting a replacement.

Review regression cases also reject a stale poller wake resurrecting a retired release, a wake abandoning a failed stop, interruption stopping accepted capacity, failed cleanup disappearing from the rollout, public HTTP or socket traffic failing to record activity, cross-organization runtime resolution, and unmeasured runner telemetry displayed as zero. The Fly runner platform, against a fake Fly HTTP endpoint, must reject starting into an app of another organization or one that already holds another deployment's machines, an image that is not pinned by digest in `registry.fly.io`, a stop that returns before Fly reports the machine stopped, a machine left behind after a stop, `terminated` without an observed exit, a url reported before Fly reports the machine started, a migration judged by a stopped machine instead of an exit code of 0, a migration machine left behind when reading its exit fails or the run is interrupted, a second machine for a repeated start key, and a provider answer's text, or the token, reaching an error. It must place a start in the next allowed region when Fly reports no capacity and fail with the transient `capacity` code when none has room. With Fly runners configured, the API must refuse a project homed in, or a deployment into, a region the runner configuration does not place. The edge must believe `Fly-Client-IP` only when `EDGE_TRUST_FLY_PROXY` is set and the header is exactly one address, and ignore every other forwarding header.

The local stack scenario must create a project through the API, register a locally built digest, observe a ready runner, send a command through the API and edge, retry it with the same client key, reject a changed payload, send to a never-created actor, roll forward and back, then withdraw Free capacity and answer the next command after a wake without duplicate execution. Exercise migration and runner interruption, not only success. Keep state and receipt expectations independent of the implementation's own counters.

The CLI scenario must log in through the device grant by approving the code the CLI printed, deploy an uploaded build context the control plane's own source does not contain and show the live image holds it, send a command with the stored session that the actor sees as that user, and leave the session refused after logout. Its unit evidence must reject denied, expired and refused device codes, credentials other users can read, an expired session, and a failed build or rollout step reported as success.

Before the first successful command, denied callers must leave the actor absent. Runtime mapping evidence must reject terminal handling of `MailboxFull`, keep defects opaque and non-retryable, and verify typed command-expiry refusals. Repository evidence must cover payload-hash conflicts, tombstone expiry, bounded 1,000-row sweeps, and a concurrent sweep/reuse race.

Use the repository's `bun install`, typecheck, lint, formatting, unit and relevant Postgres integration commands. Local container tests require Docker and remove only the exact resources they created. Do not prune the shared daemon. On a shared Mac, correctness checks must use the shared heavy-run slots and the agreed load gate; infrastructure timeouts require a clean rerun, not weaker assertions. Test durations are not deployment performance measurements.

Real Fly Machines (capacity, per-app private networks, the proxy and its TLS, cross-app image pulls), the Fly registry push, `Fly-Client-IP` as Fly sets it, Resend delivery, GitHub App installation, Neki and Fly cold-start bounds require authorized credentials and provider-specific evidence. The credential-free slice makes no claim for them. Performance measurements belong on isolated sandboxes, not the shared Mac.
Runtime verification includes an immediate post-activation command: the request must reach the newly active deployment through its deployment-bound host even while the environment-host directory may still contain the previous release.

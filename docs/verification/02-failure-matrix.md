# Failure matrix

Bucket-range claim evidence is in `runtime/database/shards.test.ts`: work immediately outside the range is untouched, a locked row is skipped and later claimed once, and a failed settle stays leased rather than being delivered again in the same drain. Public-API intents, timers, capped and uncapped jobs, and cron run across both range halves with receipt and resulting-state assertions; holder liveness preserves live rows across range boundaries and closes a deleted row. The default path is measured at one SQL statement and one network flight. `runtime/database/migrations.test.ts` audits every framework unique index and detects an injected key without `routing_key`. `runtime/storage/placements.test.ts` moves a tenant-placed type's rows to authority keys once, rolls a failed move back and moves once under two concurrent starts. These are engine-independent row-scope and scheduling guarantees on one Postgres/PGlite database, not physical data-shard targeting ([ADR 0112](../decisions/0112-postgres-and-pglite-only.md)).

**Responsibility:** make crash behavior testable.  
**Authority:** evidence.  
**Owner role:** verification/reliability.
**Change policy:** a change requires the conformance suite to be updated in the same change.

Every row MUST assert durable rows, caller result, retry identity, activation state, and later delivery—not merely absence of an exception.

Startup pool exhaustion is exercised by `runtime/database/bounded.test.ts` (`retries checkout refusals while concurrently registering actor and query layers`): 80 actor layers and 80 query layers share a two-connection PostgreSQL pool, then every actor serves an asymmetric command result and a query with exactly one receipt. The existing excess-checkout cases still require an immediate refusal before any statement is sent.

The **Evidence** column names the conformance cases that prove each row; they run in the `Verify` workflow on every pull request and on `main`. A row with no proving case says "Unverified" or "Unsupported" with its reason.

Unless a row exercises denial or expiry, external receipt replay assumes the original logical caller remains authorized and the command identity is unexpired. Trusted internal recovery retains its accepted-work authority; see [receipts](../contracts/04-receipts.md).

The expiry-after-admission case `rechecks expiry before the reply against a clock read after the commit, not the admission clock` pauses a handler until its id expires, then proves the receipt commits but the caller receives `CommandExpired`. The pipeline statement-order case independently requires the fresh clock read to follow `COMMIT` in its flight. These reject admission-clock reuse and a clock read inside the transaction, respectively ([ADR 0072](../decisions/0072-served-command-in-two-round-trips.md)).

The real-Postgres case `rejects first admission that expires while waiting for the generation fence without running its handler` holds that row from an independent transaction, waits for the command's database lock wait, and releases it only after expiry. The command must return `CommandExpired` with no handler run or new receipt. This rejects a target-list admission clock evaluated before `FOR UPDATE` acquires the fence.

Framework startup checks in `runtime/database/migrations.test.ts` require six concurrent `Actors.layer` builds and six independent processes on fresh Postgres data/coordination databases to serialize history-table and Cluster-table creation. Migration 0033 must refuse external dependencies without cascading, roll back all view/catalog changes and its history entry, then retry and restart with actor rows preserved. Application schema setup failure rolls back whole in `runtime/database/schema.test.ts`. The public socket startup/owner-loss drill in `crash/drills/production.test.ts` uses local Postgres and real subprocesses, separate from Docker-based failover fixtures. There is no provider DDL journal or propagation boundary in the supported runtime.

Public-runner process evidence also lives in `tooling/conformance/src/conformance/crash/drills/production.test.ts`: three OS processes over TCP, table lease ownership, singleton SIGKILL, clean drain/rolling handoff, acknowledgment-to-receipt/state comparison, and cron replay after commit-before-rewrite death. Incompatible count or expiration must fail before shard acquisition, and PGlite and embedded joins are refused. `runtime/runner.test.ts` rejects readiness that ignores an unacquired actor or holder shard. This is one-host loopback evidence, not a separate-host or hosted-provider claim.

Pool scheduling and checkout evidence lives in `runtime/database/gate.test.ts` and `bounded.test.ts`: a checkout past the bound is refused at once while the admitted waiters are served in arrival order, even after hundreds of statements, transactions and reservations returned their slots; queued and granted-but-not-resumed interruption returns every slot; every runtime pool advances every contending caller; nested failures roll back only their savepoint and release it; a COMMIT answered with ROLLBACK fails; and interrupting a running statement cancels it on a Postgres server and returns a clean size-one pool. The pipeline case `pipeline: a turn that chains no batch returns its session before its callers are answered` holds publication while a different actor commits using that same single turn slot. These are proofs against a Postgres server and its pool admission gate, not provider or pooler certification.

Process-death evidence (T4b): **During handler / before COMMIT** and **After COMMIT / before reply** are exercised by real SIGKILL on a Postgres database for commands, reducer turns, owned-row writes, blob writes, and the effect dead-letter transaction, and **Declared failure after attempted writes** for owned-row and blob writes (a reducer's declared failure is also replayed across SIGKILL, but `reduce` stages no writes). The `onDeadLetter` route is also killed after its receiver commits and before its outbox row is deleted (**Relay crash after receiver commit / before outbox row deletion**), and recovery replays its receipt. The rows "Intent turn rolls back", "Relay crash after sender COMMIT", and "Relay crash after receiver commit / before outbox row deletion" have single-runner, same-shard evidence from M1.6, listed in the conformance suites, including real SIGKILL cases on a Postgres database. The row "Provider success / result acknowledgment lost" has single-runner evidence from M1.7: the executor reruns under the same effect id and routes one result, and an exhausted effect whose last outcome is unknown is dead-lettered as `ambiguous`, listed in the conformance suites, including SIGKILL cases on a Postgres database. The rows "Runner dies in a paused turn" and "Stale generation" have in-process multi-runner evidence on a Postgres database from M2.1, listed in the conformance suites: no survivor takes the shard before lock expiry, the caller's retry commits once on the new owner, and a stale activation on a live runner fails its fence. The relay-claim and executor-lease rows from [ADR 0021](../decisions/0021-multi-runner-relay-singleton-and-cron.md) have in-process multi-runner evidence on a Postgres database from M2.4, and the two relay-crash rows and the provider row also run there with a runner kill between their steps, listed in the conformance suites. The four cron rows have evidence from M2.5, listed under cron: the crash-before-rewrite, downtime, and claim-filter rows on PGlite and a Postgres database, and the singleton bootstrap race and runner kills during a tick on three runners against a real Postgres database. The effect-cancellation and capped-slot rows come from [ADR 0024](../decisions/0024-effect-cancellation-and-per-actor-concurrency.md) (accepted) and have in-process multi-runner evidence on a Postgres database from M2.13, plus a SIGKILL case for a cancelled attempt, listed in the conformance suites. The `turn.mint` rows come from [ADR 0025](../decisions/0025-turn-mint.md); M2.15 has single-runner evidence on PGlite and a real Postgres database for the parent crash, commit-unknown, failed creating turn, uncommitted-proof, and client race rows, listed in the conformance suites. The relay-claim row has in-process multi-runner evidence on a Postgres database from the same slice, listed there too. The progress rows come from [ADR 0030](../decisions/0030-executor-progress-frames.md) and are required of M2.18 on the multi-runner harness against a real Postgres database. Each implementation must attach evidence and an operator signal/remediation path for the failures it claims to recover from.

Evidence for "External identity expires before delivery or retry" and "Cleanup races retry / crashes before completion" with automatic pruning is in the conformance suites. Evidence for "Restore, clock change, or version skew at the retry horizon" is in the conformance suites: restore of a whole-database snapshot and two runtime versions behind one database. A database clock stepped back behind issued ids is not supported: the [restore procedure](../operations/04-backup-restore.md) checks the clock against the backup's snapshot time and a trusted time source before runners start, and nothing detects a step back while they serve.

## Served-protocol rows

Required by [ADR 0027](../decisions/0027-served-protocol.md). M3.2 runs the HTTP rows in `conformance/http.ts`, M3.4 repeats them through the Promise client in `conformance/client.ts`, and M3.3 runs the session rows in `conformance/transports.ts`. The four HTTP rows pass on PGlite and a Postgres database as of M3.2 (see the conformance suites). As of M3.4, "Command response lost over HTTP" and "Client clock ahead of the database clock" also pass through the Promise client, as do the rows "Caller gives up before a reply" and "External identity expires before delivery or retry", and a SIGKILL of the serving process before and after commit retries exactly once on real Postgres (see the conformance suites). As of M3.3, "Credential expires during a live session" passes over WebSocket on PGlite and a Postgres database, and "Live or parked session loses authorization" also passes over a real socket (see the conformance suites). Both rows and "SSE feed reconnects after pruning" also pass for SSE event feeds (see the conformance suites).

## Runtime design rows

Required by the accepted runtime design ADRs. These framework rows remain public; hosted ingress, tenant-directory, and control-plane verification moved with the private service.

An actor need not be resident on the inspecting runner for its committed rows to be read. The public inspector's missing-actor response is `404 { "_tag": "NotFound" }`; it does not use the Cloud API's `resource: "actor"` error. Missing historical timing is `null`, not zero.

# Failure matrix

**Responsibility:** make crash behavior testable.  
**Authority:** evidence.  
**Owner role:** verification/reliability.
**Change policy:** a change requires the conformance suite to be updated in the same change.

Every row MUST assert durable rows, caller result, retry identity, activation state, and later delivery—not merely absence of an exception.

Unless a row exercises denial or expiry, external receipt replay assumes the original logical caller remains authorized and the command identity is unexpired. Trusted internal recovery retains its accepted-work authority; see [receipts](../contracts/04-receipts.md).

| Fault point                                                           | Required result                                                                                                                                                                                                                                                                                                                                                                                                         |
| --------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Before handler                                                        | No business consequences; the caller's retry with the same command id executes once.                                                                                                                                                                                                                                                                                                                                    |
| During handler / before COMMIT                                        | Transaction rolls back receipt, state, owned rows, blob chunks, events, and outbox rows; activation restarts for retryable defect; the caller retries the same command id.                                                                                                                                                                                                                                              |
| Deterministic defect                                                  | Rollback; caller receives `Die`; the turn span records the cause; no user code runs; actor remains resident.                                                                                                                                                                                                                                                                                                            |
| After COMMIT / before reply                                           | Retry with the same command id replays output or declared failure; handler does not run twice.                                                                                                                                                                                                                                                                                                                          |
| Intent turn rolls back                                                | No receiver turn occurs.                                                                                                                                                                                                                                                                                                                                                                                                |
| Relay crash after sender COMMIT                                       | The next relay pass (after the claim lease, on any runner, once a row was claimed) delivers the same intent id; the receiver executes it once.                                                                                                                                                                                                                                                                          |
| Relay crash after receiver commit / before outbox row deletion        | After the claim lease, any runner's redelivery replays the receiver's receipt; no second receiver transition.                                                                                                                                                                                                                                                                                                           |
| Caller delivery timeout / disconnect                                  | The admitted turn may still commit; retrying the same command id observes its receipt instead of cancelling or duplicating it.                                                                                                                                                                                                                                                                                          |
| Runner at `maxResidentActors`                                         | No turn or receipt; the handle retries the same id until a slot frees, else `RunnerAtCapacity` after `deliveryTimeout`. Unbounded actors never see `MailboxFull`.                                                                                                                                                                                                                                                       |
| Declared failure after attempted writes                               | Roll back all business work and staged notifications; commit only the terminal typed failure outcome with the fence/receipt. Redelivery replays it without rerunning the handler.                                                                                                                                                                                                                                       |
| Provider success / result acknowledgment lost                         | Preserve the ambiguous outcome; reconcile or retry under provider idempotency rather than assuming the call failed.                                                                                                                                                                                                                                                                                                     |
| Relay dies after claiming, before delivery                            | No runner delivers the row before its claim lease ends; then one runner delivers the same intent id once.                                                                                                                                                                                                                                                                                                               |
| Relay settle dies on the same row repeatedly                          | The row is not due again for `max(claim lease, backoff(attempts))`, capped at `maxBackoff`; newer due rows are delivered within one poll.                                                                                                                                                                                                                                                                               |
| Two runners claim the same due rows                                   | `SKIP LOCKED` gives each row to one runner per lease; a runner whose lease passed changes nothing when it settles.                                                                                                                                                                                                                                                                                                      |
| Executor lease expires mid-call                                       | The attempt is interrupted on its runner; another runner starts the next attempt with the previous one recorded as `ambiguous`; the last attempt dead-letters as `ambiguous: true`.                                                                                                                                                                                                                                     |
| Stale attempt reports after takeover                                  | A stale failure matches no row and records nothing; a stale success is routed if it is the first success, and otherwise marks the dead letter `ambiguous`; at most one result per effect id reaches `onSuccess`.                                                                                                                                                                                                        |
| Runner without an executor sees a due effect                          | It never claims the row; a runner with the executor runs it; relay lag shows the wait.                                                                                                                                                                                                                                                                                                                                  |
| Executor renewals fail on a partitioned runner                        | The attempt is interrupted after one lease measured on the runner's monotonic clock, before any takeover; the next attempt stays `ambiguous`.                                                                                                                                                                                                                                                                           |
| Claimed intents outlive their lease in a slow pass                    | A runner claims only as many intents as it can start; a delivery longer than its lease costs one duplicate delivery that the receipt deduplicates.                                                                                                                                                                                                                                                                      |
| Runner without the actor type claims a cron tick                      | It never claims the tick; a runner with the type delivers it; a tick whose entry is missing is deleted only once older than `cronSkipIfOlderThan`.                                                                                                                                                                                                                                                                      |
| Cron tick crashes after its receipt, before the rewrite               | Redelivery replays the tick's receipt, then one next-tick row is written.                                                                                                                                                                                                                                                                                                                                               |
| Deployment down longer than `cronSkipIfOlderThan`                     | The stale tick is skipped without running the handler, and the next tick is the first scheduled time after restart; inside the window it fires once.                                                                                                                                                                                                                                                                    |
| Runners race to bootstrap singleton cron                              | One pending tick row per cron entry; one receipt per scheduled time.                                                                                                                                                                                                                                                                                                                                                    |
| Effect cancelled before claim                                         | The row is deleted in the cancelling commit; no runner claims it; no provider call, route, or dead letter.                                                                                                                                                                                                                                                                                                              |
| Cancelling turn rolls back                                            | The effect row is unchanged and later runs and routes as if never cancelled.                                                                                                                                                                                                                                                                                                                                            |
| Effect cancelled while executing                                      | The row is marked cancelled and never attempted again; the attempt is interrupted within `cancelCheck`; exactly one `onCancelled` (or its fallback) reports the outcome, `Unknown` and `ambiguous` unless the attempt reported.                                                                                                                                                                                         |
| Effect result arrives after cancel                                    | A success routes once as `Succeeded` (or to `onSuccess` without `onCancelled`); a typed failure reports `Failed`; a success after the cancelled settle marks an ambiguous dead letter. No result is lost or routed twice.                                                                                                                                                                                               |
| Runner killed while a cancelled attempt runs                          | After the lease, a runner with the executor settles it as `Unknown` without running it; the cap slot frees.                                                                                                                                                                                                                                                                                                             |
| Cancel races the attempt claim                                        | Exactly one fate: deleted with no provider call, or claimed and reported.                                                                                                                                                                                                                                                                                                                                               |
| Runner killed holding a capped effect slot                            | Live leases for that actor and effect type never exceed `perActor`; the slot frees at lease end and a waiting row is claimed.                                                                                                                                                                                                                                                                                           |
| Lost-lease attempt, then a typed failure, then cancel                 | Reported `Unknown` and ambiguous, never `Failed`: the earlier attempt may have applied the call.                                                                                                                                                                                                                                                                                                                        |
| New effects arrive while capped rows wait                             | Each freed slot claims the oldest waiting row; a newer effect never overtakes it.                                                                                                                                                                                                                                                                                                                                       |
| `0015_effect_control` runs while a pre-0015 runner's attempt is live  | The backfill marks it `running`; a cancel marks it cancelled instead of settling it, and its result is still reported once.                                                                                                                                                                                                                                                                                             |
| Two runners claim one capped actor at once                            | Their counts are serialized; at most `perActor` rows are running.                                                                                                                                                                                                                                                                                                                                                       |
| Runner dies in a paused turn                                          | Transaction rolls back; no takeover before lock expiry; the caller retries the same command id against the new owner.                                                                                                                                                                                                                                                                                                   |
| Stale generation                                                      | Database fence prevents commit.                                                                                                                                                                                                                                                                                                                                                                                         |
| State decode or size defect                                           | No partial write; deterministic-defect behavior applies.                                                                                                                                                                                                                                                                                                                                                                |
| Workflow resumes elsewhere                                            | Owner, tenant, key, and caller attribution remain unchanged.                                                                                                                                                                                                                                                                                                                                                            |
| Event races workflow wait registration                                | The matching owner event resolves exactly one wait.                                                                                                                                                                                                                                                                                                                                                                     |
| Runner dies during a workflow activity                                | The recovery timer resumes the execution elsewhere; the pending attempt reruns under the same attempt number, and its actor calls reuse their derived ids so each receiver transitions once. (ADR 0022)                                                                                                                                                                                                                 |
| Workflow step write from a stale generation                           | The fenced write sees a newer generation and writes nothing; the stale run stops. (ADR 0022)                                                                                                                                                                                                                                                                                                                            |
| Resume delivered while the workflow run is live or suspending         | The run is preempted for the settled step or interrupt, or replays when it exits; a matching event is never lost and the execution never stays suspended with a resume owed. (ADR 0022)                                                                                                                                                                                                                                 |
| Activation drained with a live workflow run                           | The run is abandoned without recording an exit; another runner replays it from recorded steps. (ADR 0022)                                                                                                                                                                                                                                                                                                               |
| Wait timeout races the matching event                                 | Exactly one exit is recorded; an event committed before the deadline wins, and the loser reads the recorded exit. (ADR 0022)                                                                                                                                                                                                                                                                                            |
| Interrupt races workflow completion                                   | Exactly one terminal result is recorded; a repeated interrupt changes nothing. (ADR 0022)                                                                                                                                                                                                                                                                                                                               |
| Activity actor call reaches its expiry bound                          | The call is not sent; the activity dies with `ActivityOutcomeUnknown`, and no receiver runs twice. (ADR 0022)                                                                                                                                                                                                                                                                                                           |
| Runner lacks a step or marker an execution needs                      | The execution suspends with a `WorkflowIncompatible` span and is not failed; a compatible runner resumes it. (ADR 0022)                                                                                                                                                                                                                                                                                                 |
| Deploy removes a step an open execution may need                      | `durable workflows check` exits 1 and startup refuses, naming the workflow, step, and open-execution count. (ADR 0022)                                                                                                                                                                                                                                                                                                  |
| Event pruning reaches an open wait                                    | Pruning keeps events above the owner's smallest open cursor or pending `wait_after`; the wait still resolves. (ADR 0022)                                                                                                                                                                                                                                                                                                |
| Parked connection wakes                                               | The open or frame wakes the actor on its current owner outside the command mailbox; the session is the last committed value, `resumed` is true, and activation-local values restart fresh. A turn that wakes the actor to broadcast reaches the parked connection on whichever runner holds it.                                                                                                                         |
| Socket-owning process dies                                            | Clients reconnect as new connections with a fresh session and replay durable events from an exclusive cursor or get `RetentionGap`; no `close` handler runs; the holder's `actor_connections` rows are deleted within one sweep after its registration expires. Activation parking alone does not preserve this socket.                                                                                                 |
| Singleton runner dies                                                 | Exactly one survivor resumes residency and the background loop; each pending cron tick is claimed by one relay and delivered once after residency moves.                                                                                                                                                                                                                                                                |
| HTTP credentials absent/changed                                       | No credentials: no turn and Unauthorized; distinct tokens: distinct principals.                                                                                                                                                                                                                                                                                                                                         |
| Adapter ownership override, missing scope, or escaped turn capability | Reject without foreign or independently committed writes; concurrent contexts never exchange ownership. Owned rows and blobs: a defect that rolls back the whole turn, no receipt; a missing or unprefixed table fails startup.                                                                                                                                                                                         |
| Drain deadline expires                                                | Report forced/deadline-expired drain, interrupt local execution, preserve pending work and provider ambiguity, and permit takeover only after safe loss of old authority.                                                                                                                                                                                                                                               |
| Hosted assertion forged, expired, or bound to a different request     | Reject before admission; valid newly authenticated retries retain command identity. Expiration after admission does not cancel durable work.                                                                                                                                                                                                                                                                            |
| Application credential attempts operator repair                       | Reject without repair; authorized repair records the operator, resource scope, and reason and still respects provider-outcome safety.                                                                                                                                                                                                                                                                                   |
| Different caller reuses a committed command id                        | Deny outcome access without a second execution; credential rotation for the original caller preserves access only while currently authorized.                                                                                                                                                                                                                                                                           |
| Access revoked before admission / after durable admission             | Reject new external work and result reads; previously accepted work recovers with recorded attribution unless explicitly canceled or subject to application reauthorization.                                                                                                                                                                                                                                            |
| Live or parked session loses authorization                            | The holder (for connections) or owner (for streams) closes the session with `Unauthorized` within `policy.reauthorizeEvery` (default 60 s) of the last successful check, even while it is parked and idle; a frame is not forwarded on older authorization; a hanging or failing check closes it at the bound; resumption, reconnect, and replay do not bypass it. Commands the session already sent are not cancelled. |
| External identity expires before delivery or retry                    | Reject without new execution, including after receipt pruning; no automatic fresh-id retry and no assertion that earlier work failed.                                                                                                                                                                                                                                                                                   |
| Cleanup races retry / crashes before completion                       | Preserve supported replay and pending internal deduplication; no missing-record gap permits a second execution.                                                                                                                                                                                                                                                                                                         |
| Restore, clock change, or version skew at the retry horizon           | Preserve enforceable external expiry and accepted internal recovery; do not refresh an old identity or bypass provider reconciliation.                                                                                                                                                                                                                                                                                  |

| Pipelined batch N fails to commit | Batch N+1's staged work is discarded unseen; the activation restarts and every uncommitted caller retries. |
| Caller gives up before a reply | Retrying the same id reports the committed outcome or executes once; a new id is a new operation. |
| Commutative merge turn fails | No original command commits; each caller retries its own id and may merge again. |
| Owner runner dies ungracefully with open connections | Sockets stay open; within the owner's registration expiry each connection gets `Resync` with the last proven cursor before any new-owner frame; the resync handler or client replay delivers every event after it; late dead-generation frames are dropped; no event is silently lost. |
| Owner moves with a full inbound window | Sockets stay open; the holder resends from the oldest unacknowledged frame, one at a time; every frame is handled in order and its session write applies once. |
| Frame redelivered after the owner restarts | The handler may run again, but its session write applies at most once (`frame_seq`) and its commands replay their receipts. |
| Session write from a stale generation | The generation predicate rejects the write; the stored session is unchanged and the frame is retried on the current owner. |
| Outbound buffer overflows or broadcast gap | The connection closes with `SessionEnded` cause `SlowConsumer` and `resync: true`; no single frame is dropped or coalesced. |
| Connection session exceeds 16 KiB | Nothing is written; the handler's span records the defect; the connection closes with `SessionEnded` cause `Defect`; the activation stays resident. |
| Holder restarts at the same address | The new transport has a new epoch; the old epoch's rows are swept within one sweep and never resume. |
| Actor terminates with open connections | The terminating turn deletes every row; after commit, holders close the connections with `SessionEnded` cause `Terminated`. |
| Frame delayed past its authorization | The owner runs no handler for a frame past its `authorizedUntil` and asks the holder to reauthorize; on denial, buffered frames are discarded undelivered and `close` does not run. |
| Pre-minted command id from another caller | The connection's commands use HMAC-derived ids the other caller cannot predict; its commands commit once under its own caller. |
| Spoofed or misrouted holder message | A holder rejects another epoch's message and delivers only to its own connections of the named actor; the owner runs frames only from the stored holder. |
| Client ignores Resync | The connection closes with `SessionEnded` cause `OwnerLost` and `resync: true` at the 30-second deadline; a second owner death during a resync sends a new `Resync` with the same `after`. |
| Trigger wakes a parked actor that broadcasts | A command, intent, timer, effect route, or subscription delivery wakes the actor on its owner; the activation loads its connection rows before the broadcast flushes, and connections parked on any runner receive it. |
| Connection-row load fails before a broadcasting commit | The turn fails as a retryable defect and commits nothing; the caller retries the same command id. |
| Owner crash-loops during resync | Handlers run at bounded concurrency; a third `Resync` within 5 minutes closes the connection with `OwnerLost` and a jittered `retryAfter`. |
| Owner dies before its first message to a holder | The holder learned the owner from `Begin` before the broadcasting commit and resyncs its connections within the owner's registration expiry. |
| Seal or last flush undeliverable to a live holder | The activation excludes the holder by deleting its rows before releasing the shard; the holder closes those connections with `ServerClosed` and `resync: true` at its next liveness check. |
| Resync handler defects | The connection closes with `SessionEnded` cause `Defect`; no partial replay is taken as complete. |
| Owner dies between an open's commit and its acknowledgment | The holder closes the connection with `SessionEnded` cause `ActorUnavailable` after `deliveryTimeout` and deletes the row as its own close writer. |
| Same-runner activation restarts while holders are unsealed | The new activation cannot acquire its generation until the previous one has sealed or excluded every holder; no holder sees the newer generation first. |
| Stream's activation ends | The subscriber gets `SessionEnded` cause `ActivationEnded`, never a silent completion; resubscribing with a cursor through `read.follow` misses and repeats nothing. |
| Optimistic reducer rejected by the server | The browser handle removes the pending input and shows committed state. |
| Statement fails inside a pipelined commit group | Every statement pipelined after it is aborted and `COMMIT` returns `ROLLBACK`, which the runtime treats as a failed commit; no receipt, state, row, event, or outbox row commits; the cache is discarded, the activation restarts, and the caller retries the same command id ([ADR 0020](../decisions/0020-two-round-trip-turn-pipeline.md)). |
| Turn interrupted with a pipeline in flight | The runtime cancels and closes the leased connection and never reuses it. Before `COMMIT` is sent, the transaction rolls back. After, the outcome is commit-unknown. Either way, the caller's retry with the same command id resolves through the receipt or executes once. |

Run applicable rows on PGlite, Postgres, Neki, the in-process multi-runner harness, and the served HTTP harness. Real Postgres is mandatory for lock-contention rows.

Reducer evidence (M1.8): **Declared failure after attempted writes**, **During handler / before COMMIT**, **After COMMIT / before reply**, and part of **Deterministic defect** (rollback, `Die`, no receipt, and the actor serving the next call; the span is not asserted) are exercised for server reducer turns by the [reducer cases](01-conformance.md#reducer-cases-m18), on PGlite and Postgres. **Commutative merge turn fails** waits for M2 merging and **Optimistic reducer rejected by the server** for the M3 client.

These are required tests, not recorded passing results. The rows "Intent turn rolls back", "Relay crash after sender COMMIT", and "Relay crash after receiver commit / before outbox row deletion" have single-runner, same-shard evidence from M1.6, listed in the [conformance ledger](01-conformance.md#outbox-intents-and-timers-m16), including real SIGKILL cases on Postgres. The row "Provider success / result acknowledgment lost" has single-runner evidence from M1.7: the executor reruns under the same effect id and routes one result, and an exhausted effect whose last outcome is unknown is dead-lettered as `ambiguous`, listed in the [conformance ledger](01-conformance.md#effects-with-routes-m17), including SIGKILL cases on Postgres. The rows "Runner dies in a paused turn" and "Stale generation" have in-process multi-runner evidence on Postgres from M2.1, listed in the [conformance ledger](01-conformance.md#multi-runner-harness-m21): no survivor takes the shard before lock expiry, the caller's retry commits once on the new owner, and a stale activation on a live runner fails its fence. The relay-claim, executor-lease, and cron rows come from [ADR 0021](../decisions/0021-multi-runner-relay-singleton-and-cron.md) and are required of M2.4 and M2.5 on the in-process multi-runner harness against real Postgres; the two relay-crash rows and the provider row also run there with a runner kill between their steps. The effect-cancellation and capped-slot rows come from [ADR 0024](../decisions/0024-effect-cancellation-and-per-actor-concurrency.md) (proposed) and are required of M2.13 on the same harness. Each implementation must attach evidence and an operator signal/remediation path for the failures it claims to recover from.

# Failure matrix

**Responsibility:** make crash behavior testable.  
**Authority:** evidence.  
**Owner role:** verification/reliability.
**Change policy:** a change requires the conformance suite to be updated in the same change.

Every row MUST assert durable rows, caller result, retry identity, activation state, and later delivery—not merely absence of an exception.

Unless a row exercises denial or expiry, external receipt replay assumes the original logical caller remains authorized and the command identity is unexpired. Trusted internal recovery retains its accepted-work authority; see [receipts](../contracts/04-receipts.md).

| Fault point                                                                                      | Required result                                                                                                                                                                                                                                                                                                                                                                                                         |
| ------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Before handler                                                                                   | No business consequences; the caller's retry with the same command id executes once.                                                                                                                                                                                                                                                                                                                                    |
| During handler / before COMMIT                                                                   | Transaction rolls back receipt, state, owned rows, blob chunks, events, and outbox rows; activation restarts for retryable defect; the caller retries the same command id.                                                                                                                                                                                                                                              |
| Deterministic defect                                                                             | Rollback; caller receives `Die`; the turn span records the cause; no user code runs; actor remains resident.                                                                                                                                                                                                                                                                                                            |
| After COMMIT / before reply                                                                      | Retry with the same command id replays output or declared failure; handler does not run twice.                                                                                                                                                                                                                                                                                                                          |
| Intent turn rolls back                                                                           | No receiver turn occurs.                                                                                                                                                                                                                                                                                                                                                                                                |
| Relay crash after sender COMMIT                                                                  | The next relay pass (after the claim lease, on any runner, once a row was claimed) delivers the same intent id; the receiver executes it once.                                                                                                                                                                                                                                                                          |
| Relay crash after receiver commit / before outbox row deletion                                   | After the claim lease, any runner's redelivery replays the receiver's receipt; no second receiver transition.                                                                                                                                                                                                                                                                                                           |
| Caller delivery timeout / disconnect                                                             | The admitted turn may still commit; retrying the same command id observes its receipt instead of cancelling or duplicating it.                                                                                                                                                                                                                                                                                          |
| Runner at `maxResidentActors`                                                                    | No turn or receipt; the handle retries the same id until a slot frees, else `RunnerAtCapacity` after `deliveryTimeout`. Unbounded actors never see `MailboxFull`.                                                                                                                                                                                                                                                       |
| Declared failure after attempted writes                                                          | Roll back all business work and staged notifications; commit only the terminal typed failure outcome with the fence/receipt. Redelivery replays it without rerunning the handler.                                                                                                                                                                                                                                       |
| Provider success / result acknowledgment lost                                                    | Preserve the ambiguous outcome; reconcile or retry under provider idempotency rather than assuming the call failed.                                                                                                                                                                                                                                                                                                     |
| Relay dies after claiming, before delivery                                                       | No runner delivers the row before its claim lease ends; then one runner delivers the same intent id once.                                                                                                                                                                                                                                                                                                               |
| Relay settle dies on the same row repeatedly                                                     | The row is not due again for `max(claim lease, backoff(attempts))`, capped at `maxBackoff`; newer due rows are delivered within one poll.                                                                                                                                                                                                                                                                               |
| Two runners claim the same due rows                                                              | `SKIP LOCKED` gives each row to one runner per lease; a runner whose lease passed changes nothing when it settles.                                                                                                                                                                                                                                                                                                      |
| Executor lease expires mid-call                                                                  | The attempt is interrupted on its runner; another runner starts the next attempt with the previous one recorded as `ambiguous`; the last attempt dead-letters as `ambiguous: true`.                                                                                                                                                                                                                                     |
| Stale attempt reports after takeover                                                             | A stale failure matches no row and records nothing; a stale success is routed if it is the first success, and otherwise marks the dead letter `ambiguous`; at most one result per effect id reaches `onSuccess`.                                                                                                                                                                                                        |
| Final effect failure, then its dead-letter commit fails with retries left                        | The attempt's outcome is recorded as final, with `attempts` raised above every allowed retry limit, before the dead-letter transaction, so the next claim on any runner retries only the dead letter, from that outcome; the provider is not called again, and one dead letter and one `onDeadLetter` route commit.                                                                                                     |
| Runner without an executor sees a due effect                                                     | It never claims the row; a runner with the executor runs it; relay lag shows the wait.                                                                                                                                                                                                                                                                                                                                  |
| Executor renewals fail on a partitioned runner                                                   | The attempt is interrupted after one lease measured on the runner's monotonic clock, before any takeover; the next attempt stays `ambiguous`.                                                                                                                                                                                                                                                                           |
| Claimed intents outlive their lease in a slow pass                                               | A runner claims only as many intents as it can start; a delivery longer than its lease costs one duplicate delivery that the receipt deduplicates.                                                                                                                                                                                                                                                                      |
| Runner without the actor type claims a cron tick                                                 | It never claims the tick; a runner with the type delivers it; a tick whose entry is missing is deleted only once older than `cronSkipIfOlderThan`.                                                                                                                                                                                                                                                                      |
| Cron tick crashes after its receipt, before the rewrite                                          | Redelivery replays the tick's receipt, then one next-tick row is written.                                                                                                                                                                                                                                                                                                                                               |
| Deployment down longer than `cronSkipIfOlderThan`                                                | The stale tick is skipped without running the handler, and the next tick is the first scheduled time after restart; inside the window it fires once.                                                                                                                                                                                                                                                                    |
| Runners race to bootstrap singleton cron                                                         | One pending tick row per cron entry; one receipt per scheduled time.                                                                                                                                                                                                                                                                                                                                                    |
| Parent crashes before `COMMIT` after `turn.mint`                                                 | No outbox row and no child; the retried command mints the same ids and each child is created once.                                                                                                                                                                                                                                                                                                                      |
| Parent commit outcome unknown after `turn.mint`                                                  | The retry replays the receipt with the same ids; exactly one child per id.                                                                                                                                                                                                                                                                                                                                              |
| Relay crashes after claiming a creating intent                                                   | Another runner delivers it after the lease; the child's receipt makes creation happen once.                                                                                                                                                                                                                                                                                                                             |
| Minted child's creating turn fails                                                               | Error receipt kept, child uncreated, redelivery replays the error; parent state unchanged.                                                                                                                                                                                                                                                                                                                              |
| Proven creating call before the parent commits, or after it rolls back                           | Fails `Unauthorized` with no receipt: the parent's outbox holds no committed intent row for it.                                                                                                                                                                                                                                                                                                                         |
| Client races a creating intent with a known minted id                                            | The client's `createdBy` command fails `Unauthorized`; the parent's intent creates the child.                                                                                                                                                                                                                                                                                                                           |
| Effect cancelled before claim                                                                    | The row is deleted in the cancelling commit; no runner claims it; no provider call, route, or dead letter.                                                                                                                                                                                                                                                                                                              |
| Cancelling turn rolls back                                                                       | The effect row is unchanged and later runs and routes as if never cancelled.                                                                                                                                                                                                                                                                                                                                            |
| Effect cancelled while executing                                                                 | The row is marked cancelled and never attempted again; the attempt is interrupted within `cancelCheck`; exactly one `onCancelled` (or its fallback) reports the outcome, `Unknown` and `ambiguous` unless the attempt reported.                                                                                                                                                                                         |
| Effect result arrives after cancel                                                               | A success routes once as `Succeeded` (or to `onSuccess` without `onCancelled`); a typed failure reports `Failed`; a success after the cancelled settle marks an ambiguous dead letter. No result is lost or routed twice.                                                                                                                                                                                               |
| Runner killed while a cancelled attempt runs                                                     | After the lease, a runner with the executor settles it as `Unknown` without running it; the cap slot frees.                                                                                                                                                                                                                                                                                                             |
| Cancel races the attempt claim                                                                   | Exactly one fate: deleted with no provider call, or claimed and reported.                                                                                                                                                                                                                                                                                                                                               |
| Runner killed holding a capped effect slot                                                       | Live leases for that actor and effect type never exceed `perActor`; the slot frees at lease end and a waiting row is claimed.                                                                                                                                                                                                                                                                                           |
| Lost-lease attempt, then a typed failure, then cancel                                            | Reported `Unknown` and ambiguous, never `Failed`: the earlier attempt may have applied the call.                                                                                                                                                                                                                                                                                                                        |
| New effects arrive while capped rows wait                                                        | Each freed slot claims the oldest waiting row; a newer effect never overtakes it.                                                                                                                                                                                                                                                                                                                                       |
| Two runners claim one capped actor at once                                                       | Their counts are serialized; at most `perActor` rows are running.                                                                                                                                                                                                                                                                                                                                                       |
| A settle wakes the waiting row a claim is taking                                                 | The claim keeps the row's whole lease, so it still counts toward `perActor`; the wake goes to the next waiting row.                                                                                                                                                                                                                                                                                                     |
| Runner dies in a paused turn                                                                     | Transaction rolls back; no takeover before lock expiry; the caller retries the same command id against the new owner.                                                                                                                                                                                                                                                                                                   |
| Stale generation                                                                                 | Database fence prevents commit.                                                                                                                                                                                                                                                                                                                                                                                         |
| State decode or size defect                                                                      | No partial write; deterministic-defect behavior applies.                                                                                                                                                                                                                                                                                                                                                                |
| Workflow resumes elsewhere                                                                       | Owner, tenant, key, and caller attribution remain unchanged.                                                                                                                                                                                                                                                                                                                                                            |
| Event races workflow wait registration                                                           | The matching owner event resolves exactly one wait.                                                                                                                                                                                                                                                                                                                                                                     |
| Subscriber crashes after delivery commit                                                         | The relay redelivers the same derived id after its lease; the receipt or applied cursor acknowledges it without a second handler run, and the source-side cursor advances once.                                                                                                                                                                                                                                         |
| Source events pruned before delivery                                                             | The subscriber receives one `RetentionGap` delivery naming `after` and `resumeAfter`, then later events in order; nothing is skipped silently.                                                                                                                                                                                                                                                                          |
| Source turn rolls back                                                                           | No event, no feed row, and no subscription delivery.                                                                                                                                                                                                                                                                                                                                                                    |
| Relay dies after claiming a subscription row                                                     | No survivor delivers before the lease ends; one then delivers the same cursors under the same ids, once each in effect.                                                                                                                                                                                                                                                                                                 |
| Stale runner delivers after a lease takeover                                                     | A delivery at or below the subscriber's applied cursor runs no handler; its settle changes nothing on the source row.                                                                                                                                                                                                                                                                                                   |
| Receipt pruned before a late redelivery                                                          | The subscriber's applied cursor acknowledges the delivery as already applied; no second transition.                                                                                                                                                                                                                                                                                                                     |
| Commit races subscription settle                                                                 | The racing commit's feed row makes the subscription due again; its event is delivered, not lost.                                                                                                                                                                                                                                                                                                                        |
| Poison delivery blocks one subscription                                                          | That row retries with capped backoff and records `last_error`; later events of that row wait; other subscriptions and the publisher proceed.                                                                                                                                                                                                                                                                            |
| Subscribe and unsubscribe controls delivered out of order                                        | The newest epoch wins at the source; a delivery with no subscriber cursor row runs no handler, and its `Unsubscribed` acknowledgement deletes the source row.                                                                                                                                                                                                                                                           |
| Route throws or returns an invalid id                                                            | Deterministic defect for that row: backoff with `last_error`, no delivery, publisher unaffected.                                                                                                                                                                                                                                                                                                                        |
| Retention races a delivery claim                                                                 | The delivery sees either the event or a `RetentionGap`, never a skip.                                                                                                                                                                                                                                                                                                                                                   |
| Subscriber hibernated or parked when an event commits                                            | The delivery activates it on its owner and commits; post-commit broadcasts reach its parked connections.                                                                                                                                                                                                                                                                                                                |
| Cross-tenant or unauthorized subscription attempt                                                | Cannot be expressed, or fails at `Actor.make` for `policy.subscribers`; no rows are written.                                                                                                                                                                                                                                                                                                                            |
| Relay dies after the control claim, before the registration statement                            | The control row is claimed again after its lease and registers once at its epoch.                                                                                                                                                                                                                                                                                                                                       |
| Control row reruns after its statement committed                                                 | A registration at an epoch equal to the stored one changes nothing; `delivered` is never reset.                                                                                                                                                                                                                                                                                                                         |
| Stale epoch delivery after resubscribe                                                           | Admission sees a newer epoch and acknowledges `Stale` without running the handler; the new epoch's deliveries start from its own `from`.                                                                                                                                                                                                                                                                                |
| Relay dies after claiming a feed row, before expansion                                           | The feed is expanded after its lease ends; every subscription with pending events becomes due.                                                                                                                                                                                                                                                                                                                          |
| Publisher commits while a runner is expanding its feed row                                       | The commit resets the feed row's `attempts`, so the fenced delete matches nothing; the row stays due and the new event is expanded and delivered.                                                                                                                                                                                                                                                                       |
| Deploy adds an event class to a dynamic subscription whose rows are caught up                    | Startup widening adds the class to each row and the tag summary, keeping its cursor and epoch; the next event of only that class writes a feed and is delivered.                                                                                                                                                                                                                                                        |
| Old runner of a rolling deploy claims a subscription row widened with a class it doesn't declare | The claim skips rows whose `events` aren't within its declared plus `retired` classes; the row stays due and a new runner delivers the new class.                                                                                                                                                                                                                                                                       |
| Redelivery of a `RetentionGap` after its receipt is pruned                                       | The gap's commit set `applied = resumeAfter`, so the repeat is `AlreadyApplied` and the handler doesn't run again.                                                                                                                                                                                                                                                                                                      |
| Stale routed delivery arrives after a `NotCreated` skip and a later creation of the subscriber   | The `NotCreated` rejection stored the cursor on the subscriber's cursor row, so the stale delivery is `AlreadyApplied`.                                                                                                                                                                                                                                                                                                 |
| Unsubscribe control reaches the source before a paused, older subscribe control                  | `remove` leaves a tombstone at the newer epoch, so the late subscribe does nothing and no live row or tag summary is left behind.                                                                                                                                                                                                                                                                                       |
| Resubscribe with a cursor above the source head while a caught-up older row exists               | The relay tombstones the older row at the new epoch and delivers `Rejected`; nothing stays registered or pins events.                                                                                                                                                                                                                                                                                                   |
| Resubscribe over a tombstone, then the source emits a subscribed event                           | Reactivation increments every tag of the row in the summary, so the commit writes a feed and the event is delivered.                                                                                                                                                                                                                                                                                                    |
| Deploy adds an event class while tombstones exist for the subscription                           | Startup widening skips inactive rows; tombstones gain no tag, stay out of the summary, and are never due.                                                                                                                                                                                                                                                                                                               |
| Routed row loses history with no gap recipient                                                   | An id-routed row counts the gap on the row and in `durable-actors.subscription.undeliverable_gaps`, logs it, and resumes after it.                                                                                                                                                                                                                                                                                      |
| Runner dies during a workflow activity                                                           | The recovery timer resumes the execution elsewhere; the pending attempt reruns under the same attempt number, and its actor calls reuse their derived ids so each receiver transitions once. (ADR 0022)                                                                                                                                                                                                                 |
| Workflow step write from a stale generation                                                      | The fenced write sees a newer generation and writes nothing; the stale run stops. (ADR 0022)                                                                                                                                                                                                                                                                                                                            |
| Resume delivered while the workflow run is live or suspending                                    | The run is preempted for the settled step or interrupt, or replays when it exits; a matching event is never lost and the execution never stays suspended with a resume owed. (ADR 0022)                                                                                                                                                                                                                                 |
| Activation drained with a live workflow run                                                      | The run is abandoned without recording an exit; another runner replays it from recorded steps. (ADR 0022; `abandons a running execution on drain and resumes it on another runner`)                                                                                                                                                                                                                                     |
| Wait timeout races the matching event                                                            | Exactly one exit is recorded; an event committed before the deadline wins, and the loser reads the recorded exit. (ADR 0022)                                                                                                                                                                                                                                                                                            |
| Interrupt races workflow completion                                                              | Exactly one terminal result is recorded; a repeated interrupt changes nothing. (ADR 0022)                                                                                                                                                                                                                                                                                                                               |
| Runner dies while an interrupted workflow compensates                                            | The next runner replays the recorded steps, runs the compensations again, and records the interrupt once; compensation is at least once. (ADR 0046)                                                                                                                                                                                                                                                                     |
| Activity actor call reaches its expiry bound                                                     | The call is not sent; the activity dies with `ActivityOutcomeUnknown`, and no receiver runs twice. (ADR 0022)                                                                                                                                                                                                                                                                                                           |
| Event reaches a live run parked on a wait in a race                                              | The resume preempts the run; its replay settles the wait with the event, and a running sibling activity reruns under the same attempt. (ADR 0046)                                                                                                                                                                                                                                                                       |
| One workflow branch parks while a sibling step runs                                              | The parking branch waits until every other step has parked or finished, so no sibling loses a registration, settle, or activity result to the suspension. (ADR 0046)                                                                                                                                                                                                                                                    |
| Runner lacks a step or marker an execution needs                                                 | The execution suspends with a `WorkflowIncompatible` span and is not failed; a compatible runner resumes it. (ADR 0022)                                                                                                                                                                                                                                                                                                 |
| Deploy removes a step an open execution may need                                                 | `durable workflows check` exits 1 and startup refuses, naming the workflow, step, and open-execution count. (ADR 0022)                                                                                                                                                                                                                                                                                                  |
| Event pruning reaches an open wait                                                               | Pruning keeps events above the owner's smallest open cursor or pending `wait_after`; the wait still resolves. (ADR 0022)                                                                                                                                                                                                                                                                                                |
| Parked connection wakes                                                                          | The open or frame wakes the actor on its current owner outside the command mailbox; the session is the last committed value, `resumed` is true, and activation-local values restart fresh. A turn that wakes the actor to broadcast reaches the parked connection on whichever runner holds it.                                                                                                                         |
| Socket-owning process dies                                                                       | Clients reconnect as new connections with a fresh session and replay durable events from an exclusive cursor or get `RetentionGap`; no `close` handler runs; the holder's `actor_connections` rows are deleted within one sweep after its registration expires. Activation parking alone does not preserve this socket.                                                                                                 |
| Singleton runner dies                                                                            | Exactly one survivor resumes residency and the background loop; each pending cron tick is claimed by one relay and delivered once after residency moves.                                                                                                                                                                                                                                                                |
| HTTP credentials absent/changed                                                                  | No credentials: no turn and Unauthorized; distinct tokens: distinct principals.                                                                                                                                                                                                                                                                                                                                         |
| Adapter ownership override, missing scope, or escaped turn capability                            | Reject without foreign or independently committed writes; concurrent contexts never exchange ownership. Owned rows and blobs: a defect that rolls back the whole turn, no receipt; a missing or unprefixed table fails startup.                                                                                                                                                                                         |
| Drain deadline expires                                                                           | Report forced/deadline-expired drain, interrupt local execution, preserve pending work and provider ambiguity, and permit takeover only after safe loss of old authority. (M4.2, `conformance/drain.ts`: interrupted turns roll back or replay their receipt; interrupted attempts stay ambiguous and are taken over after their lease.)                                                                                |
| Hosted assertion forged, expired, or bound to a different request                                | Reject before admission; valid newly authenticated retries retain command identity. Expiration after admission does not cancel durable work.                                                                                                                                                                                                                                                                            |
| Application credential attempts operator repair                                                  | Reject without repair; authorized repair records the operator, resource scope, and reason and still respects provider-outcome safety.                                                                                                                                                                                                                                                                                   |
| Different caller reuses a committed command id                                                   | Deny outcome access without a second execution; credential rotation for the original caller preserves access only while currently authorized.                                                                                                                                                                                                                                                                           |
| Access revoked before admission / after durable admission                                        | Reject new external work and result reads; previously accepted work recovers with recorded attribution unless explicitly canceled or subject to application reauthorization.                                                                                                                                                                                                                                            |
| Live or parked session loses authorization                                                       | The holder (for connections) or owner (for streams) closes the session with `Unauthorized` within `policy.reauthorizeEvery` (default 60 s) of the last successful check, even while it is parked and idle; a frame is not forwarded on older authorization; a hanging or failing check closes it at the bound; resumption, reconnect, and replay do not bypass it. Commands the session already sent are not cancelled. |
| External identity expires before delivery or retry                                               | Reject without new execution, including after receipt pruning; no automatic fresh-id retry and no assertion that earlier work failed.                                                                                                                                                                                                                                                                                   |
| Cleanup races retry / crashes before completion                                                  | Preserve supported replay and pending internal deduplication; no missing-record gap permits a second execution.                                                                                                                                                                                                                                                                                                         |
| Restore, clock change, or version skew at the retry horizon                                      | Preserve enforceable external expiry and accepted internal recovery; do not refresh an old identity or bypass provider reconciliation.                                                                                                                                                                                                                                                                                  |

| Pipelined batch N fails to commit | Batch N+1's staged work is discarded unseen; the activation restarts and every uncommitted caller retries. |
| Caller gives up before a reply | Retrying the same id reports the committed outcome or executes once; a new id is a new operation. |
| Commutative merge turn fails | No original command commits; each caller retries its own id and may merge again. |
| Owner runner dies ungracefully with open connections | Sockets stay open; within the owner's registration expiry each connection gets `Resync` with the last proven cursor before any new-owner frame; the resync handler or client replay delivers every event after it; late dead-generation frames are dropped; no event is silently lost. |
| Owner moves with a full inbound window | Sockets stay open; the holder resends from the oldest unacknowledged frame, one at a time; every frame is handled in order and its session write applies once. |
| Frame redelivered after the owner restarts | The handler may run again, but its session write applies at most once (`frame_seq`) and its commands replay their receipts. |
| Session write from a stale generation | The generation predicate rejects the write; the stored session is unchanged and the frame is retried on the current owner. |
| Outbound buffer overflows or broadcast gap | The connection closes with `SessionEnded` cause `SlowConsumer` and `resync: true`; no single frame is dropped or coalesced. |
| Connection session exceeds 16 KiB | Nothing is written; the handler's span records the defect; the connection closes with `SessionEnded` cause `Defect`; the activation stays resident. |
| Holder restarts at the same address | The new transport has a new epoch; the old epoch's rows are swept within one sweep and never resume. |
| Actor terminates with open connections | The terminating turn deletes every row; after commit, holders close the connections with `SessionEnded` cause `Terminated`. |
| Frame delayed past its authorization | The owner runs no handler for a frame past its `authorizedUntil` and asks the holder to reauthorize; on denial, buffered frames are discarded undelivered and `close` does not run. |
| Pre-minted command id from another caller | The connection's commands use HMAC-derived ids the other caller cannot predict; its commands commit once under its own caller. |
| Spoofed or misrouted holder message | A holder rejects another epoch's message and delivers only to its own connections of the named actor; the owner runs frames only from the stored holder. |
| Client ignores Resync | The connection closes with `SessionEnded` cause `OwnerLost` and `resync: true` at the 30-second deadline; a second owner death during a resync sends a new `Resync` with the same `after`. |
| Trigger wakes a parked actor that broadcasts | A command, intent, timer, effect route, or subscription delivery wakes the actor on its owner; the activation loads its connection rows before the broadcast flushes, and connections parked on any runner receive it. |
| Connection-row load fails before a broadcasting commit | The turn fails as a retryable defect and commits nothing; the caller retries the same command id. |
| Owner crash-loops during resync | Handlers run at bounded concurrency; a third `Resync` within 5 minutes closes the connection with `OwnerLost` and a jittered `retryAfter`. |
| Owner dies before its first message to a holder | The holder learned the owner from `Begin` before the broadcasting commit and resyncs its connections within the owner's registration expiry. |
| Seal or last flush undeliverable to a live holder | The activation excludes the holder by deleting its rows before releasing the shard; the holder closes those connections with `ServerClosed` and `resync: true` at its next liveness check. |
| Resync handler defects | The connection closes with `SessionEnded` cause `Defect`; no partial replay is taken as complete. |
| Owner dies between an open's commit and its acknowledgment | The holder closes the connection with `SessionEnded` cause `ActorUnavailable` after `deliveryTimeout` and deletes the row as its own close writer. |
| Same-runner activation restarts while holders are unsealed | The new activation cannot acquire its generation until the previous one has sealed or excluded every holder; no holder sees the newer generation first. |
| Stream's activation ends | The subscriber gets `SessionEnded` cause `ActivationEnded`, never a silent completion; resubscribing with a cursor through `read.follow` misses and repeats nothing. |
| Progress message lost between executor and owner | Nothing durable changes; the effect's outcome and route are unchanged; the client sees a `seq` gap and later frames. |
| Executor runner dies while reporting progress | Frames stop; the next attempt reports under `attempt + 1` from `seq` 1; the activation drops the dead attempt's late frames once the new attempt's arrive or its lease passes. |
| Owner dies with progress in flight | In-flight frames are lost; holders resync as for any owner death; later frames reach the new owner, which checks the effect row before delivering. |
| Progress arrives after the effect settled or was cancelled | Dropped by the activation that committed the route or cancel, or by the effect check on a new activation; no progress follows the route's broadcast; without a route, `ProgressClosed` or the 5-second effect recheck stops it. |
| Progress floods a slow client | Coalesced per effect at the holder, dropped or evicted by member frames at the buffer limits, and discarded at `ProgressEnd`; the session is never closed because of progress. |
| Effect check cannot reach the database | The frame is dropped and the check retried after 1 second; no turn fails and no session closes. |
| Executor sends an invalid or oversized progress frame | Dropped with a warning and counted; the attempt's outcome is unchanged. |
| Connection loses authorization with progress queued | Buffered progress is discarded with the rest of the outbound buffer; nothing more is forwarded. |
| Optimistic reducer rejected by the server | The browser handle removes the pending input and shows committed state. |
| Statement fails inside a pipelined commit group | Every statement pipelined after it is aborted and `COMMIT` returns `ROLLBACK`, which the runtime treats as a failed commit; no receipt, state, row, event, or outbox row commits; the cache is discarded, the activation restarts, and the caller retries the same command id ([ADR 0020](../decisions/0020-two-round-trip-turn-pipeline.md)). |
| Turn interrupted with a pipeline in flight | The runtime cancels and closes the leased connection and never reuses it. Before `COMMIT` is sent, the transaction rolls back. After, the outcome is commit-unknown. Either way, the caller's retry with the same command id resolves through the receipt or executes once. |
| Postgres primary fails over to a synchronous standby | Every commit a caller was told about is on the promoted primary. A turn whose `COMMIT` was sent before the primary died is commit-unknown; the caller's retry with the same command id replays its receipt without a second transition, or executes once if it never committed. Runners reconnect through the moved database address without a restart; commands issued meanwhile, including their command-id mint, fail `ActorUnavailable` and are retried. |

Run applicable rows on PGlite, Postgres, Neki, the in-process multi-runner harness, and the served HTTP harness. Real Postgres is mandatory for lock-contention rows.

Reducer evidence (M1.8): **Declared failure after attempted writes**, **During handler / before COMMIT**, **After COMMIT / before reply**, and part of **Deterministic defect** (rollback, `Die`, no receipt, and the actor serving the next call; the span is not asserted) are exercised for server reducer turns by the [reducer cases](01-conformance.md#reducer-cases-m18), on PGlite and Postgres. **Commutative merge turn fails** waits for M2 merging. **Optimistic reducer rejected by the server** runs through the Promise client over HTTP on PGlite and Postgres ([Promise client](01-conformance.md#promise-client-m34)); a browser run is still to come.

Process-death evidence (T4b): **During handler / before COMMIT** and **After COMMIT / before reply** are exercised by real SIGKILL on Postgres for commands, reducer turns, owned-row writes, blob writes, and the effect dead-letter transaction, and **Declared failure after attempted writes** for owned-row and blob writes (a reducer's declared failure is also replayed across SIGKILL, but `reduce` stages no writes). The owned-row and blob turns also emit an event and stage an intent: before COMMIT and after a declared failure neither survives and nothing is delivered, and after COMMIT recovery delivers the intent once under its staged id. The `onDeadLetter` route is also killed after its receiver commits and before its outbox row is deleted (**Relay crash after receiver commit / before outbox row deletion**), and recovery replays its receipt. These cases are listed under [process death by consequence type](01-conformance.md#process-death-by-consequence-type-t4b).

Drill evidence (T7): **Runner dies in a paused turn** and **Relay crash after sender COMMIT** also run as real SIGKILL of separate runner processes under load on Postgres, with no lost or duplicated work, listed under [failure drills](01-conformance.md#failure-drills-t7). Seeded combinations of the crash, dropped-reply, relay-crash, and clock-skew rows on one runtime are T6, listed under [deterministic simulation](01-conformance.md#deterministic-simulation-t6).

Drill evidence (T10): **Postgres primary fails over to a synchronous standby** runs as a SIGKILL of the primary under load from three separate runner processes, with replies held so that at least one turn is commit-unknown, then promotion of the standby, listed under [Postgres primary failover drill](01-conformance.md#postgres-primary-failover-drill-t10). No work is lost or duplicated. Recovery can take the caller's whole `deliveryTimeout` until [#243](https://github.com/Rika-Labs/durable-actors/issues/243) is fixed.

Singleton evidence (M2.2): the residency and background-loop half of **Singleton runner dies**, after a runner kill and after lost heartbeats, has in-process multi-runner evidence on Postgres, listed under [singleton uniqueness and failover](01-conformance.md#singleton-uniqueness-and-failover-m22). Its cron half has in-process multi-runner evidence on Postgres from M2.5, listed under [cron](01-conformance.md#cron-m25).

Hosted assertion evidence (M4.8): the runner half of **Hosted assertion forged, expired, or bound to a different request** runs on PGlite and Postgres with assertions the cases sign themselves: forged, unknown-key, wrong-algorithm, expired, future, other-deployment, other-region, and misbound assertions are refused before any turn, and a turn whose assertion expires after admission commits and replays to a newly authenticated retry. Listed under [hosted assertions](01-conformance.md#hosted-assertions-m48). The edge half runs through the real `apps/edge` on Postgres: a revoked API key is refused at the edge from the moment its revocation commits, a request held past the assertion lifetime is refused as `expired` with no receipt, and a client-supplied `durable-assertion` never reaches a runner. Row **Edge signing key revoked or rotated** runs through the edge: a revocation in the control plane is pushed to runners, which refuse the key within seconds rather than the 5-minute polling bound, while a rotated key verifies during its overlap. Row **Assertion for another region or deployment** is covered by the runner cases.

These are required tests, not recorded passing results. The rows "Intent turn rolls back", "Relay crash after sender COMMIT", and "Relay crash after receiver commit / before outbox row deletion" have single-runner, same-shard evidence from M1.6, listed in the [conformance ledger](01-conformance.md#outbox-intents-and-timers-m16), including real SIGKILL cases on Postgres. The row "Provider success / result acknowledgment lost" has single-runner evidence from M1.7: the executor reruns under the same effect id and routes one result, and an exhausted effect whose last outcome is unknown is dead-lettered as `ambiguous`, listed in the [conformance ledger](01-conformance.md#effects-with-routes-m17), including SIGKILL cases on Postgres. The rows "Runner dies in a paused turn" and "Stale generation" have in-process multi-runner evidence on Postgres from M2.1, listed in the [conformance ledger](01-conformance.md#multi-runner-harness-m21): no survivor takes the shard before lock expiry, the caller's retry commits once on the new owner, and a stale activation on a live runner fails its fence. The relay-claim and executor-lease rows from [ADR 0021](../decisions/0021-multi-runner-relay-singleton-and-cron.md) have in-process multi-runner evidence on Postgres from M2.4, and the two relay-crash rows and the provider row also run there with a runner kill between their steps, listed in the [conformance ledger](01-conformance.md#multi-runner-relay-m24). The four cron rows have evidence from M2.5, listed under [cron](01-conformance.md#cron-m25): the crash-before-rewrite, downtime, and claim-filter rows on PGlite and Postgres, and the singleton bootstrap race and runner kills during a tick on three runners against real Postgres. The effect-cancellation and capped-slot rows come from [ADR 0024](../decisions/0024-effect-cancellation-and-per-actor-concurrency.md) (accepted) and have in-process multi-runner evidence on Postgres from M2.13, plus a SIGKILL case for a cancelled attempt, listed in the [conformance ledger](01-conformance.md#effect-cancellation-and-caps-m213). The `turn.mint` rows come from [ADR 0025](../decisions/0025-turn-mint.md); M2.15 has single-runner evidence on PGlite and real Postgres for the parent crash, commit-unknown, failed creating turn, uncommitted-proof, and client race rows, listed in the [conformance ledger](01-conformance.md#turnmint-m215). The relay-claim row has in-process multi-runner evidence on Postgres from the same slice, listed there too. The progress rows come from [ADR 0030](../decisions/0030-executor-progress-frames.md) and are required of M2.18 on the multi-runner harness against real Postgres. Each implementation must attach evidence and an operator signal/remediation path for the failures it claims to recover from.

Evidence for "External identity expires before delivery or retry" and "Cleanup races retry / crashes before completion" with automatic pruning is in the [conformance ledger](01-conformance.md#m19-retention-replay-pages-emit-budget-and-blob-quota). Restore and clock rollback across pruned history remain unverified.

## Served-protocol rows

Required by [ADR 0027](../decisions/0027-served-protocol.md). M3.2 runs the HTTP rows in `conformance/http.ts`, M3.4 repeats them through the Promise client in `conformance/client.ts`, and M3.3 runs the session rows in `conformance/transports.ts`. The four HTTP rows pass on PGlite and Postgres as of M3.2 (see the [ledger](01-conformance.md#served-http-m32)). As of M3.4, "Command response lost over HTTP" and "Client clock ahead of the database clock" also pass through the Promise client, as do the rows "Caller gives up before a reply" and "External identity expires before delivery or retry", and a SIGKILL of the serving process before and after commit retries exactly once on real Postgres (see the [ledger](01-conformance.md#promise-client-m34)). As of M3.3, "Credential expires during a live session" passes over WebSocket on PGlite and Postgres, and "Live or parked session loses authorization" also passes over a real socket (see the [ledger](01-conformance.md#served-websocket-connections-m33)). Both rows and "SSE feed reconnects after pruning" also pass for SSE event feeds (see the [ledger](01-conformance.md#served-sse-event-feeds-m33)).

| Fault point                              | Required result                                                                                                                                                                                                  |
| ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Command response lost over HTTP          | A retry with the same `Idempotency-Key` replays the committed output or declared failure; the handler runs once, and every response echoes the id as `x-request-id`.                                             |
| HTTP client disconnects mid-command      | The accepted command still commits once; a later retry with the same id replays it.                                                                                                                              |
| Client clock ahead of the database clock | Ids minted from the `/protocol` offset are admitted; a future id fails `InvalidCommandId` with code `future`, runs nothing, and is never replaced by the client.                                                 |
| Proxy injects its own request id         | The server takes the command id only from `Idempotency-Key`; an injected `x-request-id` never becomes a command id.                                                                                              |
| Credential expires during a live session | A WebSocket that doesn't answer `reauthenticate` ends with `Unauthorized` `expired` at the credential's expiry and discards buffered frames; an SSE feed ends there and resumes from its cursor after reconnect. |
| SSE feed reconnects after pruning        | The reconnect answers `410` with `RetentionGap` before streaming and never resumes past the gap.                                                                                                                 |

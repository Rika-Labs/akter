# 0.1 retirement map

**Responsibility:** name, for every 0.1 test file and conformance group removed from `rewrite/0.2`, the 0.2 evidence that replaces it or the accepted decision that removes the behavior.  
**Authority:** evidence.  
**Owner role:** verification/reliability.  
**Change policy:** a row changes only when its replacement suite lands (link it) or an accepted ADR changes the removal.

The 0.1 runtime (Postgres and PGlite storage, owned tables, receipts, relay, subscriptions, the Promise client, the React and Python clients, and the operator commands that read them) was deleted in one change at the start of milestone E1. Under the branch-authority rule in `AGENTS.md`, each removed suite either has a 0.2 contract clause whose planned test rejects the same wrong implementation, or an accepted removal. Planned suites are named by their contract verification id (I, F or T) and the milestone (E1–E8) whose gate requires them; none exists yet, so until the milestone lands that guarantee is **unverified on this branch**, not supported. The deleted files stay readable at `56c27d7f2a` (`git show 56c27d7f2a:<path>`), and their dated results stay in the other documents in this directory as history.

Removal codes:

- **0124**: [engine rewrite on a command log](../decisions/0124-engine-rewrite-and-command-log.md): turn transactions, receipts tables, mailboxes, the warm pipeline and SQL statement shape are gone.
- **0125**: [synchronous deterministic actions](../decisions/0125-synchronous-deterministic-actions.md): reducers, turn hooks and I/O inside handlers are gone.
- **0126**: [shard ownership on the bucket log](../decisions/0126-shard-ownership-on-the-bucket-log.md): generation fences, advisory locks and runner tables are replaced by epochs.
- **0128**: [constrained actor API](../decisions/0128-constrained-actor-api.md): one way per thing; command/query/reducer/stream member kinds are gone.
- **0129**: [jobs, timers and the shard workflow engine](../decisions/0129-jobs-timers-and-shard-workflow-engine.md): 0.1 workflows, keyed effects and executor progress are gone.
- **0130**: [views, sessions, events and RPC](../decisions/0130-views-sessions-events-and-rpc.md): SSE, stored events, feeds and MCP are gone; one RPC group at `/rpc`.
- **0131**: [`find` over owner-held indexes](../decisions/0131-find-over-owner-held-index.md): fleet views are gone.
- **0133**: [build-matched replay](../decisions/0133-build-matched-replay.md): workflow version tables and payload upcasts are gone.
- **0134**: [removing owned tables and placement](../decisions/0134-removing-owned-tables-and-placement.md): owned tables, adopted tables, blobs, content, placement, child minting and subscriptions are gone.
- **0136**: [the bucket is the store](../decisions/0136-stores-the-bucket-is-the-store.md), with D18: no Postgres or PGlite anywhere in the framework.
- **D5**: clean break for alpha users; no export, migrate or adopt tool.
- **D8**: the React and Python clients are deferred from 0.2.0 and return only through their own ADRs.
- **D9**: Effect client only; the Promise client, optimistic reducers and offline queue are gone.

## Kept on the branch

These kept files still run in `bun run --cwd packages/akter test` (and, for the platform-sensitive ones, `bun run test:node:units` under Node), so they are not in the tables below: `identity/command.test.ts`, `policies/schedules.test.ts`, `serve/{auth,jwt,origin,wire}.test.ts`, `serve/assertion/{binding,verify}.test.ts`, `runtime/peering/{authority,transport}.test.ts`, and `tooling/conformance/src/conformance/workflow-engine.test.ts`. `tooling/conformance/src/conformance/platform.ts` (Bun-or-Node HTTP server layers) is kept for the E4 harness.

`protocol/wire.test.ts` and its corpus `protocol/exchanges.json`, kept until E4, proved the 0.1 Promise client's retry schedule and status mapping against scripted exchanges. E4 deleted them with `protocol/wire.ts`; the replacements are `serve/wire.test.ts` (the refusal statuses and `retry-after`) and the client conformance suite in `tooling/conformance/src/conformance/client.test.ts`, which rejects a client that changes the command id on retry and one that surfaces a refusal as a transport failure ([E4 RPC and serving](e4-rpc-serve.md)).

One case was removed from a kept file: `serve/wire.test.ts` "rejects a declared error that claims a framework status or tag" exercised `checkDeclaredErrors` in the deleted `actor/served.ts`. Replacement: [error model](../contracts/error-model.md) "One framework error" and "Wire form", by the type tests for `ActorError.Of` and the declared-error checks of E1's contract types.

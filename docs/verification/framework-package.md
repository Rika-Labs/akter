# Framework package boundary and dependency cohort

Evidence recorded on 2026-10-08 for [ADR 0111](../decisions/0111-framework-verification-workspace.md). This is repository/package evidence, not certification of a provider or production deployment.

The measurements and commands below precede the stacked [Neki removal](neki-removal.md). Its provider tests and separate migration project have since been removed; they remain here only as the package-split baseline.

## Packed size

Both measurements used `bun .github/src/pack.ts --out <temporary-directory>` followed by `npm pack --dry-run --json --ignore-scripts <temporary-directory>`, on the same alpha.2 framework manifest.

| Framework tarball          | Unpacked bytes | Files | Compressed bytes |
| -------------------------- | -------------: | ----: | ---------------: |
| Before the workspace split |      6,476,175 |   615 |        1,117,414 |
| After the workspace split  |      2,494,508 |   411 |          639,092 |

The unpacked package shrank by 3,981,667 bytes (61.5%) and 204 files. The private `@akter/conformance` workspace owns the relocated fixtures, suites, cluster harness, simulations and Vitest configurations. The public testing entry retains `ActorTest`, database fixtures, cleanup/content sweeps, `checkBatchLaw` and fault controls. No runtime imports connect the package back to that workspace. The pack guard rejects compiled conformance, foundation, cluster and simulation modules, with a regression test that still accepts the public testing entry.

## Dependency and consumer checks

The catalog pins Effect and its platform/SQL/Vitest cohort to 4.0.3, and Vitest to 5.0.3. The staged framework manifest resolves Effect peer ranges to `^4.0.3`, excluding 4.0.2; the internal platform-node-shared runtime dependency remains exactly 4.0.3. Tarball smoke installs into a clean consumer, typechecks its public API, exercises memory and file-backed database commands/restarts, and checks the CLI.

Effect 4.0.3 changed `Crypto.randomUUIDv4` and `Crypto.randomUUIDv7` from effects to functions. Framework, CLI and verification calls use `()` to retain lowercase, hyphenated string identifiers. Fresh-consumer smoke rejects the old property-shaped calls at runtime construction, and the peer floor prevents the updated calls from being paired with 4.0.2.

The [4.0.2-to-4.0.3 upstream diff](https://github.com/Effect-TS/effect/compare/effect%404.0.2...effect%404.0.3) also changes SQL COMMIT failure propagation, single-connection SQL leases, Cluster handoff and shutdown, workflow replay, SchemaError serialization, MCP cancellation, and integer JSON Schema bounds. These are covered by the existing transaction, recovery, workflow, HTTP/MCP, protocol and packaging suites; they do not change Akter's durable authority contract. Akter's message storage owns its transaction boundary, and its runner storage retains the default session advisory-lock configuration rather than adopting lease authority or the new opt-in termination annotation. The singleton keeper now schedules its first wake too, preserving startup/activation separation as recorded in [ADR 0121](../decisions/0121-effect-4-0-3.md).

Extended checks were run and did not all pass. Random-seed full Postgres integration passed 974 tests but failed the three-runner recovery simulation at seed `c394439944` after a connection-loss fault, plus ten drain cases whose fixture could not acquire connections from the initial 100-connection server. Nightly Docker drills passed 15 tests and failed seven, including timeouts, a six-second certificate expiring before runner construction, and connection-capacity refusal. A capacity-corrected drain project passed; a concurrent conformance run under all-core CPU stress timed out in four operator/telemetry cases and one connection checkout. These failures are not counted as passes.

One complete local stress iteration ran the workflow's four suites under native `stress-ng --cpu 18`. Framework and unit/PGlite phases passed (322 and 630 tests). Postgres integration and Docker drills failed (15 and seven tests respectively, plus setup/file failures); the stress summary failed as it should. This is not a pass for the ten-run Linux workflow, and no timeout, assertion or production failure classification was weakened to obtain one.

The original [Nightly properties run 38133207788](https://github.com/Rika-Labs/akter/actions/runs/38133207788) and [Stress run 38145895276](https://github.com/Rika-Labs/akter/actions/runs/38145895276) do not share the fresh-install failure. Their logs use Effect 4.0.2 and contain no UUID API error. Nightly failed the three-runner recovery simulation at seed `c774862372` after connection loss; stress reported Postgres file failures and placement, tag-summary and capped-cancellation cases. In contrast, PRs 750 and 751 fail fresh-consumer construction at the old `crypto.randomUUIDv4.pipe` call. Adopting 4.0.3 fixes that packaging incompatibility, not all existing recovery/load failures.

After stopping the CPU workers, the final quiet Postgres run of `test:integration:postgres --project=postgres:conformance --project=postgres:drain` passed both projects: 357 tests passed and 11 capability-gated cases skipped. The dedicated primary and streaming replica both used `max_connections=300`. This establishes the requested conformance gate after the singleton scheduling adaptation; it does not turn the extended nightly or stress failures above into passes.

# T7: both seed matrices at 10,000 seeds (2026-10-14)

**Responsibility:** record the dated 10,000-seed runs that ADR 0124's registry requires before 0.2.0.  
**Authority:** dated verification evidence; simulator only.  
**Owner role:** runtime and reliability.

## What ran

Both ledger matrices in `packages/akter/src/testing/simulation.test.ts` ran at 10,000 seeds, each on Bun and on Node. Every run starts twelve concurrent transfers among five accounts on the memory bucket and crashes every shard partway through. The simulator also injects crashes, lost responses, outages and slow log calls.

- **Single-runner matrix:** "conserves money and delivers every send and timer exactly once across N faulted seeds". `AKTER_SIMULATION_SEEDS` sets N; the default is 1,000.
- **Moving-owner matrix (E3):** "keeps the same totals across N faulted seeds while the runner layer moves, drains, pauses and cuts off the owner". This is the seeded multi-runner simulation ADR 0124 places under T7. It runs over two runners while the runner layer reassigns shards, drains the owner, pauses it, or cuts off its bucket calls. `AKTER_SIMULATION_MOVING_SEEDS` sets N; the default is 200.

Run `n` uses seed `SIMULATION_SEED_BASE + n`, so each matrix covered seeds `0x5eed0000` through `0x5eed270f` (1592590336 through 1592600335).

Every seed must satisfy these assertions:

- money totals 500;
- received equals sent;
- there is one audit timer per sent transfer;
- the number sent lies between the successful transfers and the successful plus unknown ones.

`Simulation.settle` checks I1–I6 and I9 against the bucket after every run. Across each matrix, the test also asserts that every fault it depends on actually occurred:

- single-runner: refusals, crashes, lost responses and outages;
- moving: crashes, partitions and pauses.

No invariant, assertion or fault was changed. Each count variable must be a positive integer. An empty, zero or non-integer value fails the file rather than running the default.

## Commands

Run from the repository root on macOS 26.6.2, Apple M5 Max (18 cores), with Vitest 5.0.3:

```sh
cd packages/akter && AKTER_SIMULATION_SEEDS=10000 bun --bun ../../node_modules/vitest/vitest.mjs run --root ../.. packages/akter/src/testing/simulation.test.ts -t "conserves money" --reporter=verbose
AKTER_SIMULATION_SEEDS=10000 node node_modules/vitest/vitest.mjs run packages/akter/src/testing/simulation.test.ts -t "conserves money" --reporter=verbose
cd packages/akter && AKTER_SIMULATION_MOVING_SEEDS=10000 bun --bun ../../node_modules/vitest/vitest.mjs run --root ../.. packages/akter/src/testing/simulation.test.ts -t "keeps the same totals" --reporter=verbose
AKTER_SIMULATION_MOVING_SEEDS=10000 node node_modules/vitest/vitest.mjs run packages/akter/src/testing/simulation.test.ts -t "keeps the same totals" --reporter=verbose
```

The single-runner runs used commit `e8e8b020d16046b7469af241b9ac40f7450261ab`. The moving runs used `f74feb81d2469761f81a3327e22649e673bb1e57`, which added the moving-seed variable. Both trees were clean, and the matrix code under test is otherwise unchanged between the two commits.

## Limits

This is simulator evidence on the memory bucket. It is not evidence for a provider, MinIO, multiple processes or performance, and it makes no claim about provider latency or throughput (T1/T2). The other seeded suites stayed at their default sizes:

- `testing/cluster.test.ts`: 50 split-shard seeds;
- `snapshots/pages.test.ts`: 40 seeds;
- `execution/indexes.test.ts`: seeds 2301–2332;
- the two seed-replay determinism tests: 50 and 20 seeds.

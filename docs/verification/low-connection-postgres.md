# Low-connection Postgres

**Responsibility:** establish the connection floor and name the wait cycles #712 must reject.  
**Authority:** evidence.  
**Owner role:** runtime/reliability.

## Supported envelope

`Database.postgres({ preset: "low-connection" })` selects 1 turn / 2 off-turn / 1 query connections. The existing defaults remain 50/10/10; explicit pool sizes take precedence. This is a maximum of **four primary runtime sessions**, not four freely available off-turn sessions and not a process-wide limit on application-created pools.

Effect 4.0.2 reserves one of the off-turn sessions for Cluster for the layer lifetime, for both advisory and table locks. Its startup DDL and registration use the normal client while that reservation is held. At least one spare must remain. The three separate primary pools therefore cannot run on 1/1/1; the reservation is **inside** the off-turn maximum, not additional to it. Framework migration coordination temporarily leases a session and returns it before Cluster construction. Four includes that startup usage. The preset is the lowest sizing tested with these boundaries; 5/2/2 remains a higher-capacity nine-session configuration, not the minimum.

No turn/dispatch, lease, receipt or durable authority semantics change. Public socket runners retain table leases. An embedded Postgres runtime retains advisory ownership. Fewer sessions serialize more work; a FIFO queue is not a latency SLA.

## Wait-cycle analysis and regression cases

The focused cases are in [`runtime/database/bounded.test.ts`](../../packages/akter/src/runtime/database/bounded.test.ts), under `low-connection Postgres preset`. They use fresh real Postgres databases, the production `Actors.layer`, public actor APIs and real loopback HTTP, not a mocked pool.

The capped-claim case deliberately allows an inspector/off-turn operation to queue behind a real database lock. The independent query must still complete, and once the turn is released all work must settle within the deadline. This is bounded contention, not a claim that every reader remains independent of every held transaction. Queries for actors with owned tables or blobs use the off-turn pool and share that contention.

## Reproduce

Use Bun 1.4.2 and Postgres 18.6. Set `TEST_DATABASE_URL` to a test server whose role can create disposable databases. On the shared launch Mac, prefix heavy commands with `~/.capy/work/akter-launch/heavy.sh`.

```sh
bun --bun node_modules/vitest/vitest.mjs run packages/akter/src/runtime/database/bounded.test.ts
bun --bun node_modules/vitest/vitest.mjs run packages/akter/src/runtime/database/migrations.test.ts
bun --bun node_modules/vitest/vitest.mjs run tooling/conformance/src/conformance/crash/turns/main.test.ts tooling/conformance/src/conformance/crash/delivery/relay.test.ts tooling/conformance/src/conformance/crash/delivery/effects.test.ts tooling/conformance/src/conformance/crash/delivery/effect-control.test.ts
```

PR Verify runs these in the existing Postgres integration project and runs the complete public socket process drills separately. No new heavyweight local suite or duplicate conformance shard is added.

## Limits

- Fleet reserves a second off-turn session when coordination and data share the client. It needs at least three off-turn sessions (five primary sessions with one turn and one query). With separate coordination it reserves one session on each database; account for both. Fleet is not certified by the four-session cases.
- `PgClient.listen`, application-held reservations, external pools, owned-table migration tools and operator connections require additional budget. Holding the last ordinary off-turn session while awaiting a public actor command self-starves admission; increasing its pool or releasing the reservation is the application's responsibility.
- Optional replica and coordination configurations retain their existing defaults and add sessions. This preset does not make a database pooler safe or remove server-session locking. Transaction-mode PgBouncer changes are only [proposed in ADR 0117](../decisions/0117-pooler-safe-locking.md).
- Budget all simultaneously live runtimes, including rolling replacements, per physical database server. Pool saturation measures runtime capacity, not throughput, hosting-provider behavior or latency across separate hosts. The process-death evidence is Bun-specific; core tests elsewhere retain their Node support scope.

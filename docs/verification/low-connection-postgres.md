# Low-connection Postgres

**Responsibility:** establish the connection floor and name the wait cycles #712 must reject.  
**Authority:** evidence.  
**Owner role:** runtime/reliability.

## Supported envelope

`Database.postgres({ preset: "low-connection" })` selects 1 turn / 2 off-turn / 1 query connections. The existing defaults remain 50/10/10; explicit pool sizes take precedence. This is a maximum of **four primary runtime sessions**, not four freely available off-turn sessions and not a process-wide limit on application-created pools.

Effect 4.0.2 reserves one of the off-turn sessions for Cluster for the layer lifetime, for both advisory and table locks. Its startup DDL and registration use the normal client while that reservation is held. At least one spare must remain. The three separate primary pools therefore cannot run on 1/1/1; the reservation is **inside** the off-turn maximum, not additional to it. Framework migration coordination uses one bounded transaction and returns its session before Cluster construction. Four includes that startup usage. The preset is the lowest sizing tested with these boundaries; 5/2/2 remains a higher-capacity nine-session configuration, not the minimum.

No turn/dispatch, lease, receipt or durable authority semantics change. Public socket runners retain table leases. An embedded Postgres runtime retains advisory ownership. Fewer sessions serialize more work; a FIFO queue is not a latency SLA.

## Wait-cycle analysis and regression cases

The focused cases are in [`runtime/database/bounded.test.ts`](../../packages/akter/src/runtime/database/bounded.test.ts), under `low-connection Postgres preset`. They use fresh real Postgres databases, the production `Actors.layer`, public actor APIs and real loopback HTTP, not a mocked pool.

The capped-claim case deliberately allows an inspector/off-turn operation to queue behind a real database lock. The independent query must still complete, and once the turn is released all work must settle within the deadline. This is bounded contention, not a claim that every reader remains independent of every held transaction. Queries for actors with owned tables or blobs use the off-turn pool and share that contention.

## Limits

- Fleet reserves a second off-turn session when coordination and data share the client. It needs at least three off-turn sessions (five primary sessions with one turn and one query). With separate coordination it reserves one session on each database; account for both. Fleet is not certified by the four-session cases.
- `PgClient.listen`, application-held reservations, external pools, owned-table migration tools and operator connections require additional budget. Holding the last ordinary off-turn session while awaiting a public actor command self-starves admission; increasing its pool or releasing the reservation is the application's responsibility.
- Optional replica and coordination configurations retain their existing defaults and add sessions. The preset alone does not select pooling or remove server-session locking. The separate explicit mode below implements only the narrow subset of [ADR 0117](../decisions/0117-pooler-safe-locking.md) accepted in [ADR 0119](../decisions/0119-transaction-pooling.md).
- Budget all simultaneously live runtimes, including rolling replacements, per physical database server. Pool saturation measures runtime capacity, not throughput, hosting-provider behavior or latency across separate hosts. The process-death evidence is Bun-specific; core tests elsewhere retain their Node support scope.

## Transaction pooling

The separate opt-in is `Database.postgres({ pooling: "transaction" })`, not the low-connection preset or URL inference. Its envelope is public socket runners, table leases and one primary database, without fleet, cold storage, replica or separate coordination. Application session state and `LISTEN` are unsupported. Direct-endpoint tests remain independent.

[`pooling.test.ts`](../../tooling/conformance/src/conformance/postgres/pooling.test.ts) uses the real Docker fixture in [`pooling.ts`](../../tooling/conformance/src/conformance/postgres/pooling.ts). The pinned image is:

```text
edoburu/pgbouncer:v1.25.1-p0@sha256:4a8371e79d6627e74f553d0aaa8e4c5ace20e30034fb296e569b71c89c99e108
```

`SHOW VERSION` and `pgbouncer --version` report **PgBouncer 1.25.2** for this tag/digest, not 1.25.1. The test asserts the observed binary version. The local server is Postgres 18.6 and the runtime is Bun 1.4.2. This is not binary-1.25.1 evidence. The fixture has transaction pooling, prepared statements disabled, no reserve pool, round-robin reuse, and `DISCARD ALL` after every transaction. It creates an isolated container/network, an ephemeral loopback port and uniquely named `s10pooler` databases; cleanup never touches a shared server/container. Docker lifecycle has its own fixture deadlines; serving and transaction deadlines are not raised.

The stream-lifetime case additionally closes a reservation while its stream is held: the close and next checkout must wait, the stream returns 17, the next client returns 43, and a late statement on the closed reservation is interrupted. The ownership-fence case kills the backend of a transaction holding generation 1 and staging 91; a waiting takeover reaches generation 2, 91 rolls back, the old cached fence is refused and cleared, and only the new owner's 43 commits. The combined process fault case also requires both surviving processes to exit within five seconds after their clean drain; merely recovering traffic is not sufficient.

The direct foundation-collision case in `crash/turns/main.test.ts` exercises both ledger starting states. A pre-existing ledger remains present and empty after failed DDL; a ledger created by the failed startup is absent. Both paths then retry, assert every expected migration ID and zero receipts, and verify an idempotent restart. Missing history is checked with `to_regclass`, not by swallowing a missing-table error.

Local verification passed all ten pooled cases, the eight focused existing direct driver cases (including nested streaming, cancellation and savepoints), six direct concurrent startups with coordination, the unchanged direct serving scenario, and the sixteen PGlite/lock regressions. Framework and conformance typechecks, framework build, focused type-aware lint, structure and directive checks passed. CI still runs the integration suite on its own platform; local evidence does not stand in for a pending PR check.

```sh

```

The tests establish bounded correctness scenarios, not a connection floor below three shared server backends or a latency SLA under arbitrary saturation.

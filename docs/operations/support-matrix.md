# Backend support matrix

**Responsibility:** show real capability differences by backend.  
**Authority:** operational evidence.  
**Owner role:** platform/verification.

The matrix must be maintained with evidence, not protocol assumptions. Rows include transactions, fencing, locking, change feeds, incremental live SQL, locality, snapshots, pooling, migrations, and restore.

An unsupported or unverified cell is more honest than a generic “Postgres-compatible” label.

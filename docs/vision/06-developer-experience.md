# Developer experience

Start with `state` and `actions`, schema decoding defaults, and a short synchronous handler. Add a list, view, event, job, or presence only when the application needs it. The contract and one flat Effect client handle share names and schemas. Duplicate member names are rejected.

`akter dev` uses a local filesystem store. The 0.2 target development tools expose the same audited inspection paths as operators, not a second SQL inspector. Seeded `Simulation` runs the engine with controlled faults and time; real buckets establish provider behavior.

The client is Effect-only. React and Python clients, generated OpenAPI/MCP interfaces, offline queues, and optimistic Promise reducers are not part of 0.2.0. Their return needs a separate accepted decision.

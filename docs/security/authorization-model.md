# Authorization model

**Responsibility:** define authorization surfaces.  
**Authority:** security contract.  
**Owner role:** security/API.
**Change policy:** a change requires security review.

`CurrentCaller` is the ambient `Context.Reference`, defaulting to the trusted `System({ source: "process" })` in tenant `"default"` for code in the application's own process ([ADR 0059](../decisions/0059-caller-and-tenant-defaults.md)). `Actors.serve` authentication sets it independently for every request, and every served route runs with `Anonymous` as its ambient caller so a path that forgets the authenticated caller fails closed; tests use `ActorTest.layer({ as })`, and `Actor.as(caller)` scopes an explicit caller around any Effect for trusted code acting on behalf of a user. Handles capture the caller when acquired. `X.Turn` exposes `caller` and `principal`; `X.Workflow` exposes `principal`, and workflow bodies act through handles carrying persisted System/on-behalf-of attribution.

Authorization is per actor: `Actor.make`'s `access` policy, and the runtime's optional global `authorize`, both of which must allow when both exist. With neither, `System` is allowed and `User` and `Anonymous` are denied, so a served actor is closed until it declares `access`; `Actor.access.public` opens one to anyone and is only for demos and deliberately public actors. `Actors.serve` requires an explicit auth configuration, including `Auth.none` for anonymous callers, whom an actor must still allow. Bearer auth is a helper, not an implicit global default. Missing, invalid, or expired credentials produce `ActorError` with reason `Unauthorized`; the reason carries a stable `code`. A request without credentials must not fall back to `Anonymous` when authentication is required.

Hosted ingress authenticates the external API key, derives authorized deployment/tenant attribution, and forwards a short-lived internal assertion signed with an edge private key over TLS. The runner verifies a trusted issuer/key, a permitted algorithm, deployment audience, expiry, and binding to the actor, operation, command identity where applicable, and encoded payload. Verification does not replace resource/operation authorization. The edge replaces client-supplied identity fields; private-network location and unsigned headers are not authority.

Runners receive verification keys, not the edge signing key. Durable envelopes retain verified attribution, not API keys, raw credentials, or transport assertions. An assertion expiring after admission does not cancel durable execution; a newly authenticated retry can recover the same command receipt subject to receipt access and command expiry. Key rotation/revocation, canonical request binding, and streaming-session authorization still need a concrete tested protocol. Signed assertions are accepted design, not an implemented or verified hosted capability; see [ADR 0003](../decisions/0003-failure-scoping-drain-and-hosted-trust.md).

Stored outputs and declared failures belong to the original logical caller, who must still have resource/operation access when retrieving them, or an operator explicitly authorized for that receipt. Credential rotation preserves logical identity. Knowing a command id, sharing a tenant, or gaining access to an actor is insufficient. Deduplication remains tenant/actor/command-id scoped, not caller scoped: denying receipt access must not allow a second execution. Replay must authorize access independently of the handler, which does not run again.

Implementation must specify a durable logical-caller key and replay-authorization interface, including System/on-behalf-of attribution. `Auth.none` does not distinguish individual anonymous clients; no per-client receipt privacy can be claimed from an undifferentiated `Anonymous` caller. Resolve that identity model explicitly before claiming such privacy. See [ADR 0004](../decisions/0004-receipt-access-revocation-and-expiry.md).

Revocation blocks new external admissions and result reads, but already accepted durable work continues with recorded attribution unless explicitly canceled. Applications may reauthorize sensitive steps. Trusted internal recovery must not be mistaken for a new external request, and external requests must not be able to claim recovery authority. Live sessions must reauthorize or disconnect within the revocation bound `policy.reauthorizeEvery` (default 60 seconds), including parked-session resumption; the socket holder rechecks on a timer and fails closed ([ADR 0023](../decisions/0023-connections-parking-and-streams.md)). Authorization freshness and session invalidation require evidence; neither captured handles nor stored connection state grant indefinite access. Cancellation does not undo completed provider calls.

Every framework and actor-owned row is scoped by `tenant_id`; transaction predicates are mandatory and optional RLS is defense in depth. Tenant and shard placement are not authorization. Administration, migrations, drain, dead-letter repair, and reconciliation require separate action- and deployment/tenant-scoped operator capabilities. Repair records include the operator, target, and reason. [ADR 0050](../decisions/0050-operator-authority-and-audited-repair.md) implements this for inspection, receipt reads, defect reads, dead-letter retry and discard, and the audit log: an operator is authenticated by an `OperatorAuth` provider to a grant, never derived from a `Caller`, and each action writes a `durable.operator_audit` row, a repair in its own transaction. Application credentials or a claimed System caller do not confer operator authority, and authorization to retry a job does not resolve provider ambiguity.

Caller attribution propagates through intents, timers, schedules, workflows, and job routes as a `System` caller with optional `onBehalfOf`. Process memory, activation ownership, leases, generation, and network location are never authorization authority.

Internal commands are absent from public handles, HTTP, and the Promise client; a non-System attempt is a deterministic defect. Off-turn actor read contexts cannot write state, rows, or blobs; job executors have no database capability, and workflow bodies request changes through actor handles. These restrictions supplement runtime ownership checks rather than substituting TypeScript types for authority.

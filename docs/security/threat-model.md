# Threat model

**Responsibility:** identify security failure modes.  
**Authority:** security.  
**Owner role:** security/runtime.
**Change policy:** a change requires security review.

Assume clients are hostile, input is untrusted, networks fail, runners restart, and operators can make mistakes. Application handlers are trusted code with database access; the framework is not a hostile-code sandbox.

| Threat                                                | Primary controls                                                                                                                                                                                                                                                                                                                  |
| ----------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Forged or confused caller                             | explicit per-call auth, edge-signed assertions over TLS, issuer/audience/expiry/request checks, resource authorization, and `CurrentCaller` isolation                                                                                                                                                                             |
| Edge signing-key compromise                           | Ed25519 keys only in the edge's secret store; runners hold public keys from a polled key set; revocation stops verification within 5 minutes and rotation every 30 days; assertions bind the request, deployment, and region and last at most 60 s ([ADR 0031](../decisions/0031-hosted-ingress-tenant-directory-and-regions.md)) |
| Cross-tenant read or mutation                         | mandatory `tenant_id` predicates, actor ownership keys, optional RLS, isolation tests                                                                                                                                                                                                                                             |
| Stale or duplicate writer                             | generation row locked `FOR UPDATE`, one commit, stale-generation rollback                                                                                                                                                                                                                                                         |
| Replayed or conflicting command                       | caller-minted stable command id, durable receipt, `CommandConflict` on changed input                                                                                                                                                                                                                                              |
| Consequence from a rolled-back turn                   | events, intents, jobs, state, and receipt share the commit                                                                                                                                                                                                                                                                        |
| Lost or duplicated hosted intent                      | tenant-shard `actor_outbox`, stable intent identity, deduplicated destination handoff and receiver receipts, crash recovery                                                                                                                                                                                                       |
| Singleton split ownership                             | Cluster singleton registration plus two-runner uniqueness and failover gate                                                                                                                                                                                                                                                       |
| Credential or payload disclosure                      | redacted configuration, field classification, bounded telemetry, encrypted backups                                                                                                                                                                                                                                                |
| Unauthorized repair                                   | separate operator capability, audited dead-letter and migration commands                                                                                                                                                                                                                                                          |
| Restore rollback repeats an external effect           | provider idempotency keys, job records, reconciliation before execution resumes                                                                                                                                                                                                                                                   |
| Activation memory treated as authority                | durable database facts only; memory, leases, and placement never authorize                                                                                                                                                                                                                                                        |
| Stale authorization on a live or parked session       | holder timer closes at `reauthorizeEvery` from the last success, `authorizedUntil` on every frame, fail-closed checks, buffers discarded on revocation ([ADR 0023](../decisions/0023-connections-parking-and-streams.md))                                                                                                         |
| Frame injection or holder spoofing between runners    | runner traffic only over mTLS (`Runner.mtls`: TLS 1.3, deployment identity checked on both sides, [ADR 0086](../decisions/0086-runner-mutual-tls.md)) or an isolated network; holder epochs; holder delivers only to its own connections of the named actor; owner checks the stored holder                                       |
| Forged or stale resync                                | only the holder creates `Resync` and consumes `ResyncDone`, in a control envelope apart from member frames; `after` is the holder's own tenant-keyed record; resync requests carry `authorizedUntil`; bounded handler concurrency and a cap of two resyncs per 5 minutes                                                          |
| Predictable command ids from connection handlers      | ids derived by HMAC from a per-connection secret that is never stored or exposed                                                                                                                                                                                                                                                  |
| Slow-consumer, connection, or subscription exhaustion | 64 KiB inbound frames, per-actor connection and subscription caps, per-holder buffer budget, bounded reauthorization concurrency, pinned activations counted in `maxResidentActors`                                                                                                                                               |
| Executor progress disclosure or flooding              | target ([ADR 0030](../decisions/0030-executor-progress-frames.md)): owner-routed only, same tenant and actor, `to: "principal"` by default, session authorization per frame, 4 KiB frames, per-attempt, per-actor, and per-runner rate caps, never logged                                                                         |

`ActorError` exposes bounded reasons—`ActorUnavailable`, `MailboxFull`, `RunnerAtCapacity`, `Timeout`, `CommandConflict`, `NotCreated`, `Unauthorized`, `SessionEnded`, `InvalidInput`, and `TransportError`—without leaking secret internals. `isRetryable` and `retryAfter` guide clients without granting authority.

Every control needs a conformance or integration test, an observable failure signal, and a recovery procedure. Hosted claims additionally require the Neki relay and Railway topology verification gates.

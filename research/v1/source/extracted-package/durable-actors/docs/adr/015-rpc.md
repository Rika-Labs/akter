# ADR 015: Reuse Effect RPC contracts

Date: 2026-09-17  
Status: Accepted direction

## Context
Schema-driven messages, successes and errors already exist in Effect RPC and Entity. A parallel actor request system risks duplicate types and serializers.

## Decision
Compile/reuse RpcGroup and add only actor identity/durability semantics. Pick one consistent handler payload convention after a type spike.

## Alternatives considered
Custom Request objects may be convenient sugar but cannot diverge from wire/schema contracts. Generic JSON endpoints lose typed boundaries.

## Consequences and risks
Protocol versioning, persisted annotation and typed transport errors still need our explicit policy.

## Validation and revisit trigger
Revisit only a concrete inability to express the desired durable request/reply contract with acceptable type complexity.

## Implementation discipline
This is an architectural decision record, not evidence that the feature exists. Link implementation PRs, exact component versions and gate results here before changing a conditional status to accepted/verified. A conforming adapter must preserve the stated semantics, not merely satisfy TypeScript types.

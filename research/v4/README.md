# Research v4 — Effect-native actor API (2026-09-21)

Predecessor: [v3](../v3/README.md) (feature specification). v4 does not change the v3 architecture
(single relational database, transactional turns, Cluster-backed placement). It replaces the v3
`Actor.define` sketch in [01-actor-context](../v3/features/01-actor-context/README.md) with a surface
that is verified against Effect `4.0.0-rc.116` types, and records which Effect primitives each piece
compiles down to.

Everything in this folder typechecks:

```
bunx tsc --noEmit -p research/v4/tsconfig.json
```

[typecheck.ts](typecheck.ts) holds strict type equalities (`any` never satisfies them) and
`@ts-expect-error` negatives, so a regression in the sketch fails the command.

## The surface

```ts
// Chat.ts (contract)
export const SendMessage = Actor.command("SendMessage", {
  input: { id: Schema.String, body: Schema.String },
  output: Message,
  errors: [InvalidMessage, NotAMember]
})
export const Recent = Actor.query("Recent", { input: { limit: Schema.Number }, output: Schema.Array(Message), errors: [NotAMember] })

export const Chat = Actor.make("Chat", {
  commands: [SendMessage],
  queries: [Recent],
  events: [MessageAdded],
  lifecycle: [Hibernate.after("5 minutes"), Events.keep("30 days")]
})

// Chat.server.ts (implementation)
export const ChatLive = Chat.toLayer(
  Effect.gen(function*() {
    const access = yield* RoomAccess
    return Chat.of({
      SendMessage: Effect.fn("Chat.SendMessage")(function*(ctx, input) {
        yield* access.requireMember(ctx.caller, ctx.address)
        ...
        yield* ctx.emit(new MessageAdded({ message }))
        return message
      }),
      Recent: (ctx, input) => ...
    })
  })
)

// anywhere
const room = yield* Chat.get("room-1")
const msg = yield* room.SendMessage({ id: "m1", body: "hi" })
const counter = yield* Counter.get("counter-123")
yield* counter.Increment(1)
yield* counter.Reset()
const actors = yield* Actors
actors.get(Counter, "counter-123") // same handle, non-sugared
```

## Decisions recorded in this iteration

| Decision | Choice | Why |
| --- | --- | --- |
| Handle acquisition | `const counter = yield* Counter.get(id)` — one yield, then methods are plain Effects with `R = never` | The runtime is captured at `get`; no `(yield* Svc).method()` at call sites. `Counter.get` is sugar over `Actors.get(Counter, id)`. |
| Command naming | Tag, handler key, and handle method are the same PascalCase name (`SendMessage`), 1:1 with `Rpc.make` / `RpcClient` | One name per command; nothing to map. |
| Handler signature | `(ctx, input)` | |
| Declarations | Standalone values in arrays: `commands: [...]`, `queries: [...]`, `events: [...]`, `lifecycle: [...]` | Contract values are importable and reusable across actors. |
| Contract / implementation split | `X.ts` exports the definition; `X.server.ts` exports `X.toLayer(...)` | Clients never bundle handler code or server services. |
| `commandId` | Generated by the framework; `ctx.commandId` exposes it; optional trailing `{ commandId }` override on request/reply for externally supplied idempotency keys; intents derive theirs from `(turn commandId, intent index)` | Receipts stay exactly-once without every caller inventing keys. |
| Direct request/reply inside a turn | Not a type error; a runtime guard rejects it (defect) | Encoding "inside a turn" in the type system would force `Turn` into every method's `R`. `.send/.after/.at` do carry `R = Turn`, so intents are statically confined to turns. |
| Errors | Every command's `E` is exactly `declared errors | CommandConflict | ActorUnavailable`; queries `declared | ActorUnavailable` | `ActorUnavailable.cause` keeps the original Cluster error. Nothing collapses to `unknown`. |

## What compiles down to what

| Surface | Effect primitive |
| --- | --- |
| `Actor.command` / `Actor.query` | `Rpc.make(tag, { payload, success, error: Schema.Union(errors) })`, annotated `ClusterSchema.Persisted: true` |
| `Actor.make` | `RpcGroup.make(...)` + `Entity.fromRpcGroup(name, rpcs)`; exposed as `X.rpcs` / `X.entity` escape hatches |
| `X.toLayer(handlers)` | `Entity.toLayer(build, { concurrency: 1, maxIdleTime, mailboxCapacity, defectRetryPolicy })`; `Sharding` is supplied from `Actors` so actor layers only require `Actors` |
| `X.get(id)` / `Actors.get` | `Sharding.makeClient(entity)` wrapped so each method is a plain Effect and Cluster errors become `ActorUnavailable` |
| `ctx.db` | `drizzle-orm/effect-postgres` on the same `PgClient`, joined to the turn transaction |
| `ctx.emit`, `.send`, `.after`, `.at` | Rows in `actor_events` / `actor_outbox` inside the turn transaction; delivered post-commit |
| `handle.events(E)` | `Stream` fed by post-commit `NOTIFY` / PubSub, filtered by tag |
| `Actor.layer` | `Layer<Actors, never, Database \| Sharding>`; the app provides `Database.layer(config)` and a runner layer (`TestRunner.layer` in tests) |

## Lifecycle policies

The `lifecycle` array is the single home for per-actor runtime behaviour. Each policy maps to one
knob; unknown combinations are impossible by construction (a policy is a tagged value, not a config
object).

| Policy | Maps to | Default |
| --- | --- | --- |
| `Hibernate.after(d)` | `Entity.toLayer.maxIdleTime` | 1 minute |
| `Mailbox.capacity(n \| "unbounded")` | `Entity.toLayer.mailboxCapacity` | `ShardingConfig.entityMailboxCapacity` (4096) |
| `Defects.retry(schedule)` | `Entity.toLayer.defectRetryPolicy` (Cluster concatenates it with its default backoff and re-writes in-flight requests after restart) | Cluster default |
| `Commands.timeout(d)` | `turn()` wraps the handler in a timeout inside the transaction; expiry is a defect, so the transaction rolls back and Cluster redelivers | none |
| `Commands.lockWait(d)` | `SET LOCAL lock_timeout` on the `SELECT … FOR UPDATE` generation fence; expiry is a defect | server default |
| `Receipts.keep(d)` | `actor_receipts` retention. Must be ≥ Cluster message retention; purge `cluster_replies`, then `cluster_messages`, then receipts | 7 days |
| `Events.keep(d \| "forever")` | `actor_events` retention | 30 days |

Not policies, on purpose: `concurrency` is always `1` (a turn is a transaction), `Persisted` is
always `true`, and `WithTransaction` is always `false` (see v3 decision B0: Cluster resumes reply
listeners before the outer commit, and on Neki `cluster_*` and business rows live in different shard groups).

## Types the sketch guarantees (from typecheck.ts)

- `Counter.get(id): Effect<CounterHandle, never, Actors>`
- `counter.Increment: (input: number, options?: CallOptions) => Effect<number, Overflow | CommandConflict | ActorUnavailable>`
- `counter.Reset: (options?: CallOptions) => Effect<void, CommandConflict | ActorUnavailable>`
- `counter.GetCount: () => Effect<number, ActorUnavailable>`
- `counter.Reset.after: (delay: Duration.Input) => Effect<void, never, Turn>`
- `counter.events(CountChanged): Stream<CountChanged, never, Scope>`
- `CounterLive: Layer<never, never, Actors>`; `ChatLive: Layer<never, never, RoomAccess | Actors>`; full app `Layer<never, never, never>`
- Handlers reject undeclared errors, wrong input types, unknown commands, intents without a `Turn`, events not declared on the actor, and handles of the wrong actor.
- Inside `Effect.fn(...)(function*(ctx, input))`, `ctx` and `input` are contextually typed (probed: `ctx.nonexistent`, `input.foo`, `ctx.self.Decrement`, and `ctx.emit` on a query context all fail to compile).

## Unresolved

1. **Queries: through the entity or direct?** Declared queries currently route through the entity, so they serialize behind commands (`concurrency: 1`). With a single database, `Recent` could run on the caller's node against committed rows instead. Candidate: `Queries.direct()` policy, or make direct the default and reserve entity-routed queries for reads that need the activation's in-memory state.
2. **`Actors.get` is synchronous and returns a handle whose first call resolves the Cluster client.** The alternative (`Actors.get` returning an Effect) costs a second yield at every call site; rejected for ergonomics, but the client must be cached per definition.
3. **Handle method casing**: PascalCase follows Rpc. A one-line `Uncapitalize<Tag>` mapping would give `counter.increment(1)` while keeping `Increment` as the tag; it introduces a second name per command.
4. **`Database` on Neki**: `Database.layer` must pin `SET __neki.tx_mode='single'` to the connection that runs `BEGIN`, and `shardLockDisableAdvisory: true`. `LISTEN/NOTIFY`, `FOR UPDATE`, and session pinning are undocumented on Neki and need provider evidence before `handle.events` is claimed there.
5. **Repo debt found during review** (not changed): `packages/database/src/index.ts` builds two pools (`PgClient.layer` and a raw `pg.Pool` for `drizzle-orm/node-postgres`), so Drizzle never joins an Effect transaction; it should use `drizzle-orm/effect-postgres`. `packages/database/src/migrate.ts` hand-rolls migrations with raw `pg`; `Migrator` exists in `effect/unstable/sql`.
